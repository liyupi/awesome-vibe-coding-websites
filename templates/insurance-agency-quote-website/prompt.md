# Insurance Agency Quote Website

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a polished three-page website for [BRAND], an invented independent insurance agency serving [AUDIENCE] in [SERVICE_AREA]. The central message is [PROMISE]. Include home, auto, and life coverage paths; a short branching three-step quote-summary form; a clear working process; three fictional agent profiles; explicitly illustrative reviews; and a practical claims-help page. Use the exact default copy and sample data below, rewriting every agency-specific detail when variable values change.

- Audience: Individuals and families comparing home, renters, auto, or term life coverage who want plain-language guidance before speaking with an independent agent. It also suits small agency owners adapting a complete static front end for their own audience and service area.
- Goal: Help visitors identify the right coverage path, understand the agency's role, prepare a concise summary for a real conversation, and find calm claims guidance. Demonstrate a complete client-side quote journey without calculating premiums, submitting personal data, or implying coverage is bound.
- Tone: Warm, clear, steady, and specific. Sound like a patient local advisor rather than a carrier, call center, or aggressive lead funnel. Use short sentences, concrete examples, transparent limitations, no scare tactics, no savings promises, and no pressure countdowns.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Tailwind CSS 3.4
- Libraries: react (MIT), react-dom (MIT), vite (MIT), @vitejs/plugin-react (MIT), typescript (Apache-2.0), tailwindcss (MIT), postcss (MIT), autoprefixer (MIT), motion (motion.dev, import from 'motion/react') (MIT), lucide-react (ISC), @fontsource/fraunces (OFL-1.1), @fontsource/public-sans (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Scaffold a Vite React TypeScript app. Keep index.html, quote.html, and claims.html at the project root, each with a div id='root' whose data-page value is home, quote, or claims and the same src/main.tsx entry.
  - In vite.config.ts set base './', plugins [react()], build.outDir 'dist', build.sourcemap false, build.assetsInlineLimit 0, and rollupOptions.input to all three root HTML files using resolve(__dirname, '<file>'). Do not copy src/ into dist/.
  - Configure Tailwind 3.4 through PostCSS with content ['./index.html', './quote.html', './claims.html', './src/**/*.{ts,tsx}']. Add the Design colors and fontFamily display ['Fraunces', 'Georgia', 'serif'] and sans ['Public Sans', 'system-ui', 'sans-serif'].
  - In src/fonts.ts import '@fontsource/fraunces/600.css', '@fontsource/fraunces/700.css', '@fontsource/public-sans/400.css', '@fontsource/public-sans/500.css', '@fontsource/public-sans/600.css', and '@fontsource/public-sans/700.css'; import src/fonts.ts and src/index.css from the entry file.
  - src/main.tsx reads the root element's data-page value and renders the matching page without a router. Every navigation link points to ./index.html, ./quote.html, or ./claims.html, with section hashes and quote query parameters only where specified.
  - Keep every visible string, sample answer option, review, agent, address, hour, contact detail, FAQ, and image path in typed records in src/content.ts. Derive brand-dependent values and rewrite all dependent content when variables change.
  - Add src/lib/brand.ts for brandSlug and the reserved .example email address, src/lib/quote.ts for query parsing, typed branching fields, validation, summary formatting, and reset behavior, and src/lib/clipboard.ts for copy with a local fallback.
  - Use Motion for React for section reveals, mobile navigation, quote-step transitions, checklist tabs, and accordions. Use Lucide icons only. Keep quote state in memory for the current page session; do not persist answers in localStorage or send them anywhere.
  - Before the first build, download the six supplied images into public/images/ with the exact paths under Assets. The production build itself never fetches anything.
  - Create public/favicon.svg from the original open-door line motif under Assets. Give each HTML file a plain variable-aware title and a local favicon link; do not add SEO metadata or structured data.
  - Write ASSETS.md at the project root with every supplied image, font package, and icon package as specified under Assets. Keep dist/ under 20 MB with no source maps.

- [AUDIENCE] — Primary audience (default: "homeowners, drivers, and growing families"). A concise lowercase phrase shaping the hero, coverage guidance, agent introductions, and quote invitation.
- [SERVICE_AREA] — Service area (default: "Alder Grove and the west-side neighborhoods"). An invented local service area used throughout the site. Keep street addresses and neighborhood names fictional.
- [PROMISE] — Central promise (default: "Clear choices. A real person in your corner."). A short original agency promise used as the homepage H1 and repeated in the quote and footer copy. Do not promise savings, acceptance, or claims outcomes.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/insurance-agency-quote-website in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.
