# Trending Topics Microblog

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build an original static microblog called [BRAND] for [AUDIENCE] interested in [COMMUNITY_TOPIC]. The first screen is a complete, polished app workspace with navigation, a short-post composer, a media-rich timeline, and a ranked trend panel. Add a full trending board and a focused topic page. All accounts, conversations, counts, and activity are fictional local sample data; clearly identify the changing heat scores as a local simulation.

- Audience: Indie hackers, community builders, creators, educators, and product designers who need a convincing social-community prototype that works entirely in the browser and can be adapted to a different subject through a small set of variables.
- Goal: Let visitors scan rising conversations, open a topic, read and interact with posts, and publish a short post with an optional local image. Make every visible control useful without accounts, remote APIs, or a server, and persist the visitor's interactions in localStorage.
- Tone: Observant, friendly, specific, and unhurried. Use concise posts about concrete discoveries and works in progress rather than engagement bait, generic motivational copy, or claims of real online activity.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Tailwind CSS 3.4
- Libraries: react 18.3.1 and react-dom 18.3.1 (MIT), lucide-react 0.468.0 (ISC), @fontsource-variable/bricolage-grotesque 5 (OFL), @fontsource-variable/inter 5 (OFL), @fontsource/ibm-plex-mono 5 (OFL)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Configure vite.config.ts with base './' and build.sourcemap set to false; produce only the static dist/ directory and never copy src/ into it.
  - Use Tailwind CSS 3.4 with a small theme extension for the specified colors and font families; put global focus styles, scrollbar styling, keyframes, and the reduced-motion override in src/index.css.
  - Keep all brand values, navigation labels, sample accounts, posts, comments, topics, counts, and artwork selection in src/content.ts. Rewrite the sample world to fit the supplied variable values instead of leaving default-only urban-nature copy in an alternate build.
  - Build focused components named AppShell, Composer, PostCard, Artwork, TrendBoard, TopicHeader, CommentThread, BookmarksDrawer, and Toast; keep shared interaction state in one React context or a small custom store.
  - Implement hash routing without another dependency: index.html is home, ./index.html#/trends is the full board, ./index.html#/topic shows [FEATURED_TOPIC], and ./index.html#/topic/<slug> opens any other topic. Unknown topic slugs fall back to [FEATURED_TOPIC], never an empty state.
  - Use a localStorage namespace derived from a lowercase slug of [BRAND] so likes, reposts, bookmarks, follows, comments, and new posts survive reloads without colliding with another brand.
  - Create a deterministic local activity sequence that updates heat scores and rank order every eight seconds after initial render; pause it while the document is hidden and replace automatic updates with a Refresh activity button when reduced motion is requested.
  - Use FileReader for the composer's optional image so a PNG, JPEG, or WebP up to 1 MB can be previewed, removed, published, and persisted locally; reject other types or larger files with an inline error and never upload the file.

## Variables
- [BRAND] — Community name (default: "Cloverloop"). An invented two-syllable or compound name; derive the wordmark, favicon, page title, and storage namespace from it.
- [COMMUNITY_TOPIC] — Community subject (default: "urban nature and citizen science"). The broad subject that shapes every sample post, illustration, topic, and community description.
- [AUDIENCE] — Community audience (default: "neighborhood observers and amateur ecologists"). A concise description of the people participating in this community.
- [FEATURED_TOPIC] — Featured trend (default: "Roof Gardens"). The leading topic shown first on the trend board and at the bare #/topic route; derive its hash slug and hashtag from this value.
- [COMPOSER_PROMPT] — Composer placeholder (default: "What did you notice outside today?"). A short question tailored to the community subject and audience.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/trending-topics-microblog in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design
### Colors
- Canvas `#F3F0E8` — Warm oat page background with a very subtle CSS dot texture at 3% opacity.
- Surface `#FFFCF6` — Cards, header, composer, and drawers.
- Ink `#20231F` — Primary text, dark navigation pills, and primary buttons.
- Muted `#6F7269` — Metadata, timestamps, secondary labels, and inactive icons.
- Line `#D9D6CC` — One-pixel borders, separators, input outlines, and heat-bar tracks.
- Coral `#E86A4A` — Heat bars, rank-change highlights, selected reaction accents, and small graphic details.
- Coral Dark `#A63F2A` — Accessible coral text, hot-badge text, counter warnings, and focus details on light surfaces.
- Sage `#DCE8D8` — New badges, selected filter backgrounds, and gentle illustration fields.
- Forest `#285846` — New-badge text, positive rank deltas, and live-simulation labels.
- Sun `#F1C75B` — Small hot-badge fields and warm highlights in the SVG artwork; never body text.

### Typography
- Display and brand: Bricolage Grotesque Variable (OFL), weights 600/700/800
- Interface and post body: Inter Variable (OFL), weights 400/500/600/700
- Heat scores, counts, timestamps, and rank numbers: IBM Plex Mono (OFL), weights 500/600

### Layout & motion
- Spacing: Use a 4px base unit. The desktop shell is max-width 1360px with 24px outer padding, columns of 216px, minmax(0, 660px), and 312px, and 24px gutters. Cards use 20px padding on desktop and 16px on mobile. Post rows have 16px vertical rhythm; trend rows are 64px tall. At 1440×900, show the full header, composer, first media post, and at least five trend rows without crowding.
- Radius: Use 18px for feed and panel cards, 14px for artwork and image previews, 12px for inputs and buttons, and 999px for chips, badges, avatars, and icon-button hover fields. Borders and spacing define the layout; use only a soft 0 10px 30px rgba(32,35,31,0.05) shadow on drawers and the sticky composer when focused.
- Motion: On first load, stagger the shell, composer, first post, and trend panel by 40ms with a 240ms opacity and 12px upward reveal; never animate the entire feed for several seconds.
- Motion: When local activity changes a ranking, animate row reordering with a 260ms FLIP transition and heat-bar width over 500ms using cubic-bezier(0.22,1,0.36,1); briefly tint only the changed numeric delta.
- Motion: New posts enter at the top with a 280ms opacity and -12px transform transition. Toasts fade and translate upward over 180ms, remain for 2.5 seconds, and never cover the composer or mobile navigation.
- Motion: Reaction buttons use 160ms color and background transitions with no layout shift. Comment regions expand with opacity and a maximum-height transition while remaining keyboard accessible.
- Motion: Hash-page changes crossfade the main column over 180ms and scroll its heading into view without smooth scrolling on mobile. Respect prefers-reduced-motion by removing reveals, FLIP movement, automatic activity, and smooth scrolling.
- Imagery: Draw every visual in code. Use four original 16:9 inline SVG editorial illustrations with flat geometric shapes, crisp 2px ink outlines, restrained coral, sage, sun, and cream fills, and tiny hand-placed texture marks rather than photographs. The scenes are a rain-filled rooftop garden, a shaded neighborhood tree map, evening primroses with abstract pollinators, and a gravel-and-reed pocket wetland. Include no words, logos, recognizable landmarks, real products, or human faces. Generate abstract avatars from circles, arcs, and offset color blocks with a unique seed per fictional account; do not use initials-only avatars, stock portraits, or real likenesses. A compact SVG sparkline in the community-pulse card uses the same visual language. The first-screen media post and dense app UI are the visual anchor.

## Don'ts
- Do not use any real social platform name, logo, mascot, slogan, proprietary typeface, trademarked icon, exact brand palette, or pixel-for-pixel interface.
- Do not copy real posts, usernames, profile photographs, trends, comments, code, or artwork; every account and metric is fictional sample content and all illustrations must be original code.
- Do not add a backend, authentication, database, API route, remote form submission, analytics, real social sharing, or third-party activity service. Label simulated activity honestly and keep all state in the browser.
- Do not hotlink images, fonts, scripts, icons, map tiles, or other assets. Do not use stock-photo sites, placeholder-image services, CDNs, real faces, recognizable landmarks, or external SVG files.
- Do not load fonts from Google Fonts or another CDN; use only the specified self-hosted Fontsource packages and keep the exact three-family typography system.
- Do not replace the stack, add a routing or animation dependency, use restricted component-library source, or introduce a commercial font. Use React, Tailwind, Lucide, CSS transitions, and the specified local hash router.
- Do not use bare-directory links. Use ./index.html, ./index.html#/trends, ./index.html#/topic, and ./index.html#/topic/<slug>; opening #/topic without a slug must show [FEATURED_TOPIC].
- Do not ship source maps, src/ files in dist/, unminified production output, or a dist/ larger than 20 MB. Keep base './' so the static build works from a nested demo path.
- Do not leave dead buttons, decorative search fields, nonfunctional tabs, or placeholder comments. Every compose, filter, follow, reaction, bookmark, share, drawer, and navigation control must work with mouse, touch, and keyboard.
- Do not upload composer images or accept files over 1 MB. Provide preview, removal, validation, alt-text input for user-added images, and local persistence without a network request.
- Do not allow horizontal overflow or obscured controls at 1440×900 and 390×844. Keep touch targets at least 44px, visible focus indicators, sufficient contrast, semantic buttons, labeled inputs, and zero console errors.
- Do not ignore prefers-reduced-motion, run endless background activity, use autoplaying sound, flash content, or block reading with rank animations.
- Do not add SEO metadata, Open Graph tags, JSON-LD, sitemaps, analytics, or keyword-stuffed copy; use only a plain document title derived from [BRAND] and a simple original favicon.
- Do not display calendar dates or imply real online users, real popularity, or verified metrics. Use the supplied relative-time sample labels and clearly mark counts and heat as fictional local data.
- Do not hard-code default urban-nature copy outside src/content.ts or leave it unchanged when variables differ; derive hashtags, topic slugs, brand labels, storage keys, and all sample content from the current values.
