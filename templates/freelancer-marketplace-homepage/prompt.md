# Freelancer Marketplace Homepage

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build an original four-page marketplace website for [BRAND], a fictional directory connecting [AUDIENCE] through [MARKET_FOCUS]. The default brand is Workkind, based in [LOCATION], with the headline [HERO_HEADLINE]. Include a polished homepage, a query-driven talent category page, individual profile views, and a four-step post-a-project experience. Every person, company, rating, review, price, and availability note is invented sample content.

- Audience: The primary audience is [AUDIENCE]. For the defaults, this means small studio founders, startup operators, and independent creative or technical specialists in and around [LOCATION]. Speak equally clearly to clients comparing help and freelancers deciding whether to join.
- Goal: Help a visitor move from a broad need to a relevant sample freelancer, understand both sides of the marketplace, and assemble a useful project brief. Search, filters, sorting, profile links, local draft persistence, brief copying, and text download must work entirely in the browser.
- Tone: Warm, capable, plain-spoken, and human. Favor specific skills and practical expectations over marketplace hype. Never imply that the fictional profiles, ratings, companies, availability, or submissions are real.

## Stack

- Styling: Tailwind CSS 3.4
- Libraries: motion (MIT), lucide-react (ISC), @fontsource-variable/fraunces (OFL), @fontsource-variable/inter (OFL)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Set Vite base to './' and disable source maps in the production config.
  - Configure Vite multi-page inputs for index.html, category.html, profile.html, and post-project.html; each HTML file loads the same typed React entry, which selects the page from window.location.pathname.
  - Use Tailwind for layout and state styling, with a small CSS file for tokens, keyframes, focus rings, image treatment, and reduced-motion overrides.

## Variables
- [BRAND] — Marketplace name (default: "Workkind"). An invented, short marketplace name with no connection to a real service.
- [MARKET_FOCUS] — Talent market (default: "independent creative and technical talent"). The professional niche; rewrite categories, profiles, skills, and examples to fit.
- [AUDIENCE] — Two-sided audience (default: "small teams and independent specialists"). Describe both the people hiring and the people offering services.
- [HERO_HEADLINE] — Homepage headline (default: "Good work starts with the right people."). A concise, warm promise suited to the chosen talent market.
- [LOCATION] — Home location (default: "Portland, Oregon"). An invented marketplace home base; use it in hero support copy and footer details.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/freelancer-marketplace-homepage in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

### Layout & motion
- Spacing: Use a 4px base scale with a 1280px max-width content container and 40px desktop gutters. Desktop sections have 104px vertical padding, compact directory sections 64px, and mobile sections 64px with 20px gutters. Hero uses a 12-column grid with 64px gaps. Card interiors use 20–24px; form fields have 12px vertical and 16px horizontal padding.
- Radius: Use 18px on cards, 24px on photographic panels and major callouts, 12px on inputs and buttons, and full rounding only for chips and compact status pills. Keep shadows sparse: one soft 0 16px 50px rgba(24,58,50,0.10) elevation for the floating search panel and mobile menu.
- Motion: On initial load, fade and translate the hero copy upward by 18px over 500ms, then reveal the photograph with a 24px clip-path inset resolving over 650ms; stagger only these two groups.
- Motion: Reveal major homepage sections once as they enter the viewport with 16px upward travel and 450ms easing; never hide core copy waiting for JavaScript.
- Motion: Give category chips, profile-card arrows, and buttons 160–200ms color, border, and 2px directional transforms; filtering updates crossfade results in 180ms without layout jumps.
- Motion: Advance the project form with a 220ms horizontal fade of 12px and animate the progress fill; preserve focus by moving it to the new step heading.
- Motion: Disable smooth scrolling, reveals, parallax, and nonessential transitions under prefers-reduced-motion; all content and controls remain immediately visible.
- Imagery: Use six locally hosted, generated editorial photographs as one coherent shoot: warm cream interiors, forest-green and terracotta clothing or props, natural window light, realistic skin texture, gentle film grain, and uncluttered composition. The hero is a wide collaborative scene with environmental space, never a tight face close-up. The five freelancer images are natural working portraits of explicitly fictional adults with varied ages and ethnicities, not resembling any real individual. Use consistent 3:4 crops for profile cards and a 4:3 crop for the hero. Portfolio thumbnails are original CSS and SVG compositions, not extra photographs. Use Lucide icons only, with no third-party brand marks.

## Don'ts
- Do not use or imitate any real marketplace name, logo, slogan, interface copy, exact palette, proprietary illustration, or custom iconography.
- Do not use real people, recognizable likenesses, real freelancer biographies, real client companies, or verifiable testimonials; every profile, rating, review, price, company, and working note is fictional sample content.
- Do not claim real marketplace scale, verified earnings, guaranteed outcomes, live online status, current availability, response times, successful placement, or actual project submission.
- Do not add backend logic, API routes, databases, authentication, payments, messaging, identity verification, external form endpoints, analytics, or third-party API calls. Search, filtering, profiles, draft storage, and exports must remain client-side.
- Do not hotlink assets or load scripts, styles, icons, images, or fonts from a CDN. Download the six specified generated images into public/images and use the local paths in the site.
- Do not use Unsplash, Pexels, Pixabay, Google Images, placeholder-image services, CC BY-NC or CC BY-SA material, commercial fonts, or any dependency outside the permitted licenses.
- Do not generate recognizable celebrity or public-figure likenesses. The generated people are fictional adults, varied in age and ethnicity, with no logos, readable screens, watermarks, or text in the photographs.
