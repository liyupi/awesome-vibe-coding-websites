# Paper Lantern Festival Page

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build [BRAND], an original single-page paper-lantern festival called [FESTIVAL_NAME] above the fictional [RIVER_NAME]. The welcome headline is [HEADLINE], written for [AUDIENCE], with original ambient wishes shaped by [WISH_THEMES]. A full-width living Canvas 2D river scene carries the first screen. Beside it, a three-step DOM composer lets each visitor write a private wish, fold an SVG paper lantern, and release it into the animated sky. Released wishes persist in a personal local gallery with Release again and Remove actions. Use only procedural Canvas 2D, local SVG, CSS, and original copy; do not reproduce an existing event or lantern website.

- Audience: Write the welcome, wish prompts, helper text, and ambient wishes for [AUDIENCE]. The experience should feel understandable to a first-time visitor without instructions or an account. Keep the core write-fold-release workflow available through ordinary labeled buttons and fields on desktop, touch screens, and keyboards; canvas movement and pointer parallax are decorative enhancements, never required input.
- Goal: Within five seconds, show a richly layered night river, many warm lanterns, and an obvious place to write a wish. Make the transition from text to folded paper to released light feel coherent and rewarding, then make the saved wish easy to find after a reload. Preserve the draft through folding, keep up to 24 released wishes locally, and deliver the entire experience as static files with no external data request.
- Tone: Tender, quiet, secular, and lightly poetic rather than mystical or sentimental. Use concise US English and concrete interaction feedback. Treat lanterns as original paper-craft objects, not as sacred symbols or a claim of cultural authenticity. Never promise that a wish will come true. Be explicit that ambient wishes are invented, visitor wishes stay in the current browser, and there is no live public feed.

Wrap an ambient lantern to just below the river horizon when it exits the top or side, incrementing cycle and deriving its replacement x deterministically from id and cycle; never allocate random values every frame.
  - The wind range input has integer values 0, 1, and 2 labeled Still, Gentle, and Brisk, defaulting to Gentle. Map these to wind multipliers 0, 1, and 1.85. Cap device pixel ratio at 1.75 desktop and 1.5 mobile, use ResizeObserver without resetting wishes or ambient positions, and clean up observers, listeners, and animation frames.
  - Implement subtle pointer parallax only on devices with a fine pointer: stars move at most 2 CSS pixels, far hills 4, mist 7, and near bank/dock 10 opposite the normalized pointer position, eased over 200ms. Personal lanterns do not follow the pointer. Disable parallax for touch and reduced motion, never use scroll-jacking or a custom cursor, and do not make ambient lanterns required click targets.
  - Model the composer as a finite state machine: write, folded, releasing, released. Write requires a trimmed wish of 3–120 UTF-16 characters and keeps the exact user text intact. Fold my lantern enters folded and plays the SVG sequence once. Back to wish returns to write without losing text. Release lantern enters releasing, creates one personal lantern at normalized x 0.48 and y 0.78, and saves exactly one gallery record. After 1.4 seconds it enters released and joins normal upward simulation. Write another clears only the composer; the gallery remains. Release again in the gallery creates a personal lantern for the existing wishId at x 0.48 and y 0.78 without adding a duplicate record.
  - Build the folding preview as a local inline SVG with a 160 × 160 viewBox and six named polygon groups. Start with a flat 104 × 104 diamond and four visible crease lines; over 1100ms fold the four corners inward at 0–420ms, close the side panels at 300–760ms, raise the base and illuminate the center at 680–1100ms. Finish on the same six-panel lantern silhouette used on canvas. Use transforms and opacity only, with no 3D library and no text on the paper. Under reduced motion, show the completed lantern immediately.
  - During releasing, draw a short amber trail and interpolate the personal lantern from y 0.78 to y 0.60 with easeOutCubic over 1.4 seconds while scale moves from 0.72 to 1. Afterward, apply the normal personal ascent speed of 9 + depth × 5 CSS pixels per second and the same wind rule. A personal lantern that leaves the viewport stays saved but becomes visually dormant; Release again resets its scene position. Reduced-motion release skips travel and trail, places the lantern immediately at y 0.58, announces success, and leaves the scene static.
  - Persist released wishes in localStorage under a versioned key derived from a lowercase hyphenated slug of [BRAND] plus '-lantern-wishes-v1'. Store at most 24 records in release order, assigning ordinals sequentially from 1 and storing no real dates. At 24 records, disable Release lantern for a new wish and show 'Your gallery holds 24 wishes. Remove one before releasing another.'; Release again remains available because it adds no record. Validate restored JSON for version, id, 3–120 character text, ordinal, and allowed paperTone; discard malformed records and recover silently from unavailable storage with an inline 'This browser could not save your gallery; this session still works.' message. Remove requires one inline confirmation, renumbers surviving records sequentially in release order, hides active personal lanterns with that wishId, and never contacts a server.
  - Use semantic DOM controls for the entire ritual: labeled textarea, three wish-prompt buttons, step buttons, native wind range, Pause or Resume, gallery Release again and Remove, and a Reset scene button that resets only camera/parallax and wind, not saved wishes. The canvas has an accessible summary naming [FESTIVAL_NAME], the current wind, and the number of released personal lanterns; it is not the only way to perform any action. Use visible focus, aria-current on the active composer step, aria-live polite for fold/release/save feedback, and do not announce animation frames.
  - For prefers-reduced-motion, render the initial stars, hills, river, and all lanterns as a complete static tableau; do not run ambient ascent, flicker, parallax, folding travel, release trails, or autonomous UI movement. Preserve write, fold, release, gallery, wind-label, and removal functions with immediate state changes. Listen for preference changes and stop or restart rendering appropriately without losing state.
  - Write ASSETS.md at the project root covering the original procedural scene and lantern geometry, original SVG folding preview and favicon, Lucide ISC, and all three Fontsource packages with OFL-1.1 licenses. Keep every runtime request local and dist/ below 20 MB. No generated, stock, downloaded, or placeholder image files are required for this template.

## Variables
- [BRAND] — Project name (default: "Avelume"). An invented short name for the wordmark, document title, footer, and local-storage namespace; never a real event or organization.
- [FESTIVAL_NAME] — Festival title (default: "The Stillwater Ascent"). A short invented gathering title used in the eyebrow, canvas description, gallery introduction, and footer.
- [HEADLINE] — Welcome headline (default: "Let your wish find the sky."). A clear five-to-nine-word invitation; adapt the supporting sentence if its meaning changes.
- [RIVER_NAME] — Fictional river or inlet (default: "River Elian"). An invented waterfront place used in the welcome and festival note; never a real landmark.
- [AUDIENCE] — Audience (default: "dreamers, friends, and quiet night wanderers"). A plain-language phrase used to shape the welcome, wish prompts, and guide copy.
- [WISH_THEMES] — Wish themes (default: "hope, gratitude, and new beginnings"). Three broad themes used to rewrite the twelve ambient wishes and three prompt suggestions without predictions or advice.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/paper-lantern-festival-page in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Don'ts
- Do not copy, trace, recolor, or closely imitate an existing lantern festival, event website, wish wall, or interactive lantern experience, including its code, prompt text, layout composition, illustrations, icons, copy, slogans, names, logos, mascots, or signature animation assets. The procedural scene and interaction here must remain original.
- Do not use real festival names, logos, branded lanterns, real people's likenesses, licensed characters, recognizable landmark skylines, culturally specific sacred symbols, religious iconography, or claims of cultural authenticity. Keep the river and event fictional and the paper craft generic.
- Do not copy wishes, ceremony copy, illustrations, textures, code, or animation assets from another source. The twelve ambient wishes, prompt suggestions, interface copy, and alternate-theme content must be newly written and kept in the content module.
- Do not present ambient lanterns as live visitors, wishes as public submissions, or the gallery as an online community. Never promise that wishes come true. Keep the imagined-festival and local-only disclosures visible and never request a name, email, location, account, or social profile.
- No backend, server code, API routes, database, authentication, remote form submission, analytics, third-party API, runtime fetch, tracking pixel, social widget, or public sharing service. Saved wishes stay in validated localStorage and contain only the declared id, text, ordinal, and paperTone fields.
- No CDN scripts or styles, Google Fonts URLs, hotlinked assets, externally hosted icons, placeholder-image services, Unsplash, Pexels, Pixabay, Google Images, or assets with unclear, noncommercial, or share-alike licenses. Use Vite base './', relative paths, locally bundled packages, and self-hosted Fontsource fonts.
- Do not add image generation, photographs, video, WebGL, Three.js, a canvas helper library, a state-management library, an animation framework, a router, or an external physics service. Native Canvas 2D, SVG, CSS, React state, and the declared packages are sufficient.
- Do not hard-code default brand, festival, headline, river, audience, wish themes, ambient wishes, prompt suggestions, or storage namespace outside src/content.ts. Alternate values must produce coherent new copy and twelve theme-appropriate wishes with no default remnants or unresolved [VARIABLE] placeholders.
- Do not bypass the write-fold-release state machine, allow duplicate submissions during release, save before Release lantern is activated, erase a draft when moving Back to wish, duplicate gallery records on Release again, or reset saved wishes with Reset scene. Follow the storage cap and validation rules exactly.
- Do not attach touch-action none to the canvas or page, require dragging to fold paper, make ambient lanterns mandatory click targets, use pointer-only controls, autoplay audio, scroll-jack, pin sections, use a custom cursor, or hide content behind scroll reveals. The complete ritual must work with keyboard and touch.
- Do not run unbounded lantern counts, per-frame React rendering, per-frame random or star-array allocation, uncapped device pixel ratio, animation while hidden, autonomous camera movement, or motion that ignores prefers-reduced-motion. Keep the fixed counts, frame caps, cleanup, and static reduced-motion tableau.
- Do not use excessive bloom, moving wish paragraphs, fake visitor counts, public usernames, timestamps, pricing, testimonials, newsletter forms, marketing sections, splash screens, or confetti. The festival scene and composer are the first screen and primary experience.
- Do not add extra pages, bare-directory links, SEO markup, structured data, Open Graph work, sitemap code, or metadata beyond the plain title, theme color, and original favicon. The only page is index.html and all navigation uses local anchors.
- Production npm run build must emit minified static dist/ below 20 MB with no source maps and no src/ copied into dist/. It must run without console errors at 1440 × 900 and 390 × 844, keep all tap targets at least 44px, preserve long wishes without clipping, and leave no horizontal page overflow.
