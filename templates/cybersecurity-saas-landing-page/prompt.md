# Cybersecurity SaaS Landing Page

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build an original single-page landing site for [BRAND], a [PRODUCT_CATEGORY] for [AUDIENCE]. The hero combines a clear sales pitch with a rich animated SVG world map labeled [EVENT_LABEL], a simulated event feed, and explicit sample-data notices. Continue through product modules, an incident workflow, illustrative customer outcomes, generic trust controls, a demo request form, FAQs, and a focused closing call to action.

- Audience: The site speaks to [AUDIENCE] who need to understand the product quickly and evaluate whether a guided walkthrough is worth their time. The template owner is a technical SaaS team that needs a polished, credible marketing page with a substantial product visualization rather than abstract decoration.
- Goal: Get visitors to understand the product's detection-to-response story, explore all four modules, recognize the sample nature of every metric and event, and complete a valid demo request preview. Every visible control must work locally, and no form data may leave or persist beyond the current page state.
- Tone: Calm, exact, operational, and assured. Use concrete product language and useful detail instead of fear, cinematic hacker clichés, vague superlatives, or unsupported security claims. Treat animated activity as illustrative interface content, never as evidence of real protection or live telemetry.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Tailwind CSS 3.4
- Libraries: React 18 (MIT), Vite 5 (MIT), TypeScript (Apache-2.0), Tailwind CSS 3.4 (MIT), motion (MIT), lucide-react (ISC), @fontsource-variable/space-grotesk (OFL-1.1), @fontsource-variable/inter (OFL-1.1), @fontsource/ibm-plex-mono (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Use Vite 5 with React 18 and TypeScript. Set base: './' in vite.config.ts, set build.sourcemap to false, and emit only static production files to dist/.
  - Configure Tailwind CSS 3.4 with the exact colors, font families, spacing, radii, and shadows below. Put map keyframes, focus styles, selection color, and reduced-motion overrides in src/index.css.
  - Keep all editable brand copy, headlines, module copy and data, map events, metrics, trust labels, FAQs, and form options in src/content.ts with TypeScript interfaces. Components must not embed copy that only fits the default topic.
  - When variable values change, rewrite every topic-specific headline, product module, event label, sample event, metric, workflow step, trust explanation, FAQ answer, and form option to fit [PRODUCT_CATEGORY], [AUDIENCE], and [EVENT_LABEL], while preserving the layout and interactions.
  - Use Motion for React for section entrances, product-tab transitions, accordion answers, and the request-preview state. Use original inline SVG and CSS keyframes for the map; do not add a mapping, charting, or animation dependency.
  - Create a deterministic ThreatMap component with fixed nodes, routes, and six predefined events. Use one cleaned-up interval to rotate the highlighted event every 2800ms; Pause feed must stop both the interval and decorative animation. Do not use random data or external telemetry.
  - Keep product tab state, mobile menu state, open FAQ state, feed pause state, and form state in React memory only. Do not use localStorage, sessionStorage, cookies, analytics, URL tracking parameters, or any network request.
  - Import Space Grotesk Variable, Inter Variable, and IBM Plex Mono locally from Fontsource. Create ASSETS.md listing the three font packages, lucide-react, their sources and licenses, and stating that all map and product artwork is original code-drawn SVG/CSS with no raster images.
  - Use semantic landmarks, labeled controls, visible focus, 44px minimum touch targets, keyboard-operable tabs and accordions, and reduced-motion behavior. Verify the complete page at 1440×900 and 390×844 with zero console errors and no horizontal overflow.

- [BRAND] — Product brand (default: "Sablegrid"). An invented product name used in the original bracket mark, header, copy, form preview, and footer.
- [PRODUCT_CATEGORY] — Product category (default: "threat detection and response platform"). A concise lowercase category phrase; all product and workflow copy must follow it.
- [AUDIENCE] — Primary audience (default: "lean security teams"). A concise lowercase audience description used in the hero and sales copy.
- [EVENT_LABEL] — Map event label (default: "Threat activity"). A short title-case label for the map and its simulated events, such as Data risk activity.
- [PRIMARY_CTA] — Primary call to action (default: "Request a demo"). A short button label that scrolls visitors to the local demo request form.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/cybersecurity-saas-landing-page in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design
### Colors
- Deep Field `#071114` — Page background, header, and footer
- Panel Ink `#0D1C20` — Map, product viewer, form, and raised section surfaces
- Raised Line `#173036` — Selected rows, input backgrounds, and quiet tonal blocks
- Grid Line `#28434A` — Borders, coordinate rules, dividers, and inactive tracks
- Mist `#E8F1EE` — Primary headings, body text on dark surfaces, and important values
- Slate Text `#93AAA9` — Secondary copy, metadata, labels, and inactive controls

- Alert Coral `#FF927A` — Only investigating events, one alert node, validation errors, and sparse emphasis
- Button Ink `#09201F` — Text and icons on Signal Mint buttons

### Typography
- Display headlines, section titles, and large sample metrics: Space Grotesk Variable, self-hosted with @fontsource-variable/space-grotesk (OFL), weights 500/600/700
- Body copy, navigation, buttons, tabs, and form controls: Inter Variable, self-hosted with @fontsource-variable/inter (OFL), weights 400/500/600/700
- Eyebrows, map coordinates, event metadata, badges, and small system labels: IBM Plex Mono, self-hosted with @fontsource/ibm-plex-mono (OFL), weights 400/500

### Layout & motion
- Spacing: Use an 8px base grid. Content max-width is 1280px with 40px desktop and 20px mobile gutters. Major sections use 112px desktop and 76px mobile vertical padding. The header is 72px high. Hero copy and visual columns have a 56px gap; panel padding is 24–32px desktop and 18–22px mobile. Keep body measures between 48 and 66 characters.
- Radius: Use 4px for tags and small badges, 8px for inputs and buttons, and 12px for major panels. Avoid pill-shaped containers except tiny status dots. Use 1px Grid Line borders and a restrained 0 20px 60px rgb(0 0 0 / 0.24) shadow only on the hero map and demo form.
- Motion: Reveal major sections once with Motion whileInView: opacity 0 to 1 and translateY(22px) to 0 over 480ms with a 60ms stagger between direct children; content must remain visible without JavaScript intersection support.
- Motion: On the hero map, animate route dash offset over 4.5 seconds and node rings from scale 0.75 to 1.35 with fading opacity over 2.4 seconds. Only one route and one node receive Alert Coral emphasis at a time.
- Motion: Advance the simulated highlighted event every 2800ms without adding or removing rows. Pause feed freezes dash, pulse, and interval motion and changes its label to Resume feed; restarting continues from the current event.
- Motion: Product views swap with AnimatePresence using 180ms opacity and translateX(10px) transitions inside a stable min-height viewer. Active tab indicator color changes over 160ms; content height must not jump dramatically.
- Motion: Buttons translate upward 1px on hover and return on press over 140ms. Accordion answers use 180ms opacity and height transitions, and the mobile menu uses a 160ms fade and 8px downward entrance.
- Motion: The request preview replaces the form with a 220ms opacity and 12px rise transition, then moves focus to its heading. Copy request changes its button label to Request copied for 1600ms.
- Motion: Under prefers-reduced-motion, remove section reveals, route movement, node pulses, automatic event rotation, smooth scrolling, and transform transitions. Show the complete static feed and final component states immediately.
- Imagery: Use no photographs, generated bitmaps, external maps, stock illustrations, or image placeholders. The hero anchor is a large original SVG operational map: simplified hand-authored continent silhouettes, a subtle dot matrix, longitude and latitude guides, six fixed location nodes, curved routes, crosshair details, and a compact event rail. Draw four distinct product-module interfaces in HTML/CSS/SVG. Use only abstract bracket, node, route, waveform, and ledger motifs; no shields, hooded figures, skulls, padlock clichés, brand logos, or certification seals.

## Don'ts
- Do not add a backend, serverless function, API route, database, authentication, live telemetry, external map service, third-party API, form endpoint, or network-dependent behavior. The demo form only validates and previews local state and must never claim a request was sent or booked.
- Do not transmit or persist names, email addresses, company details, or any other input. No localStorage, sessionStorage, cookies, analytics, tracking pixels, hidden telemetry, or URL tracking parameters.
- Do not load any CDN script, stylesheet, font, icon, map tile, image, or remote asset. Bundle all dependencies and use relative asset paths with Vite base './'.
- Do not use real cybersecurity companies, product names, logos, customer marks, slogans, proprietary interfaces, exact copy, or recognizable brand color systems. Keep [BRAND] and all organizations and people fictional.
- Do not use official certification seals, auditor marks, compliance logos, security guarantees, real attack attribution, real threat intelligence, customer results, or unverified claims. Retain visible SAMPLE DATA and simulated-feed labels.
- Do not use shields, hooded hackers, skulls, glowing padlocks, fingerprint clichés, purple-blue neon gradients, matrix rain, stock hacker photography, anime or game characters, or real-person likenesses.
- Do not copy map artwork or interface code from another product. Use the original hand-authored SVG geometry and predefined sample events specified here; no external geoJSON, tile service, or chart library.
- Do not use commercial fonts, fonts.googleapis.com, fonts.gstatic.com, Adobe Fonts, restricted UI source, non-permissive packages, or dependencies outside the fixed stack.
- Do not use Unsplash, Pexels, Pixabay, Google Images, placeholder-image services, generated bitmaps, third-party logos, or hotlinked files. No raster images are needed.
- Do not leave navigation, feed pause, module tabs, detection switch, graph nodes, FAQ items, demo form, copy action, edit action, or closing CTA nonfunctional. Do not add dead social, login, legal, or integration links.
- Do not emit source maps, copy src/ into dist/, exceed 20 MB in dist/, or require more than npm run build for the production output. Keep everything in index.html with file-name or hash-only local navigation.
- Do not hard-code default threat content inside components or leave Sablegrid security copy in an alternate-variable build. Keep all editable copy and sample data in src/content.ts and use US English throughout.
- Do not add SEO metadata, Open Graph tags, JSON-LD, sitemaps, keyword-stuffed headings, dates, or analytics; a plain [BRAND] document title and original favicon are enough.
- Do not mention VibeFather, its license, pricing, metrics, or membership anywhere in the site except the optional rendered [CREDIT] footer link.
- Do not sacrifice accessibility or responsive behavior: maintain visible focus, semantic controls, labeled fields, keyboard-operable tabs and accordions, accessible error focus, reduced-motion support, 44px touch targets, zero console errors, and no horizontal overflow at 390×844 or 1440×900.
