# Personal Budget Dashboard

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build an original, complete personal budget app branded [BRAND] for [OWNER_NAME], whose sample plan concerns [BUDGET_CONTEXT]. Use a monthly overview with a category donut and daily spending chart, a searchable and filterable transaction ledger, editable budget goals with progress bars, and an accessible add-transaction dialog. Seed believable fixed data for [SAMPLE_MONTH], format amounts with [CURRENCY], and persist transactions and targets in localStorage. The polished application workspace is the first-screen visual anchor; do not add a marketing hero.

- Audience: Individuals, students, households, and freelancers who want to understand a monthly plan and practice a complete budgeting workflow without signing up, linking financial accounts, or sending personal data to a service.
- Goal: Let a visitor understand the sample month at a glance, find any transaction, adjust a category target, add an income or expense, and see every dependent figure and chart update correctly before and after a reload.
- Tone: Calm, precise, encouraging, and nonjudgmental. Use short practical labels and plain helper text. Never shame overspending, promise savings, provide financial advice, or imply that sample data came from a real account.

## Stack
- Framework: Vite 6 + React 19 + TypeScript
- Styling: Tailwind CSS 4.1
- Libraries: motion (motion.dev, import from 'motion/react') (MIT), lucide-react (ISC), @fontsource-variable/fraunces (OFL), @fontsource-variable/inter (OFL), @fontsource/ibm-plex-mono (OFL)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Set Vite base to './' and build.sourcemap to false; emit minified static files to dist/ with relative asset paths and no src/ directory copied into it.
  - Use Tailwind CSS 4 with its Vite plugin. Define the color, font, radius, shadow, and motion tokens from Design in src/index.css; use CSS media queries for responsive layout and prefers-reduced-motion.
  - Keep all copy, variable values, category metadata, merchants, transactions, budget targets, chart labels, and empty-state text in src/content.ts. When [BRAND], [OWNER_NAME], [BUDGET_CONTEXT], [CURRENCY], or [SAMPLE_MONTH] changes, rewrite every context-dependent employer, merchant, note, owner label, sample date, and storage namespace so no household-specific or freelance-specific content is left stale.
  - Define canonical Transaction and CategoryBudget types in src/lib/budget.ts. Store money as integer minor units, keep income positive and expenses negative only at the input boundary, and derive every total, chart series, percentage, goal state, and filtered row with pure functions. Never hard-code a displayed KPI separately from the transaction data or render NaN.
  - Implement a small hash router without another dependency: ./index.html and ./index.html#/overview show Overview, ./index.html#/transactions shows Transactions, and ./index.html#/goals shows Goals. Unknown hashes return to Overview. Preserve the shared shell and local data across view changes.
  - Create a versioned localStorage repository in src/lib/storage.ts with a namespace derived from [BRAND]. Seed only when no valid saved dataset exists, persist transactions and edited targets after each mutation, guard malformed JSON and storage or quota errors with a nonblocking message, and make Reset demo data restore the variable-derived seed after confirmation.
  - Use native dialog elements or an equally complete accessible implementation for Add transaction, Adjust target, and Reset confirmation: visible labels, initial focus, trapped focus, Escape to close, a close button, focus return to the invoker, and no background interaction while open.
  - Draw the donut, daily spending bars, and goal progress visuals with inline SVG or CSS from derived data. Provide text equivalents and accessible names; chart hover or tap details may enhance but must never replace visible values.
  - Use a plain document title containing [BRAND], an original local SVG favicon, and an ASSETS.md at the project root that lists the code-drawn visuals plus every font and icon package with package path, upstream source, author, and license.

## Variables
- [BRAND] — Budget app brand (default: "Willowsum"). Invented product name used in the wordmark, document title, and localStorage namespace.
- [OWNER_NAME] — Sample budget owner (default: "Maya Chen"). Fictional person whose first name and initials personalize the workspace; no portrait or real personal data.
- [BUDGET_CONTEXT] — Sample budget context (default: "a two-income household"). Short lowercase phrase that drives the sample income sources, merchants, notes, and one flexible spending category.
- [CURRENCY] — Display currency (default: "USD"). ISO currency code for local number formatting only; changing it must not claim to convert values at an exchange rate.
- [SAMPLE_MONTH] — Primary sample month (default: "May 2026"). Fixed sample month for all default dates and headings; derive the previous and next sample months without reading the real clock.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/personal-budget-dashboard in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

- Motion: Toasts rise 8px and fade over 160ms, remain readable for at least 4 seconds, and can be dismissed manually.
- Motion: Under prefers-reduced-motion, remove chart drawing, stagger, sliding, and interpolation; render final states immediately while preserving every focus and status change.
- Imagery: Use no photographs, stock images, generated images, avatars, or external illustrations. The rich budget interface is the visual anchor: a forest navigation rail, a ruled financial summary, a large multi-segment SVG donut, and a dense daily-spending chart. Draw an original [BRAND] mark as a 28px forest square containing three ivory ledger lines and one chartreuse dot. ## Don'ts
- Do not add a backend, server routes, accounts, authentication, database, cloud sync, bank linking, analytics, third-party APIs, live exchange rates, or any network submission; all behavior and persistence are local.
- Do not copy an existing budgeting or banking product's layout, copy, charts, illustrations, icons, slogans, or visual identity; the interface and all sample content must remain original.
- Do not use real banks, employers, merchants, account identities, account numbers, receipts, personal financial records, or claims that the sample is connected to a real account.
- Do not give financial advice, shame spending, promise savings or returns, fabricate security claims, or describe localStorage as encrypted, backed up, synced, or available on another device.
- Do not use chart, table, form, or drag-and-drop libraries; use hand-drawn SVG or CSS visuals, semantic tables and lists, native controls, and the specified Motion and Lucide packages only.
- Do not use photographs, generated images, avatars, stock-image services, recognizable brand logos, commercial fonts, CDN scripts, CDN CSS, Google Fonts, Adobe Fonts, or hotlinked assets.
- Do not read the real clock to create today labels or transaction dates. Use fixed dates derived from [SAMPLE_MONTH] and the two adjacent sample months, with all sample content stored explicitly in src/content.ts.
- Do not hard-code default merchants, income sources, notes, owner details, month labels, or currency-specific copy outside src/content.ts, and do not leave household content stale when [BUDGET_CONTEXT] or another variable changes.
- Do not allow inconsistent totals, stale charts, NaN, invalid amounts, duplicate submissions, silent storage failures, or target edits that erase transactions. Derive all views from the canonical state and use integer minor units.
- Do not add landing-page sections, pricing, testimonials, sign-up forms, carousels, decorative gradients, glass effects, unrelated widgets, extra routes, or bare-directory links; keep only Overview, Transactions, and Goals at the specified file and hash URLs.
- Do not ship source maps, src/ in dist/, remote assets, absolute asset paths, or a dist/ bundle over 20 MB; npm run build must produce static files with zero console errors.
- Do not mention VibeFather inside the app except the optional credit link; keep all interface copy, sample data, validation messages, and accessible labels in US English.
- Do not sacrifice visible labels, keyboard operation, focus trapping and return, semantic tables, 44px mobile targets, readable contrast, text status in addition to color, reduced-motion support, or the 1440×900 and 390×844 layouts.
