# 3D Cathedral Light Tour

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a one-page first-person architecture tour for [BRAND]'s fictional [BUILDING_NAME], presented as an original [ARCHITECTURE] interior for [AUDIENCE]. The default is a Gothic cathedral nave modeled entirely with Three.js primitives and custom BufferGeometry. A full-viewport threshold view leads into six scroll-linked architectural stops; a shared time-of-day slider changes the sun, stained-glass glow, and colored floor projections. When variable values change, keep the six-stop tour, editorial layout, lighting controls, and field-note structure but redesign the procedural architecture, stop explanations, dimensions, and visual details to fit the new [ARCHITECTURE] and [BUILDING_NAME].

- Audience: [AUDIENCE], plus educators, museum interpreters, designers, and curious visitors who benefit from seeing architectural structure and daylight together. The default copy introduces core Gothic vocabulary without assuming prior architectural training.
- Goal: Let visitors identify six major architectural elements, understand their structural or spatial purpose, and observe how window position and time of day alter colored light. The primary action, [PRIMARY_CTA], advances from the threshold into the guided route; field-note controls provide direct non-scroll access to every stop.
- Tone: Contemplative, precise, welcoming, and visually cinematic. Use short declarative explanations and clearly labeled illustrative dimensions. The experience should feel like an intimate architecture exhibit, not a horror scene, fantasy game, religious service, real-estate listing, or generic landing page.

## Stack
- Framework: Vite 6 + TypeScript
- Styling: Vanilla CSS
- Libraries: three (MIT), lucide (ISC), @fontsource-variable/newsreader (OFL), @fontsource-variable/inter (OFL), @fontsource/ibm-plex-mono (OFL)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Use Vite with strict TypeScript. Set base: './', build.outDir: 'dist', build.emptyOutDir: true, and build.sourcemap: false in vite.config.ts; npm run build must emit only static production files. Do not substitute React, another renderer, Tailwind, a scroll library, or a global state package.
  - Install only three, lucide, @fontsource-variable/newsreader, @fontsource-variable/inter, and @fontsource/ibm-plex-mono as runtime dependencies, plus Vite, TypeScript, and @types/three as development dependencies. Import all fonts, scripts, and icons locally.
  - Create src/content.ts as the single source for resolved variable values, navigation, hero copy, six tour stops, camera keyframes, field notes, light presets, labels, and footer copy. Include the default [BRAND], [BUILDING_NAME], [ARCHITECTURE], [AUDIENCE], and [PRIMARY_CTA] values there, rewrite all architecture-specific content when values change, and never leave square-bracket variable tokens visible.
  - Organize scene code into modules for architecture geometry, stained glass, materials, lighting, camera route, projections, and rendering; keep DOM code separate for navigation, captions, controls, diagrams, and accessibility. Use one shared state containing tourProgress, activeStop, timeMinutes, lookOffset, menuOpen, quality, and webglAvailable.
  - Use scene units as illustrative meters. The default nave is 16m wide with a 6m central aisle, 22m vault crown, six 8m bays, and an apse wall at z=-52. Place seven pairs of structural piers at x=±4.8 and z=4,-4,-12,-20,-28,-36,-44. Give each pier a stone core and twelve engaged shafts. Build pointed arches from paired quadratic curves, four curved rib segments per bay with TubeGeometry, thin custom BufferGeometry vault webs, a stone floor with subtle procedural vertex-color variation, and twelve abstract lancet windows at the six bay centers on x=±7.9.
  - Create original abstract stained glass from colored geometric meshes and dark lead came: circles, diamonds, shards, and simple rosette geometry only, with no people, saints, heraldry, writing, or copied church patterns. Duplicate simplified glass shapes as transparent additive floor-projection meshes 0.015m above the floor; do not use image textures, decal downloads, or photographed light.
  - Use MeshStandardMaterial for stone and floor, MeshPhysicalMaterial for glass, ACESFilmicToneMapping, exposure 1.05, one shadow-casting DirectionalLight, one HemisphereLight, at most three low-intensity colored SpotLights, and restrained scene fog. Cap pixel ratio at 1.5 on desktop and 1.25 on mobile, use a 1024px shadow map only on desktop, reduce dust and geometry detail on mobile, and pause rendering while the tour is outside the viewport or the document is hidden.
  - Create the time model from minutes 360–1200 inclusive in 15-minute steps. Let u=(minutes-360)/840, solar elevation=sin(πu)×58°, azimuth=75°+210°×u, sun intensity=0.25+2.25×sin(πu), hemisphere intensity=0.12+0.38×sin(πu), glass emissive intensity=0.3+1.1×sin(πu), and projection opacity=0.12+0.58×sin(πu). Move, rotate, skew, and scale the projection geometry from the same u; projection length is clamp(8,18/max(tan(elevation),0.18),32) meters. Warm the light near dawn and dusk without making noon pure blue.
  - Provide an original inline SVG nave illustration as the no-WebGL fallback, with the current stop highlighted and a simplified colored floor projection controlled by the same time input. Keep all captions, field notes, preset controls, and navigation usable without canvas or WebGL; never show a blank scene or a browser-alert error.
  - Use Lucide only for Menu, X, ArrowDown, ChevronLeft, ChevronRight, RotateCcw, Sun, and BookOpen. Give every icon button an accessible text label and at least a 44px touch target. Centralize responsive rules in src/styles.css, include visible keyboard focus and safe-area insets, support 1440×900 and 390×844 without horizontal overflow or console errors, and dispose geometries, materials, listeners, and the renderer on teardown.

## Variables

- [BUILDING_NAME] — Fictional building (default: "Alderquay Cathedral"). Invented building name used throughout the tour; it must not identify or closely imitate a real cathedral.
- [ARCHITECTURE] — Architectural style (default: "Gothic"). Architectural direction for the procedural geometry, vocabulary, materials, glass patterns, and all six explanations.
- [AUDIENCE] — Audience (default: "architecture students"). Lowercase descriptive audience phrase that fits naturally after for in introductory copy.
- [PRIMARY_CTA] — Primary action (default: "Begin the light tour"). Short button label that advances from the threshold to the next architectural stop.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/3d-cathedral-light-tour in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design

- Walnut panel `#1B1916` — Header, caption, light-console, and mobile-menu surfaces at 92–96% opacity.

### Layout & motion
- Spacing: Use an 8px base unit, a maximum content width of 1440px, 40px desktop gutters, and 20px mobile gutters. Ordinary sections use 112px desktop and 76px mobile vertical padding with a 12-column grid and 24px gaps. Keep body measure between 50 and 66 characters. Caption padding is 28px desktop and 20px mobile; light-control gaps are 12–16px. Preserve 72px desktop and 64px mobile header clearance.
- Radius: Use 2px on buttons and range controls, 6px on captions and the light console, and no rounding on major sections or field-note rows. Avoid generic floating glass-card grids. Circles are reserved for progress dots and the sun-symbol control.
- Motion: On first entry, reveal the hero copy with a 16px rise over 550ms and ease the threshold camera from z=9 to z=7 over 900ms. After entry the camera is controlled only by scroll and deliberate look input; remove both entrance movements when reduced motion is requested.
- Motion: Map normalized tour progress 0,0.2,0.4,0.6,0.8,1 directly to the six camera keyframes. Interpolate camera position and look target with smoothstep, then call lookAt; never use time-based triggers that can drift from scroll. Do not hijack the wheel, snap the page, or block native scrolling.
- Motion: At each stop, allow horizontal drag to add at most ±30° yaw and vertical drag or pointer movement to add at most ±18° pitch around the current look target. Reset view removes only these offsets. On touchscreens horizontal drag looks around while vertical touch movement continues to scroll the document.
- Motion: Time-of-day changes update sun, hemisphere light, glass emissive intensity, spotlights, projection geometry, SVG diagram, and readouts from one timeMinutes value. Smooth visual lighting changes over 180ms unless reduced motion is requested; the displayed numeric value updates immediately and there is no automatic day cycle.
- Motion: Use 160–220ms opacity and at most 6px translation for captions, menus, preset buttons, and field-note return links. Active-stop changes must not wait for a long stagger, and all text remains present in the DOM for assistive technology.
- Motion: A restrained field of 180 desktop or 60 mobile dust motes may drift slowly inside the light shafts. Stop dust, entrance easing, look smoothing, and lighting interpolation under prefers-reduced-motion; scroll then selects discrete camera states instantly while every stop and manual control remains available.
- Imagery: The only hero visual is an original high-craft procedural Three.js [ARCHITECTURE] interior seen from first-person eye level. The default scene must immediately read as a Gothic nave through repeated clustered piers, pointed arcades, ribbed vaults, tall abstract stained-glass lancets, warm limestone, and colored light across a stone floor. All geometry, glass designs, material variation, dust, and projections are generated in code. No photographs, AI-generated images, downloaded models, HDRIs, texture maps, religious figures, recognizable landmarks, people, or logos are used. Original inline SVG supplies the architectural section and no-WebGL fallback; Lucide supplies only interface icons.

## Don'ts
- Do not use or mention Kimi, Kimi K3.1 Pro, or 3D Make in the rendered site, and do not reuse their names, wordmarks, logos, product identity, Chinese copy, interface arrangement, or signature visual details.
- Do not reproduce the reference cathedral's exact geometry, dimensions, stained-glass designs, scene composition, camera path, source code, prompt text, screenshots, models, textures, icons, audio, video, or any other reference asset.
- Do not identify a real cathedral or copy its floor plan, facade, artwork, heraldry, religious figures, slogans, or institutional identity. The building, abstract glass patterns, annotations, and dimensions must remain original and fictional.
- Do not use real people's likenesses, third-party brands, commercial fonts, restricted library source, or identifiable commercial architectural visualizations.
- Do not load photographs, AI-generated images, external 3D models, HDRIs, texture maps, placeholder-image services, brand logos, or media from a CDN. The complete scene must be generated from code and dist/ must remain under 20MB.
- Do not add a backend, API routes, databases, authentication, analytics, remote forms, tracking pixels, or third-party API calls. Tour, lighting, presets, navigation, and fallback behavior must work entirely in the browser.
- Do not load fonts from Google Fonts or any other CDN. Use only the listed local Fontsource packages and their specified OFL fonts and weights.
- Do not change the fixed Vite, TypeScript, Three.js, and vanilla CSS stack; do not add React, Tailwind, a physics engine, a global state package, a scroll-jacking library, or an animation dependency for effects already specified with interpolation.
- Do not emit source maps, copy src/ into dist/, use absolute asset URLs, or require a server. Set Vite base to './' and ensure dist/ contains only the production static build.
- Do not use bare-directory links or create empty detail pages. This is one index.html page; every navigation link must use './index.html#tour', './index.html#light', or './index.html#notes'.
- Do not hide essential architectural information inside canvas-only text. Every stop and field note must exist as accessible HTML, with keyboard-operable controls, visible focus, useful aria labels, and a meaningful no-WebGL SVG fallback.
- Do not let look-around gestures trap vertical page scrolling. On mobile use horizontal drag for look and preserve vertical touch scrolling, keep targets at least 44px, and verify 390×844 without clipped captions, overlapping light controls, or horizontal overflow.
- Do not autoplay a camera route or daylight cycle, force scroll snapping, or ignore reduced motion. Remove dust, smoothing, and decorative movement when requested and retain instant manual state changes.
- Do not display dates, fake visitor numbers, ticket offers, unverified historical claims, real institutional affiliations, or claims that illustrative dimensions and daylight readings came from a surveyed building.
- Do not add SEO metadata blocks, structured data, sitemap instructions, keyword-stuffed headings, or template-provider branding inside the demo. A plain document title, simple favicon, and optional [CREDIT] footer link are sufficient.
- Do not hard-code default-only architecture copy outside src/content.ts or leave variable tokens visible. When variables change, rewrite the procedural style, stop names, explanations, dimensions, glass patterns, diagrams, and all architecture-specific copy together.
