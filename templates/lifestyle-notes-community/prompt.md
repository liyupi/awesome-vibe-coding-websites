# Lifestyle Notes Community

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build [BRAND], an original English-language lifestyle notes community centered on [NICHE] for [AUDIENCE]. The product is a polished three-page static web app: a masonry discovery feed at index.html, an immersive note detail at note.html, and a featured creator profile at profile.html. The default brand is Morrow & Moss and its editorial promise is 'Small rituals, beautifully shared.' Every screen must feel populated, intentional, and usable rather than like a marketing mockup.

- Audience: Creators, independent publishers, designers, and community builders who want an image-led notes product for [AUDIENCE], with realistic content and social interactions that work entirely in the browser.
- Goal: Let visitors discover visual notes, filter and search them, open a complete note, swipe through its photography, react and comment, then continue to the featured creator's notes and collections. Keep all content swappable through five variables while preserving the same layout and interaction model.
- Tone: Warm, observant, specific, and quietly optimistic. Write like thoughtful people sharing useful details from daily life, never like an engagement farm. Use concise US English, invented names, original conversations, and no claims about real users or online activity.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Tailwind CSS 3.4
- Libraries: Vite 5 (MIT), React 18 (MIT), Tailwind CSS 3.4 (MIT), Motion (MIT), lucide-react (ISC), @fontsource-variable/fraunces (OFL-1.1), @fontsource-variable/dm-sans (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Configure Vite with base './', build.sourcemap false, and three explicit HTML entry points: index.html, note.html, and profile.html. Each HTML file loads its own small React entry that shares components and content.
  - Use Tailwind for layout and state styling, with the supplied colors, spacing, radii, and font families in the theme. Add only a small global stylesheet for base typography, masonry columns, focus states, and reduced-motion overrides.
  - Put all variable values, navigation labels, notes, creator bios, tags, comments, collections, image paths, alt text, and calls to action in src/content.ts. Rewrite every content item to suit changed variable values; do not leave slow-living copy in an alternate case.
  - Create shared TypeScript models and a small localStorage store whose key is derived from a slug of [BRAND]. Persist likes, saves, follows, added comments, and selected creator tab locally; sample counts and conversations are fictional and never fetched.
  - Import Fraunces Variable and DM Sans Variable from their Fontsource packages and use Lucide React icons. Bundle all six supplied images from public/images; no remote fonts, icons, scripts, or images.
  - Use shared accessible buttons, visible keyboard focus, descriptive labels, and a skip link. Support 1440×900 and 390×844 without overflow, provide touch targets of at least 44px, and honor prefers-reduced-motion.

## Variables
- [BRAND] — Community name (default: "Morrow & Moss"). An invented two- or three-word lifestyle community name.
- [NICHE] — Community focus (default: "slow living and thoughtful homes"). The subject shared by all notes and collections.
- [AUDIENCE] — Audience (default: "people creating calmer, more personal spaces"). The people this community is meant to serve.
- [TAGLINE] — Editorial promise (default: "Small rituals, beautifully shared."). A short original sentence used as the discovery-page headline.
- [CREATOR_NAME] — Featured creator (default: "Maya Ellison"). An invented creator whose profile, notes, and collections are featured.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/lifestyle-notes-community in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design

### Typography
- Display and note titles: Fraunces Variable (OFL), weights 400/500/600
- Interface, body, and metadata: DM Sans Variable (OFL), weights 400/500/600/700

### Layout & motion
- Spacing: Use an 8px base grid with a 1360px maximum content width, 40px desktop gutters, 20px mobile gutters, and a 72px desktop header. The discovery hero is a 5/7-column split with 48px between columns, 56px top padding, and 40px bottom padding. Feed cards have 20px text blocks and 28px masonry gaps. Note reading copy is capped at 640px. Mobile uses 24px section gaps and a 64px bottom navigation clearance.
- Radius: Use 20px for feature and note cards, 16px for image frames and inputs, 12px for small buttons, and full pills for tags and counters. Keep shadows minimal: 0 12px 36px rgba(36,37,31,0.08) only on the floating carousel controls and mobile navigation.
- Motion: On first load, fade the hero copy and feature image in over 420ms with a 12px upward offset and a 70ms stagger; do not animate again when returning to the page.
- Motion: Use Motion layout animations for masonry filter and search changes, 260ms with easing [0.22,1,0.36,1], while preserving document reading order and focus.
- Motion: Move carousel slides horizontally with a 280ms ease-out transition; support pointer swipe with a 45px threshold, touch swipe, arrow buttons, dots, and left/right keyboard keys without autoplay.
- Motion: Give like and save controls a 160ms icon fill and 0.92-to-1 scale response, and animate follow-state text with a simple 160ms crossfade.
- Motion: Use 180ms fade-and-8px-rise transitions between Notes and Collections and for locally added comments. Disable transforms and smooth scrolling when reduced motion is requested.
- Imagery: Use only the six coordinated local editorial lifestyle photographs listed in assets: morning-table.webp, reading-corner.webp, ceramic-hands.webp, kitchen-ritual.webp, balcony-garden.webp, and creator-portrait.webp. They share warm ivory, muted sage, terracotta, and caramel tones, soft window light, natural grain, and tactile unstyled imperfection. Reuse them deliberately across notes and collection collages with stable aspect-ratio containers and focal-point crops rather than stretching. The featured creator portrait is an entirely fictional adult and must not resemble a real individual. No readable packaging, text, logos, recognizable brands, landmarks, celebrities, or real people's likenesses. Every image gets content-specific US English alt text from src/content.ts; decorative duplicates use empty alt text.

## Don'ts
- Do not use any existing lifestyle or social platform's name, logo, mascot, slogan, exact palette, custom font, unique iconography, code, copy, photography, or signature interface composition.
- Do not use real people's likenesses, celebrities, licensed characters, recognizable product branding, readable packaging, or third-party logos. The generated creator must remain an explicitly fictional person.
- Do not add a backend, authentication, database, API routes, third-party APIs, analytics, real posting, remote comments, or network-dependent social counts. All interactions and persistence must be honest browser-only behavior.
- Do not hotlink assets or load scripts, fonts, icons, or images from CDNs. Do not use Unsplash, Pexels, Pixabay, placeholder-image services, restricted component source, or non-permissive dependencies.
- Do not use commercial fonts or external font services; ship only the specified self-hosted OFL Fontsource families.
- Do not leave placeholder copy, lorem ipsum, slow-living remnants in an alternate case, empty detail views, dead buttons, nonfunctional tabs, or unimplemented navigation. note.html without a valid id must show morning-reset.
- Do not use bare-directory links, client-only routes that break on static hosting, source maps, copied src directories, or absolute production asset paths. Use ./index.html, ./note.html, and ./profile.html with relative assets and Vite base './'.
- Do not display dates, fabricated live-status indicators, online-member claims, or engagement numbers presented as real activity. All people, conversations, and counts are fictional sample content.
- Do not make the first screen typography-only, replace the photographic feed with generic cards, add autoplay to the carousel, or hide article content behind scroll animations.
- Do not exceed 20 MB in dist/, ignore mobile touch gestures or keyboard controls, allow horizontal overflow at 390px, or ship console errors. Respect prefers-reduced-motion throughout.
- Do not mention VibeFather inside the product except the optional [CREDIT] footer link. Keep all site copy, sample data, labels, and alt text in US English.
