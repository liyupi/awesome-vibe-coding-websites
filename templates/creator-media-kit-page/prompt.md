# Creator Media Kit Page

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a polished one-page media kit for [BRAND], an independent creator working in [CREATOR_NICHE]. Write for [AUDIENCE], use [MEDIA_KIT_TAGLINE] as the hero message, and set the creator in [LOCATION]. The page must combine a personal introduction, sample audience analytics, content-channel fit, fictional partnership cases, clear sample rates, and a client-only sponsorship inquiry draft.

- Audience: Independent creators and freelancers who need to present their work to sponsors, plus the marketers, founders, and small-brand teams evaluating a potential partnership.
- Goal: Help a prospective sponsor understand the creator's audience, see the available content formats and collaboration evidence, compare packages, and turn their project details into a copyable inquiry without implying that anything was transmitted.
- Tone: Warm, assured, specific, and editorial; commercially useful without sounding corporate, and transparent about every illustrative statistic, outcome, price, and local-only interaction.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Tailwind CSS 3.4
- Libraries: React + ReactDOM (MIT), Tailwind CSS (MIT), lucide-react (ISC)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Configure vite.config.ts with base './' and build.sourcemap false for a single index.html entry and a self-contained static build.
  - Extend the Tailwind theme with the exact Design colors and font families; put chart transitions, reveal keyframes, focus-visible rings, disclosure states, and reduced-motion overrides in src/index.css.
  - Keep every headline, paragraph, sample metric, chart datum, channel, case study, package, form label, image path, alt text, and link in src/content.ts, keyed by section. The supplied copy is for the default variable values; whenever values change, coherently rewrite every dependent proper noun, statistic context, campaign, package description, and image alt text and remove all default-only references.
  - Build all charts with local React components and inline SVG; use no charting package. Give each chart visible labels and values, a concise screen-reader summary, and keyboard-focusable data points when tooltips are available.
  - Self-host Newsreader, Inter, and IBM Plex Mono by importing the specified Fontsource packages in src/main.tsx; never use a font CDN.
  - Create an original four-petal spark favicon in SVG from the Design colors and set only a plain document title containing [BRAND] and 'Media Kit'; do not add SEO metadata beyond that.

## Variables
- [BRAND] — Creator name or public identity (default: "Nora Vale"). An invented creator identity used in the wordmark, biography, footer, document title, and inquiry copy.
- [CREATOR_NICHE] — Creator subject and content niche (default: "small-space gardening and mindful city living"). A concise niche phrase that drives channel descriptions, audience interests, and campaign examples.
- [AUDIENCE] — Primary content audience (default: "urban renters, first-time gardeners, and slow-living enthusiasts"). The community the creator serves; rewrite audience labels and partnership fit when this changes.
- [LOCATION] — Creator home base (default: "Portland, Oregon"). A short city-and-region label, not a street address.
- [MEDIA_KIT_TAGLINE] — Media kit hero tagline (default: "Make room for a greener everyday."). An original short line expressing the creator's point of view.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/creator-media-kit-page in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design

- Paper `#FFFCF6` — Chart, form, rate-card, and case-study surfaces

### Typography

- Body copy, navigation, buttons, and form controls: Inter Variable (OFL), weights 400/500/600/700
- Statistics, chart labels, package prices, and eyebrows: IBM Plex Mono (OFL), weights 400/500

### Layout & motion
- Spacing: Use a 4px base unit, a maximum content width of 1320px, 20px mobile and 48px desktop gutters, and a 12-column desktop grid with 24px gaps. Section padding is 72px mobile and 112px desktop, with compact 32px stat-band spacing. Card padding is 24–32px. Keep reading copy to 62 characters per line and never let large metrics force horizontal overflow.
- Radius: Use 2px on small labels, 10px on buttons and inputs, 20px on charts and case cards, and 28px on the hero photograph and large feature panels. Use 999px only for compact filter-like tags. Borders are 1px Ink at 14% opacity; shadows are limited to a subtle 0 12px 36px Ink at 7% on the hero and inquiry panels.
- Motion: Reveal major sections once with IntersectionObserver: opacity 0 to 1 and translateY 18px to 0 over 450ms, with a 70ms stagger between siblings and no scroll-jacking.
- Motion: When the audience section first enters, count numeric values from zero to their final displayed values over 800ms, scale horizontal bars from the left, and draw the line chart with stroke-dashoffset; screen readers receive final values immediately.
- Motion: Buttons, campaign disclosures, chart points, and navigation links respond within 160–220ms using color, underline, arrow translation of 4px, or chevron rotation rather than bouncing.
- Motion: Selecting a rate package updates the inquiry selection and scrolls to the form only after the explicit click; the destination field receives a visible focus indicator without unexpected form submission.
- Motion: Under prefers-reduced-motion, show final numbers and complete charts immediately, remove reveals and smooth scrolling, and keep every disclosure, selection, tooltip, and form state fully functional.
- Imagery: Use exactly the two coordinated generated photographs listed in Assets: a spacious environmental working portrait as the first-screen anchor and a close crop of the same fictional creator's hands at a worktable in the collaboration section. The person is fictional, does not resemble any real individual, and is shown from behind or by hands only so no face is recognizable. Both images share a lived-in home studio, moss linen, parchment walls, persimmon ceramics, leafy green plants, soft morning window light, and restrained editorial film grain. Draw all three partnership covers locally as original SVG compositions of leaves, arcs, grids, circles, and abstract packaging shapes in Canvas, Persimmon, Soft Persimmon, Moss, and Ink; the invented partner name is the only text. Do not add any other photographs, people, client artwork, external logos, or recognizable product designs.

## Don'ts
- Do not use real creator names, recognizable people, copied biographies, real audience figures, testimonials, or performance claims. The creator and every partner must be fictional, and all metrics, outcomes, and prices must retain visible sample-data labels.
- Do not use existing social-platform logos, partner logos, brand marks, slogans, campaign artwork, proprietary interface screenshots, or recognizable product designs. Use generic channel names, permissive Lucide icons, and the specified original SVG campaign covers.
- Do not hotlink any asset in the finished site, use placeholder-image services, or add Unsplash, Pexels, Pixabay, Google Images, CC BY-NC, or CC BY-SA material. Keep exactly the two supplied generated photographs local and preserve their credits in ASSETS.md.
- Do not add other people, portraits, faces, brand mascots, anime or game characters, signature illustrations, or external artwork. The hero and process imagery must remain the two specified generated images with no recognizable face.
- Do not load commercial fonts, fonts.googleapis.com, fonts.gstatic.com, Adobe Fonts, CDN scripts, CDN stylesheets, analytics, live audience services, social-media APIs, or any third-party API. Self-host every font, icon, image, and script.
- Do not use Aceternity UI source, Tailwind Plus or Tailwind UI source, purchased templates, packages without allowed licenses, restricted component source, or a charting library; implement the specified charts as local SVG.
- Do not add a backend, server code, API routes, database, authentication, external form submission, real email capture, or persistent storage of inquiry entries. Validation, package selection, disclosures, tooltips, and the copyable inquiry draft must work entirely in the browser and never claim that an inquiry was sent.
- Do not use bare-directory internal links or client routes requiring rewrites. This is one index.html page with file-anchor navigation only, and every CTA must reach its real section or perform its described local action.
- Do not ship source maps, source files in dist/, assets over the 20 MB total limit, console errors, horizontal page overflow, unlabeled controls, or inaccessible charts. Verify at 1440×900 and 390×844 and provide visible focus states and readable contrast.
- Do not autoplay media, scroll-jack, loop count-up animations, hide essential values behind motion, or ignore prefers-reduced-motion. All final statistics and interactions must remain available with motion disabled.
- Do not add SEO descriptions, Open Graph tags, JSON-LD, sitemaps, keyword-stuffed headings, or decorative publication dates; a plain [BRAND] media-kit title and favicon are sufficient.
- Do not leave default names, niche references, audience descriptions, campaign examples, package context, or alt text unchanged when variables change; all dependent content must be rewritten coherently from src/content.ts while the layout and design remain fixed.
