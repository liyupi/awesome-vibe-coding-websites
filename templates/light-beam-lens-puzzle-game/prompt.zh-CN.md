# 光束透镜解谜游戏

完全按照以下描述构建此网站。将 [VARIABLES] 替换为你自己的值；其余内容保持不变。

## 简介
构建 [BRAND]，一款原创的英语 3D 光路解谜游戏，背景设定在 [WORLD]，面向 [AUDIENCE]。默认品牌为 Lumenwild，默认世界为 Glassroot Caverns，默认标语为“Turn the light. Wake the quiet.”。整个产品是一个可玩的静态页面，位于 index.html：一个等距水晶密室、一个确定性的网格光学引擎、12 个手工编写的关卡、移动和目标计数器、撤销、重新开始、关卡选择、帮助、可选的合成音效以及本地进度。首屏必须是可玩的游戏，绝不能是营销落地页或单独的启动画面。

- 受众：独立游戏制作者、开发者、教育工作者以及喜欢平静空间推理的玩家。界面必须通过直接操作和简短说明来欢迎非技术玩家，同时让谜题数据和光学规则便于开发者改编。
- 目标：让访客立即旋转透镜、镜子以及后续的分束器，为每个接收器供能，然后继续通过 12 个逐渐复杂的关卡。让每一次交互都清晰可读且可逆，验证每个编写的解法都能从初始状态开始运行，并在当前设备上保留已解决状态和最佳移动次数，无需任何服务器。
- 语气：安静、精确、神秘且令人安心。使用简短的原创美式英语标签和少量环境文案，而不是庞大的奇幻叙事。没有角色、敌人、计时器、惩罚、温泉、恢复任务、技能树，也没有对现有游戏或 AI 产品的引用。

## 技术栈
- 框架：Vite 5 + React 18 + TypeScript
- 样式：原生 CSS（Vanilla CSS）
- 库：Vite 5（MIT）、React 18（MIT）、Three.js（MIT）、lucide-react（ISC）、@fontsource-variable/space-grotesk（OFL-1.1）、@fontsource/ibm-plex-mono（OFL-1.1）
- 构建：`npm run build` → `dist/` 中的静态文件。无后端、无服务器代码、无外部 API。
- 设置：
  - 使用上述固定依赖。配置一个 index.html 入口、Vite base './'、build.sourcemap false。将 package 的 build 脚本设置为运行 TypeScript 检查和 Vite 生产构建，仅在 dist/ 中生成静态文件。
  - 让 React 负责菜单、对话框、HUD、按钮、无障碍和游戏状态。使用一个由单个 React 棋盘组件拥有的普通 Three.js 场景；不要添加 react-three-fiber、物理引擎、后处理包、Tailwind 或其他框架。
  - 为关卡数据、光束追踪、游戏状态、Three.js 渲染和合成音频实现独立的 TypeScript 模块。纯 traceBeam 函数必须根据当前棋子朝向计算路径；渲染器绝不能简单地绘制预设的解法路线。
  - 将 BRAND、WORLD、AUDIENCE、TAGLINE、全部 12 个关卡名称、所有说明、按钮标签、对话框文案、声音标签和 aria 文案放入 src/content.ts。当变量变化时，重写每个世界特定的词。将固定的关卡坐标和机制保留在 src/game/levels.ts 中。
  - 使用 React reducer 管理当前关卡、棋子旋转、选中棋子、步数、撤销快照、已解决关卡、最佳分数和打开的对话框。仅将已解决状态、最佳分数、声音偏好和当前关卡持久化到由 BRAND 的 slug 派生的 localStorage 键中。全部 12 个关卡从一开始就可选择。
  - 从各自的 Fontsource 包中导入 Space Grotesk Variable 和 IBM Plex Mono 的 400 和 500 字重。使用 Lucide React 作为界面图标。将所有字体、脚本、图标和生成的视觉内容本地打包；无远程资源或 API。
  - 使用正交相机、程序化几何体、实例化装饰晶体、限制设备像素比，且不使用后处理。桌面端像素比上限为 2，移动端为 1.5，在低于 700px 时减少装饰实例数量，文档隐藏时暂停渲染，并在卸载时释放几何体、材质、监听器、音频节点和渲染器。
  - 提供可见的键盘焦点、至少 44px 的触摸目标、指向游戏控制的跳过链接，以及每个指针操作的无障碍 DOM 替代方案。支持 1440×900 和 390×844，无水平溢出或控制台错误，并遵循 prefers-reduced-motion。

## 变量
- [BRAND] — 游戏名称（默认：“Lumenwild”）。一个虚构的一词或两词标题；绝不使用现有的游戏、平台或 AI 品牌。
- [WORLD] — 世界名称（默认：“the Glassroot Caverns”）。一个虚构的水晶之地，用于关卡选择和帮助文案中。
- [AUDIENCE] — 玩家受众（默认：“players who enjoy calm logic puzzles”）。目标玩家，自然地用于帮助介绍中，而非作为元数据。
- [TAGLINE] — 游戏标语（默认：“Turn the light. Wake the quiet.”）。一行简短的原创文字，显示在游戏名称下方以及完成对话框中。
- [CREDIT] — 在页脚保留一个小的“Template by VibeFather”链接指向 https://vibefather.ai/t/light-beam-lens-puzzle-game（默认：是；删除此行即可移除）

页面与区块下的文案是针对默认值编写的。如果你的值不同，请为它们重写每个标题、段落、标签和图片——保持相同的长度、语气和结构。布局、颜色、字体和动效保持所述不变。
将所有文案、图片路径和链接放在一个内容文件中（例如 `src/content.ts`），按区块作为键，以便之后无需改动组件即可替换内容。

4. **确定性光学与游戏状态** — 使用从棋盘左上角开始的零基 x,y 坐标和基本方向 N,E,S,W。发射器沿其固定方向发送一单位光。逐格推进。离开网格或碰到阻挡物会停止该分支。上升反射镜映射 N→E、E→N、S→W、W→S；下降反射镜映射 N→W、W→N、S→E、E→S。水平透镜仅通过 E 和 W；垂直透镜仅通过 N 和 S；轴错误的透镜会停止分支。分光器将入射方向直接通过，并在其显示的基方向添加一个分支。接收器仅在分支沿其所需方向进入时激活；方向错误的光会停止且不会激活它。完成要求每个接收器在同一次追踪中均处于激活状态。对分光分支使用队列，对单元格+方向访问去重，并将总访问次数上限设为 2048 以安全终止循环。每次移动后渲染得到的单元格中心线段。

将每个光学部件的旋转存储为 0–3 个顺时针四分之一圈；反射镜和透镜使用旋转模 2，分光器使用全部四个方向。每次旋转都会将快照推入撤销栈并增加步数。Undo 恢复先前的朝向和先前的步数；Restart 恢复作者设定的初始朝向和零步数。仅在解出时保存最佳分数，且仅当它优于先前最佳时保存。所有目标、反射镜、透镜、分光器、发射器和阻挡物都必须是数据，而不是硬编码的渲染器分支。交付前，以编程方式将每个列出的解法应用到其初始关卡，并断言每个接收器都激活；同时断言每个初始关卡开始时未解出。
