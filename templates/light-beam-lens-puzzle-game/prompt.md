# Light Beam Lens Puzzle Game

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build [BRAND], an original English-language 3D light-routing puzzle game set in [WORLD] for [AUDIENCE]. The default brand is Lumenwild, the default world is the Glassroot Caverns, and the default tagline is 'Turn the light. Wake the quiet.' The entire product is one playable static page at index.html: an isometric crystal chamber, a deterministic grid-optics engine, 12 hand-authored levels, move and target counters, undo, restart, level selection, help, optional synthesized sound, and local progress. The first screen must be the playable game, never a marketing landing page or a separate start screen.

- Audience: Indie game makers, developers, educators, and players who enjoy calm spatial reasoning. The interface must welcome non-technical players with direct manipulation and short instructions while keeping the puzzle data and optical rules easy for a developer to adapt.
- Goal: Let a visitor immediately rotate lenses, mirrors, and later beam splitters to energize every receiver, then continue through 12 increasingly involved levels. Make every interaction legible and reversible, verify that every authored solution works from the initial state, and preserve solved status and best move counts on the current device without any server.
- Tone: Quiet, precise, mysterious, and reassuring. Use short original US English labels and tiny pieces of environmental copy, not a sprawling fantasy narrative. There are no characters, enemies, timers, penalties, hot springs, restoration quests, skill trees, or references to existing games or AI products.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Vanilla CSS
- Libraries: Vite 5 (MIT), React 18 (MIT), Three.js (MIT), lucide-react (ISC), @fontsource-variable/space-grotesk (OFL-1.1), @fontsource/ibm-plex-mono (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Use the fixed dependencies above. Configure one index.html entry, Vite base './', and build.sourcemap false. Set the package build script to run TypeScript checking and the Vite production build, producing only static files in dist/.
  - Keep React responsible for menus, dialogs, HUD, buttons, accessibility, and game state. Use a plain Three.js scene owned by one React board component; do not add react-three-fiber, a physics engine, a postprocessing package, Tailwind, or another framework.
  - Implement independent TypeScript modules for level data, beam tracing, game state, Three.js rendering, and synthesized audio. The pure traceBeam function must calculate paths from current piece orientations; the renderer must never simply draw the authored solution route.
  - Put BRAND, WORLD, AUDIENCE, TAGLINE, all 12 level names, all instructions, button labels, dialog copy, sound labels, and aria copy in src/content.ts. Rewrite every world-specific word when variables change. Keep the fixed level coordinates and mechanics in src/game/levels.ts.
  - Use a React reducer for current level, piece rotations, selected piece, moves, undo snapshots, solved levels, best scores, and open dialog. Persist only solved status, best scores, sound preference, and current level in a localStorage key derived from a slug of BRAND. All 12 levels remain selectable from the start.
  - Import Space Grotesk Variable and IBM Plex Mono weights 400 and 500 from their Fontsource packages. Use Lucide React for interface icons. Bundle every font, script, icon, and generated visual locally; no remote assets or APIs.
  - Use an orthographic camera, procedural geometry, instanced decorative crystals, capped device pixel ratio, and no postprocessing. Cap pixel ratio at 2 on desktop and 1.5 on mobile, reduce decorative instance counts below 700px, pause rendering when the document is hidden, and dispose geometries, materials, listeners, audio nodes, and the renderer on unmount.
  - Provide visible keyboard focus, at least 44px touch targets, a skip link to the game controls, and an accessible DOM alternative for every pointer action. Support 1440×900 and 390×844 without horizontal overflow or console errors and honor prefers-reduced-motion.

### Layout & motion
- Spacing: Use an 8px base grid. Desktop header is 64px with 24px horizontal gutters. The main shell has a 1500px maximum width, height calc(100dvh - 88px), 24px side and bottom padding, a minmax(0,1fr) board column, a 340px control rail, and a 20px gap. Keep the whole game visible at 1440×900. The board canvas fills its card with at least 600px height on large screens. Use 16px rail padding, 12px control gaps, and 24px dialog padding. Below 760px, use a 56px header, one column, 12px gutters, a board height of min(100vw,420px), compact HUD blocks, and a fixed 72px bottom control bar with 96px page-bottom clearance.
- Radius: Use 20px for the scene card and dialogs, 14px for HUD panels, 10px for buttons and level cells, and full pills for move and target counters. Keep tile geometry beveled but angular. Use soft mint shadows only around active optics and the primary next-level action; ordinary panels use 1px Edge borders rather than heavy shadows.
- Motion: Fade the complete cave and HUD in together over 480ms on first load; do not show an intro animation, camera fly-through, or blocking start button.
- Motion: Rotate a selected optical piece around the vertical axis by exactly 90 degrees over 180ms with ease-out, then redraw affected beam segments over 140ms. Game state updates immediately and never waits for the animation.
- Motion: Use a 120ms hover and keyboard-selection outline, a 160ms button press scale of 0.98, and 180ms fade-and-scale dialogs. No camera orbit or board movement is required for play.
- Motion: On completion, brighten all receivers, emit one restrained ring pulse per receiver over 900ms, and open the completion panel after 450ms. Do not loop confetti or shake the board.
- Motion: Ambient dust may drift very slowly and receiver light may breathe at low amplitude, but stop both when reduced motion is requested. Under reduced motion, rotations and beam changes are immediate and completion uses a static glow.
- Imagery: Create every visual in code with Three.js geometry, CSS, and inline SVG; there are no bitmap images, downloaded models, texture maps, HDRIs, or audio files. Build beveled square basalt tiles, angular rising and falling mirror bars, translucent flattened-sphere lenses with a clear axis line, prism splitters with a visible branch arrow, and ring-shaped receivers around faceted crystal cores. Surround the board with instanced low-poly mineral clusters and distant stalactites, using seeded placement so the scene is stable between runs. Use Cave-colored fog, hemisphere illumination, one soft directional light, and small point lights at the emitter and active receivers. Render each beam as a narrow Beam-core cylinder inside a wider transparent additive Beam cylinder at tile-center height. The board and its live optical state are the first-screen visual anchor; typography alone is never the hero. No people, mascots, logos, readable textures, brands, or reference-inspired props.

4. **Deterministic optics and game state** — Use zero-based x,y coordinates from the board's top-left and cardinal directions N,E,S,W. An emitter sends one unit of light in its fixed direction. Advance cell by cell. Leaving the grid or hitting a blocker stops that branch. A rising mirror maps N→E, E→N, S→W, W→S; a falling mirror maps N→W, W→N, S→E, E→S. A horizontal lens passes E and W only; a vertical lens passes N and S only; a wrong-axis lens stops the branch. A splitter passes the incoming direction straight through and adds one branch in its displayed cardinal direction. A receiver activates only when a branch enters while traveling in its required direction; wrong-direction light stops without activating it. Completion requires every receiver to be active on the same trace. Use a queue for split branches, deduplicate cell+direction visits, and cap total visits at 2048 to terminate loops safely. Render the resulting cell-center segments after every move.

Store each optical piece's rotation as 0–3 clockwise quarter turns; mirrors and lenses use rotation modulo 2 and splitters use all four directions. Every rotation pushes a snapshot onto the undo stack and increments moves. Undo restores the prior orientations and prior move count; Restart restores the authored initial orientations and zero moves. Save best score only when solved and only if it improves the prior best. All targets, mirrors, lenses, splitters, emitters, and blockers must be data, not hard-coded renderer branches. Before delivery, programmatically apply each listed solution to its initial level and assert that every receiver activates; also assert that each initial level begins unsolved.
   Layout: Implement this as pure game logic independent of React and Three.js, with the HUD reading the same traced receiver state as the 3D scene. No visual or timing difference may change the puzzle result.
   Motion: None in the logic layer. Visual interpolation must never delay state updates or completion detection.
