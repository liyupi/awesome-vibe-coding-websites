# Daily Tarot Reading Page

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a polished single-page tarot reading toy for the invented brand [BRAND], using the original six-card [DECK_NAME]. The default invitation is '[TAGLINE]' for [AUDIENCE], with reflections centered on [REFLECTION_FOCUS]. Visitors shuffle a tactile fan of card backs, reveal either a persistent daily card or a three-card past-present-future spread, read original upright or reversed interpretations, and download a canvas-rendered share image. This is an original symbolic deck, not a reproduction of a traditional or commercial tarot deck.

- Audience: The primary audience is [AUDIENCE]: adults who enjoy beautiful interactive objects, journaling prompts, and a brief daily ritual. It also suits designers and creators adapting the format for affirmations, oracle cards, or creative reflection. No prior tarot knowledge is expected.
- Goal: Get a first-time visitor from an intriguing visual deck to a complete, understandable reading in two deliberate actions. Make the daily card stable across reloads for the visitor's local day, make three-card readings freely repeatable, and provide a useful downloaded keepsake while keeping every interaction private and client-side.
- Tone: Quiet, poetic, grounded, and non-directive. Use precise reflection prompts rather than prophecy. Never claim to predict the future or advise on health, money, relationships, or safety. A visible 'For entertainment and reflection only' note is part of the experience, not hidden fine print.

## Stack
- Framework: Vite 6 + React 18 + TypeScript
- Styling: Vanilla CSS with custom properties
- Libraries: react (MIT), react-dom (MIT), vite (MIT), typescript (Apache-2.0), lucide-react (ISC), @fontsource/cormorant-garamond (OFL-1.1), @fontsource/manrope (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Create a Vite 6 React 18 TypeScript project. Set base: './', build.outDir: 'dist', and build.sourcemap: false in vite.config.ts. Use no router and no backend.
  - Keep all variable values, derived brand copy, six card records, upright and reversed meanings, reflection prompts, instructions, and FAQs in src/content.ts. When variable values change, rewrite every dependent headline, label, storage-key namespace, meaning, and prompt to fit [BRAND], [TAGLINE], [AUDIENCE], [DECK_NAME], and [REFLECTION_FOCUS]; do not leave default-brand remnants.
  - Self-host Cormorant Garamond 500 and 600 and Manrope 400, 500, 600, and 700 through the listed Fontsource packages. Import only the required weights in src/main.tsx.
  - Implement the design in src/styles.css with custom properties, an 8px spacing system, named shuffle and flip keyframes, and explicit desktop and mobile layouts. Use inline CSS or a local SVG for subtle paper grain; do not fetch a texture.
  - Use Lucide icons for interface actions only: Sparkles for the original geometric brand accent, RotateCcw for shuffle, Download for share, ArrowRight for the primary action, X for close, and ChevronDown for expandable explanations. Do not use any brand or suit icons.
  - Define the reading interaction as an explicit state machine: idle, shuffling, ready, revealing, and revealed. Clear pending animation timers on reset or mode change so rapid taps cannot create duplicate draws.
  - Use local browser dates, not UTC dates, for the daily reading. Namespace the localStorage key from a slug derived from [BRAND] and the local YYYY-MM-DD date. Store a versioned object containing date, card id, orientation, and mode; validate restored data and recover silently from malformed storage.
  - Implement the downloadable share image with the native Canvas 2D API at 1080 × 1350 pixels, including a text-wrapping helper and a toBlob download. No screenshot service, canvas dependency, Web Share requirement, or remote request is needed.
  - Download the six generated card illustrations to the exact public paths listed in Assets before building. Reference them with relative-safe public URLs and create ASSETS.md with every asset path, source, author or generator, and license.

## Variables
- [BRAND] — Brand (default: "Asterhollow"). An invented, elegant two- or three-syllable name for the reading experience.
- [TAGLINE] — Invitation line (default: "A quiet card for the day ahead."). One short non-predictive invitation to pause and reflect.
- [AUDIENCE] — Audience (default: "curious minds who enjoy a nightly reflection ritual"). A plain-language phrase describing who the ritual is for.
- [DECK_NAME] — Deck name (default: "The Night Field Deck"). An original name for the six-card symbolic deck.
- [REFLECTION_FOCUS] — Reflection themes (default: "creativity, relationships, and everyday choices"). Three approachable themes used to adapt the card meanings and prompts.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/daily-tarot-reading-page in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

- Body, controls, labels, and interpretation text: Manrope (OFL), weights 400/500/600/700

### Layout & motion
- Spacing: Use an 8px base grid. The content shell is max-width 1240px with 32px desktop and 20px mobile side padding. Header height is 76px. Desktop sections have 104px vertical padding; mobile sections have 64px. Hero copy and reading table are separated by 64px on desktop and 36px on mobile. Keep reading prose at 62–68 characters per line.
- Radius: Use 28px for large reading and share panels, 18px for physical cards and small content panels, and 999px for segmented controls and buttons. Physical cards have a strict 3:4 aspect ratio, a 1px antique-gold border at 45% opacity, and a soft 0 24px 70px rgba(0,0,0,.38) shadow.
- Motion: On Shuffle, collapse the six-card fan into a stacked deck over 240ms, split alternating cards left and right in three 180ms passes, then return to a fan over 300ms. Disable controls during the 1.1s sequence and use transform and opacity only.
- Motion: On Reveal, move the selected card or cards from the deck into their reading positions over 320ms, then rotate each inner card from rotateY(0deg) showing its back to rotateY(180deg) showing its face over 680ms. Stagger three-card flips by 140ms. Use perspective: 1200px, transform-style: preserve-3d, and backface-visibility: hidden.
- Motion: Use restrained 180ms hover lifts of at most 6px, border-color changes, and icon rotations. Never make the whole page drift or add a custom cursor.
- Motion: Scroll reveals are optional only for the guide and deck sections: 16px upward movement with a 450ms ease-out transition, once per section, without delaying access to content.
- Motion: With prefers-reduced-motion: reduce, remove fan movement, stagger, parallax, smooth scrolling, and 3D rotation. Show the next state immediately with a 100ms opacity change at most; all reading functions remain available.
- Imagery: Use exactly six original generated gouache-and-gold-ink symbolic illustrations, one for each card in [DECK_NAME]. Every image is full-bleed inside a code-built 3:4 card frame with no generated typography or border. The shared visual language is textured midnight indigo, charcoal, dusty plum, parchment, and muted antique gold, with soft candlelit illumination and fine woodblock-like grain. Do not imitate any existing tarot deck. The card back is separately drawn in CSS/SVG from original concentric lines, a central eight-point star, and six small orbital dots; it uses no generated image. The interactive fanned deck is the hero's visual anchor, not typography alone.

## Don'ts
- Do not copy, trace, recolor, or closely imitate any existing tarot or oracle deck, including its card art, card-back pattern, suit system, signature composition, guidebook passages, names, packaging, or slogans. Keep this six-card deck and its interpretations original.
- Do not use real people's likenesses, celebrities, fictional characters, brand logos, proprietary occult marks, or recognizable commercial products. The illustrations must contain no people, text, letters, numbers, logos, or watermarks.
- Do not present readings as predictions, diagnoses, warnings, instructions, or professional advice. Never generate alarming interpretations. Keep the entertainment-and-reflection disclaimer visible in the header, FAQ, share image, and footer area.
- Do not add accounts, a backend, API routes, databases, analytics, remote randomness, external forms, tracking pixels, social widgets, or any network submission. Daily readings and share images stay on the visitor's device.
- Do not use Unsplash, Pexels, Pixabay, Google Images, placeholder-image services, hotlinked files, or assets with unclear, noncommercial, or share-alike licenses. Use only the six supplied generated images and original code-drawn decoration.
- Do not load fonts from Google Fonts, Adobe Fonts, or any CDN. Use only the specified self-hosted Fontsource packages and do not add commercial fonts.
- Do not add Three.js, a physics engine, a screenshot package, a state-management library, or another animation framework. CSS transforms, React state, and native Canvas 2D are sufficient.
- Do not hard-code [BRAND], [DECK_NAME], the default storage namespace, share-image filename, audience copy, or reflection themes outside src/content.ts. Alternate variable values must produce a coherent site without default-brand remnants.
- Do not redraw the daily card on reload, mode change, resize, or rerender. Use the visitor's local calendar day and validate localStorage contents; three-card mode alone may be reshuffled repeatedly.
- Do not allow repeated taps or unfinished animations to create duplicate draws, timers, or inconsistent card orientations. Disable actions during transitions and make the full flow keyboard and touch accessible.
- Do not hide card meanings behind hover, rotate labels for reversed cards, use tiny low-contrast text, or let the fan create horizontal overflow. Verify the full experience at 1440 × 900 and 390 × 844 with zero console errors.
- Do not use scroll-jacking, pinned sections, a custom cursor, autoplay audio, parallax on the reading controls, or animation that ignores prefers-reduced-motion.
- Do not emit source maps, copy src/ into dist/, use CDN script or style tags, or exceed 20 MB in dist/. Keep Vite base relative and all assets local.
- Do not add extra pages, bare-directory links, SEO markup, structured data, fake testimonials, invented visitor counts, pricing, newsletter forms, or calls to purchase a physical deck.
