# How the Internet Works Explainer

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
A single-page scrollytelling explainer published by Northbeam Primers that follows one HTTPS request for https://kettleandcrumb.example/recipes/rye-sourdough from a laptop to an origin server and back. Seven full-height scenes (request, DNS lookup, router hops on an abstract dotted map, TCP handshake, TLS and the lock, the server's reply in packets, rendering) each pair three short reading beats with a sticky code-drawn SVG diagram and exactly one hands-on control. A header rail tracks the packet's stage and a running round-trip timer; a fast replay and a 14-term glossary close the story. When the variables change, all copy and sample data are rewritten to fit them; keep everything in src/content.ts.

- Audience: Curious readers who use the web every day but have never seen what happens underneath; also usable by teachers and developer advocates as a lesson page.
- Goal: Make one round trip feel concrete: the reader should finish knowing the seven stages in order, why distance and handshakes add time, and what the lock actually protects, and should have played with every control on the way.
- Tone: Calm, precise and friendly, like a good science editor: short sentences, everyday analogies used sparingly, exact numbers in monospace, no hype and no jokes at the reader's expense.

## Variables
- [BRAND] — Publisher or series name (default: "Northbeam Primers"). The invented publisher of the explainer, shown in the header wordmark, hero kicker, <title> and footer.
- [TOPIC] — Explainer headline (default: "How one web page reaches your laptop"). The question the page answers; used as the hero headline and in the <title>.
- [SITE_DOMAIN] — Example site being loaded (default: "kettleandcrumb.example"). The made-up site the reader 'visits'. Must end in a reserved name (.example or .test, or a subdomain of example.com) so it can never point at a real site. Used in the address bar, DNS records, certificate, headers and the mock page.
- [PAGE_PATH] — Page requested on that site (default: "/recipes/rye-sourdough"). The path in the address bar and in the GET line. The mock page drawn on the laptop in scene 7 shows content that fits this path.
- [AUDIENCE] — Who the page is for (default: "curious readers who use the web every day but have never seen what happens underneath"). Sets vocabulary, analogies and how much jargon each beat uses.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/how-the-internet-works-explainer in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

### Layout & motion
- Spacing: 8px base unit. Content container max-width 1280px with 32px side padding (16px on mobile). Scenes have 120px vertical padding on desktop and 72px on mobile, beats are spaced 60vh apart on desktop and 40svh on mobile. Inside cards use 20-30px padding; inside diagrams keep at least 24px between labels and edges.
- Radius: Diagram panels 20px, hero visual card and recap panel 24px, reading cards 16px (14px mobile), callouts and inputs 10px, glossary cards 14px, buttons, chips and the timer pill 999px, packet squares 3px, packet tiles 4px.
- Motion: Scene structure uses CSS position: sticky for the diagram (not GSAP pin), and GSAP ScrollTrigger only to detect which beat is active. One ScrollTrigger per beat card: start 'top 65%', end 'bottom 65%', onToggle when isActive sets that scene's beat index (0-2). A beat change runs a GSAP timeline (0.7s, ease 'power3.inOut') from the current diagram state to that beat's target state with overwrite 'auto', so scrolling back up reverses cleanly.
- Motion: Beat cards: inactive cards sit at opacity 0.45; the active card goes to opacity 1 and translates from y 12px to 0 over 0.4s 'power2.out'.
- Motion: Packets: a 12x12px signal-colored rounded square (rx 3) with a 3px ink stripe across its top third (the 'header'), moved along SVG paths with a GSAP tween on a proxy {t: 0 → 1} that calls path.getPointAtLength(t * length) on update; ease 'none' between nodes, 0.12s pause at each router where the node ring pulses (scale 1 → 1.6, opacity 0.8 → 0 over 0.5s).
- Motion: Dashed trails: every active link is a 1.5px signal path with stroke-dasharray '3 6' revealed behind the packet using a second mask path whose stroke-dashoffset tweens from the path length to 0 in sync with the packet; once revealed, the dashes drift (stroke-dashoffset animates -18 per second, linear, infinite).
- Motion: Header round-trip timer counts up or down to the new milestone with a GSAP tween over 0.6s 'power2.out', rounding to whole milliseconds; the active rail packet dot slides between stage stops over 0.5s 'power3.inOut'.
- Motion: Hero: kicker, headline, deck and buttons fade up 16px in sequence (stagger 0.08s, 0.6s each) on load; the URL in the hero laptop types in at 32ms per character with a 2px signal caret blinking (steps(1) 1s); the hero packet loops along its path every 3.2s forever.
- Motion: Lock: the TLS lock is drawn in SVG; its shackle translates from y -6px (open, rotated -18deg around the right leg) to closed over 0.5s 'back.out(2)' and the badge flashes amber once.
- Motion: Micro-interactions: buttons and chips lift 1px on hover with a 150ms transition; focus-visible gets a 2px signal outline at 2px offset; segmented controls slide a raised thumb under the active option over 0.25s.
- Motion: prefers-reduced-motion: no typing, no looping packets, no drifting dashes, no tweens, no sticky diagrams. Each scene renders its diagram in the final beat state as a normal block after the intro text, beats follow as plain cards, and every control still works with instant (0s) updates.
- Imagery: No photographs and no raster images. Everything visual is inline SVG drawn in code: a neutral, generic laptop (rounded lid, plain window frame with one address field, no logo, no traffic-light buttons, no recognizable OS or browser chrome), a generic server rack (stacked units with LED dots), router nodes (6px circles with a 1.5px ring), an abstract dotted landmass map generated from math (dots on a grid kept inside a few overlapping ellipses with a sine-wobble edge, never traced from real geography), sequence diagrams, packet tiles and a simple mock web page on the laptop screen. Strokes are 1.5px, corners rounded, palette limited to the tokens above. The packet is always an abstract rounded square, never a character. Lucide icons appear only in UI controls.

## Don'ts
- No backend of any kind: no server code, API routes, databases, auth, forms that submit anywhere or third-party APIs. No real DNS lookups, pings or network calls from the browser; every lookup, route and timing is computed from src/content.ts.
- Fonts only from the three Fontsource packages; never load fonts from fonts.googleapis.com, fonts.gstatic.com, Adobe Fonts or any other CDN, and no commercial fonts.
- No CDN script or link tags, no analytics, no remote images: every font, icon and script is bundled locally.
- Production build must be minified with no source maps (build.sourcemap false) and no src/ folder copied into dist/; dist/ stays well under 20 MB.
- Use relative paths (Vite base './'); internal links are in-page anchors or ./index.html, never a bare directory.
- Must work at 1440x900 and 390x844 with zero console errors and no horizontal page scroll.
- Respect prefers-reduced-motion: no typing, looping packets, drifting dashes, tweens or sticky diagrams; show each scene's final diagram state as a static figure with its control still usable.
- Exactly one interactive control per scene; do not add extra sliders, toggles or settings panels.
- Never name real companies, internet providers, cloud or CDN providers, browsers, operating systems or certificate authorities, and never show their logos; use generic labels such as 'Your ISP', 'Resolver', 'Root server', 'Origin server' and 'Demo Root Authority (invented)'.
- Do not draw a real browser's or operating system's chrome (no traffic-light buttons, tab shapes, icons or toolbars of a recognizable product); the laptop and window frame stay neutral and generic, with no logo on the lid.
- No real domain names and no real public IP addresses: domains end in .example or .test (or are example.com subdomains) and are built from [SITE_DOMAIN]; IPs come only from 192.0.2.0/24, 198.51.100.0/24 and 203.0.113.0/24.
- Do not copy copy, analogies, diagrams or illustration style from existing networking explainers, comics, courses or textbooks; use only the wording and diagrams described here.
- No real map tiles, map libraries, GeoJSON or traced country and coastline outlines; the map is abstract and generated in code.
- No mascot, character or guide figure, and no people illustrations; the packet is always an abstract rounded square.
- No code or components from Aceternity UI, Tailwind Plus / Tailwind UI or any paid template; build every effect from scratch. No React or other framework: vanilla TypeScript modules only.
- No dependency outside the listed libraries and licenses; no placeholder-image services, stock photos or brand logos.
- Keep all copy in US English in src/content.ts; when the variable values change, rewrite the copy, the mock page on the laptop, the DNS server names, headers and certificate subject to fit the new values instead of leaving the defaults.
- No SEO extras: no meta descriptions, Open Graph tags, JSON-LD or sitemaps; a plain <title> with [BRAND] and the SVG favicon are enough.
- No mention of VibeFather anywhere in the site except the optional credit link in the footer.
