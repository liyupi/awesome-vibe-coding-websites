# Custom Cake Bakery Website

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build an original single-page website for [BRAND], an invented custom cake bakery offering [SPECIALTY] in [CITY]. The centerpiece is a working cake configurator with a live code-drawn SVG cake, deterministic pricing, lead-time-aware pickup selection, and a copyable order request. Use six coordinated local cake photographs for the hero, gallery, and process section; the configurator itself must be drawn in code, not represented by a static image.

- Audience: People planning birthdays, weddings, showers, anniversaries, and small gatherings who want to understand cake choices, servings, price, and pickup timing before contacting a local bakery.
- Goal: Help visitors move from visual inspiration to a complete, coherent cake request while making the bakery feel established, careful, and approachable. Make the builder genuinely useful on desktop and mobile, with no fake checkout or submission.
- Tone: Warm, specific, assured, and lightly playful. Use concise sensory language about cake and clear practical language about ordering. Avoid exaggerated claims, luxury clichés, and sugary marketing filler.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Tailwind CSS 3.4
- Libraries: Motion 11 for React (MIT), lucide-react (ISC), @fontsource-variable/fraunces (OFL), @fontsource/dm-sans (OFL)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Create a Vite React TypeScript project; install Tailwind CSS 3.4, motion, lucide-react, @fontsource-variable/fraunces, and @fontsource/dm-sans.
  - Set base: './' and build.sourcemap: false in vite.config.ts; the production output must be dist/.
  - Configure Tailwind with the colors, font families, spacing, and keyframes below; import the local Fontsource packages in src/main.tsx.
  - Keep all site copy, image paths, opening hours, FAQs, testimonials, and variable-derived values in src/content.ts; keep cake options and prices in src/cakeOptions.ts.
  - Use one React state object for the cake configuration and derive servings, SVG geometry, line items, and total from it; never maintain duplicate price or preview state.
  - Persist only non-personal cake configuration choices in localStorage; do not persist names, contact details, messages, or pickup dates.

## Variables
- [BRAND] — Bakery name (default: "Fable & Frost"). An invented bakery name used in the header, hero, footer, and page title.
- [CITY] — City and region (default: "Portland, Oregon"). Used in the eyebrow, pickup guidance, and visit copy.
- [SPECIALTY] — Cake specialty (default: "garden-inspired celebration cakes"). A short lowercase phrase describing the bakery's point of view.
- [LEAD_TIME_DAYS] — Minimum notice in days (default: "4"). A positive integer used by both the pickup-date validation and ordering copy.
- [PICKUP_ADDRESS] — Pickup address (default: "18 Marigold Lane, Portland, Oregon"). An invented street address used in the visit section, footer, and copied request.
- [ORDER_EMAIL] — Order email (default: "orders@fableandfrost.example"). The destination shown when visitors copy their request; use a reserved .example address for fictional content.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/custom-cake-bakery-website in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design
### Colors
- Paper `#F7F1E8` — Primary page background and generous negative space
- Ink `#30251F` — Headlines, body text, and dark controls
- Cherry `#A4473C` — Primary buttons, selected states, links, and small editorial accents
- Blush `#EBC9C0` — Hero panel, illustration background, and selected-option wash
- Sage `#68735D` — Secondary accents, decorative stems, and success feedback
- Cream `#FFFCF7` — Photograph mats, form surfaces, and text on dark buttons

### Typography
- Display and brand wordmark; use 76px/0.98 at desktop, 48px/1.02 on mobile, weight 600 with occasional italic emphasis: Fraunces Variable (OFL), weights 500/600/700
- Body, navigation, controls, labels, and prices; body 17px/1.65, labels 13px with modest tracking: DM Sans (OFL), weights 400/500/600/700

### Layout & motion
- Spacing: Use an 8px base grid. Cap the main container at 1280px with 40px desktop and 20px mobile side padding. Give major sections 112px desktop and 72px mobile vertical padding. Keep form groups 28px apart and body measures below 62 characters.
- Radius: Use 18px for photograph frames and the cake-preview stage, 12px for form controls and option rows, and 4px for small labels. Reserve fully rounded shapes for tiny status dots and the cake's piped decorations, not every container.
- Motion: Reveal major section headings and content groups once with Motion whileInView: opacity 0 to 1 and y 24 to 0 over 500ms, with 80ms stagger between siblings.
- Motion: When a cake option changes, crossfade and gently scale only the affected SVG tier or decoration over 220ms; animate the estimated-total digits with a subtle 120ms highlight rather than a rolling counter.
- Motion: Give gallery images a 1.03 scale on hover and focus within 450ms; give buttons a 2px upward shift and keep selected option rows visibly marked without layout movement.
- Motion: Use a 180ms opacity and scale transition for the request dialog and a short toast for copy feedback. Under prefers-reduced-motion, disable reveals, smooth scrolling, scaling, and nonessential transitions.
- Imagery: Use the six generated photorealistic editorial food photographs listed in assets: hero-cake.webp, berry-cake.webp, pistachio-cake.webp, chocolate-cake.webp, citrus-cake.webp, and cake-making.webp. All share warm left-side window light, soft shadows, subtle film grain, realistic buttercream, and a cream, terracotta, blush, and muted-sage palette. Show complete cakes or close craft details, never tight faces, text, logos, or branded decorations. The live cake in the builder is a separate original inline SVG with clean, softly textured geometry.

## Don'ts
- Do not use a backend, serverless functions, API routes, database, authentication, third-party APIs, analytics, real payment, or external form submission. All interactions must run locally in the browser.
- Do not claim that an order was submitted, an email was sent, a date was reserved, or payment was taken. The final working action only copies the request summary.
- Do not hard-code a second copy of prices, servings, lead-time validation, or preview state; derive every displayed value from the shared configuration and option data.
- Do not use real bakery names, existing logos, slogans, branded toppers, copyrighted characters, celebrity likenesses, recognizable product branding, or copied website code, copy, photographs, or illustrations.
- Do not use Unsplash, Pexels, Pixabay, Google Images, placeholder-image services, CC BY-NC or CC BY-SA material, commercial fonts, restricted component source, or any asset without an allowed license.
- Do not hotlink assets or load scripts, fonts, icons, styles, maps, or images from a CDN. Download the six approved images into public/images and self-host all fonts through the specified npm packages.
- Do not replace the photographic hero with typography alone, a flat placeholder, a CSS cake, or a generic gradient. Do not replace the live SVG configurator with a static image.
- Do not add fake reviews presented as verified, social-media counts, unverifiable awards, scarcity timers, or claims about the template publisher inside the bakery site.
- Do not hide builder choices behind inaccessible divs or a multi-step wizard. Use semantic fieldsets, labels, radio controls, keyboard-visible focus, a properly labelled dialog, and at least 44px touch targets.
- Do not ignore invalid pickup dates, Sundays, Mondays, or a lead time different from the variable value. Do not persist personal contact details in localStorage.
- Do not use bare-directory links, root-absolute asset paths, external navigation for section links, or a framework server. The only page is index.html and all section links use local anchors.
- Do not emit source maps, copy src/ into dist/, exceed 20 MB, or require more than npm run build for the static production output.
- Do not introduce console errors, horizontal overflow, clipped footer text, sticky elements that cover controls, or motion that ignores prefers-reduced-motion at 1440×900 or 390×844.
- Do not add SEO metadata beyond a plain [BRAND] title and favicon, and do not add JSON-LD, Open Graph tags, sitemap work, or keyword-stuffed copy.
- Do not overuse rounded cards, pills, glass effects, purple gradients, emoji, or generic AI-style decoration; preserve the restrained editorial rules, warm paper surface, and practical hierarchy.
