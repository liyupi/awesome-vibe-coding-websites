# Music Streaming App with Lyrics

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build [BRAND], an original multi-view music streaming web app for [AUDIENCE], with a [MUSIC_MOOD] editorial catalog and the product promise '[TAGLINE]'. Open on the actual Library, not a marketing page. Include curated playlists, an editorial sample chart, a now-playing view with spinning vinyl and time-synchronized lyrics, local song comments and likes, a working queue drawer, and a mini player that persists across views. Feature the invented playlist [FEATURED_PLAYLIST], six fictional artists, original lyric previews, six coordinated abstract covers, and six original locally generated audio previews.

- Audience: The in-product listeners are [AUDIENCE]. The template itself suits music creators, product designers, developers, and indie hackers who need a polished static prototype with real audio, synchronized lyrics, social interactions, and continuous playback state.
- Goal: Let a visitor discover a track, play and seek its original preview, follow the active lyric line, read and add local comments, manage the upcoming queue, and move between catalog views without losing the current song. Every visible control must have a real client-side result and every track must have its own coherent cover, audio, lyrics, and comments.
- Tone: Intimate, editorial, precise, and quietly nocturnal. Write lyrics and listener comments as original English snippets with concrete images and restrained emotion. Keep utility labels direct and disclose sample data and local-only behavior without turning the interface into a disclaimer wall. Avoid music-platform clichés, fake popularity claims, and empty superlatives.

## Stack

- Styling: Tailwind CSS 3.4
- Libraries: motion (MIT), lucide-react (ISC), @fontsource-variable/fraunces (OFL), @fontsource-variable/dm-sans (OFL), @fontsource/ibm-plex-mono (OFL)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Use Vite 5, React 18, TypeScript 5, Tailwind CSS 3.4, PostCSS, Autoprefixer, Motion, and Lucide React. package.json scripts are dev='vite', audio='node scripts/generate-audio.mjs', build='npm run audio && tsc -b && vite build', and preview='vite preview'. Do not add routing, state-management, audio, component, or animation dependencies.
  - In vite.config.ts set base='./', build.outDir='dist', build.sourcemap=false, and assetsInlineLimit=0. Produce one minified index.html application with relative asset paths and no src/ copied into dist/. Configure Tailwind with the Design colors, font families, tabular numerals, custom range styling, vinyl keyframes, lyric scrollbars, focus rings, and reduced-motion overrides.
  - Implement a small hash router without another dependency. Support exactly '#/', '#/charts', and '#/now-playing'; index.html without a hash shows Library, unknown hashes fall back to '#/', browser back and forward work, and the shared audio element and player context are never recreated on navigation.
  - Keep variable values, derived brand copy, playlists, six track records, artists, cover and audio paths, synthesis parameters, six timed lyric lines per track, comments, chart ranks and sample play counts, search keywords, alt text, and UI labels in typed src/content.ts. Rewrite every dependent value and all default proper nouns for supplied variables; do not leave late-night city copy in a different musical direction.
  - Create scripts/generate-audio.mjs using only Node built-ins. For each track, read its BPM, root note, scale, six-note motif, and seed from the track data and synthesize an original 18-second 22050Hz mono 16-bit PCM WAV: soft sine/triangle electric-piano notes with exponential decay, a restrained low kick, filtered high-frequency hat ticks, and very low seeded noise. Apply 40ms edge fades, a short seam crossfade, normalize peaks below 0.78, write canonical WAV headers, and make repeated runs byte-identical. Generate afterglow-avenue.wav, peach-static.wav, blue-hour-radio.wav, velvet-satellites.wav, glass-garden.wav, and midnight-orchard.wav into public/audio/; together they must remain below 5 MB.
  - Use one React player context and one hidden HTMLAudioElement. Track state includes currentTrackId, ordered queue IDs, isPlaying, currentTime, duration, volume, muted, lyricsEnabled, and queueOpen. Audio never autoplays on load or route change. Play, pause, previous, next, track selection, seek, volume, mute, and lyric-line seeking control actual audio; ended playback advances to the next queued track and stops cleanly at the end.
  - Derive the active lyric line from audio currentTime and each line's start seconds, clamping at the final line. Update progress with requestAnimationFrame while playing and audio timeupdate events otherwise. Keep the active line centered in the lyric viewport with smooth scrolling only when reduced motion is not requested; clicking a line seeks to its exact start and does not scroll the page.
  - Use one versioned localStorage namespace derived from a lowercase hyphenated BRAND slug for liked comment IDs, locally posted comments, followed playlist IDs, queue order, removed queue IDs, and the last selected track. Validate stored IDs against content data, handle unavailable storage without errors, and restore reloads paused at 0:00 rather than unexpectedly playing sound. Provide a confirmed Reset local demo action.
  - Use Motion only for short route, drawer, toast, comment, and queue-row transitions. Drive vinyl rotation and lyric activation from real playback state, pause animation while audio is paused or the document is hidden, and use useReducedMotion plus CSS media queries to replace rotation and smooth lyric travel with static states.
  - Implement the queue and mobile navigation as accessible drawers or dialogs with visible Close controls, Escape and scrim dismissal, focus trapping, focus return, and aria-modal semantics. Give every icon button an accessible name, use aria-pressed for toggles, maintain 44px touch targets, and announce track, comment, like, queue, and playback changes through a restrained aria-live region.
  - Import Fraunces Variable, DM Sans Variable, and IBM Plex Mono 400/500 locally through Fontsource. Download the six supplied cover images to their exact public/images/ paths before the first build; the build itself never fetches remote assets. Write ASSETS.md with every cover, generated audio file, font, icon package, source, author, and license.

### Layout & motion
- Spacing: Use a 4px base scale. The desktop shell has a 216px fixed sidebar, a minmax(0,1fr) main column, 32px main gutters, and an 88px fixed mini player. Main content has a 1320px maximum width within its available column. Page headers use 32px top and 24px bottom spacing; playlist cards use 18px padding and track rows 12px. Now Playing uses 32px stage padding and a 48px column gap. Mobile uses 16px gutters, a 72px mini player above 62px bottom navigation, 150px combined bottom clearance, and at least 44px pointer targets.
- Radius: Use 24px for the featured playlist and now-playing stage, 18px for playlist cards and the queue drawer, 14px for standard panels and cover frames, 10px for buttons and inputs, and full rounding only for compact chips, icon buttons, and the vinyl. Use one-pixel Plum Line borders and restrained 0 20px 60px rgba(10,6,14,0.32) shadows only on drawers and the now-playing stage.
- Motion: Route changes fade and settle the main content upward 6px over 180ms while the sidebar, mini player, bottom navigation, and current audio remain untouched. Move focus to the new page heading without resetting playback.
- Motion: The vinyl rotates once every 3.2 seconds only while audio is playing and motion is allowed. The cover label rotates with the disc; pausing freezes the current angle rather than snapping back.
- Motion: The active lyric changes color, opacity, and a 3px Apricot side rule over 160ms. The lyric viewport scrolls the active line to its center over 240ms; seeking or switching tracks updates immediately before any effect.
- Motion: Play, like, follow, queue-add, and volume controls give 120–180ms color or scale feedback without layout shift. New local comments enter with a 160ms fade and comment-like counts update once per visitor.
- Motion: The queue drawer enters from the right over 220ms with a fading scrim. Reordered rows use Motion layout transitions of 180ms; removed rows collapse without delaying the underlying queue state.
- Motion: Toasts remain for 1800ms and never cover the mini player. No autoplay, audio visualization unrelated to the actual track, bouncing music notes, continuous ambient particles, or scroll-jacking.
- Motion: Under prefers-reduced-motion: reduce, stop vinyl rotation, remove route travel, smooth lyric scrolling, drawer travel, and row interpolation while preserving instant active-line, playback, queue, and comment feedback.
- Imagery: Use exactly six local generated square album-cover illustrations in one coherent mixed-media style: layered translucent paper, brushed gouache, deep plum ground, apricot and dusty coral forms, restrained lilac and powder-blue accents, soft upper-left editorial light, fine analog grain, and bold full-bleed abstract compositions. Use original inline SVG for the service's open-oval-and-seed mark and favicon, plus generic Lucide icons for controls.
