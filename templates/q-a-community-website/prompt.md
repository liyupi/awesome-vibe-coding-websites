# Q&A Community Website

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build an original multi-view knowledge Q&A application for [BRAND], a fictional community about [COMMUNITY_FOCUS] for [AUDIENCE]. The product promise is [TAGLINE]. Open on the actual trending feed, not a marketing page, and provide working question, topic, answer-editor, and reputation views. All people, questions, answers, metrics, badges, and community activity are invented sample content; visitor changes remain on this device.

- Audience: The in-product audience is [AUDIENCE], from beginners asking their first practical question to experienced members sharing detailed answers. The template itself suits educators, creators, community builders, designers, and developers who need a polished long-form community interface with real client-side interactions.
- Goal: Help a visitor discover a relevant question, understand the quality of its answers, upvote or collapse answers, follow topics, and write a formatted answer with preview. Make search, filters, hash navigation, draft persistence, local publishing, and reputation progress work without accounts, a server, or third-party APIs.
- Tone: Thoughtful, generous, specific, and calm. Answers should sound like experienced peers explaining what they would try and why, with useful constraints and honest uncertainty. Avoid growth-hacking language, empty welcomes, generic encouragement, and claims that sample contributors or metrics are real.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Tailwind CSS 3.4
- Libraries: motion (MIT), lucide-react (ISC), @fontsource-variable/newsreader (OFL), @fontsource-variable/source-sans-3 (OFL)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Set Vite base to './', build.outDir to 'dist', and build.sourcemap to false. Produce one self-contained index.html application with hashed assets and no server fallback requirement.
  - Configure Tailwind with semantic colors backed by CSS variables, Newsreader and Source Sans 3 font families, tabular numeric utilities, and a small global stylesheet for long-form answer typography, focus rings, scrollbars, and reduced-motion overrides.
  - Implement a tiny hash router without another dependency. Support '#/', '#/question/<question-slug>', '#/topic/<topic-slug>', '#/write/<question-slug>', and '#/reputation'; direct index.html loads show the feed, browser back and forward work, and a missing or unknown slug falls back to the first real question or topic instead of a not-found screen.
  - Keep every variable-derived label, topic, question, full answer, contributor, badge, metric, guideline, diagram definition, and editor example in src/content.ts. Rewrite the entire knowledge base for the supplied variable values so no urban-gardening copy survives in another community.
  - Use React useReducer for app state and small components for the shell, feed, question cards, answers, author cards, topic view, editor, preview, reputation guide, search results, and mobile drawers. Keep derived filtering and sorting functions pure and covered by the actual UI behavior.
  - Persist upvotes, collapsed answer IDs, followed topic IDs, per-question editor drafts, locally published answers, and local reputation adjustments under one versioned localStorage key derived from the slugified [BRAND]. Handle empty or unavailable storage without console errors and provide a confirmed Reset local demo action in the community menu.
  - Use motion/react AnimatePresence and layout transitions only for short route, collapse, drawer, toast, and published-answer feedback. Call useReducedMotion and replace nonessential movement with immediate state changes when requested.
  - Build the editor preview as safe React elements from a small allowlisted Markdown subset: bold, italic, inline code, links, lists, block quotes, and paragraphs. Do not inject raw HTML. Formatting buttons insert syntax at the textarea selection and preserve undo behavior.
  - Import Newsreader Variable and Source Sans 3 Variable locally from Fontsource. Use native buttons, inputs, textarea, nav, main, aside, and article elements; all overlays need accessible names, Escape handling, focus return, and visible keyboard focus.
  - Support '/' or Command/Ctrl+K to focus global question search when the visitor is not already typing. Announce filter counts, votes, follows, save status, and publish results through restrained aria-live regions.

### Layout & motion
- Spacing: Use a 4px base scale. The sticky desktop header is 68px high. The workspace has a 1480px maximum width, 28px outer gutters, and a 208px left rail, minmax(0,760px) center, and 264px right rail with 24px gaps. Feed cards use 22px padding and 18px vertical gaps. Question reading uses a 68px vote rail and a maximum 680px text measure with 20px Newsreader body text at 1.72 line-height. Mobile uses 16px gutters and at least 44px touch targets.
- Radius: Use 10px for buttons and inputs, 14px for standard cards, 18px for featured panels and editor surfaces, and full rounding only for compact chips and status pills. Make geometric portraits rounded squares rather than generic initial circles. Prefer hairline borders; reserve 0 18px 50px rgba(32,42,36,0.14) shadows for search results, drawers, and dialogs.
- Motion: On hash-route changes, fade the new main view in with translateY(6px) over 180ms; do not animate the shared header or side rails and do not delay readable content.
- Motion: Upvote buttons fill and their count crossfades over 140ms. Follow buttons swap label and icon with a 160ms ease-out transition without shifting neighboring controls.
- Motion: Collapsed answers animate height and opacity over 200ms while retaining the author row and Expand answer control; newly published local answers enter with a 220ms fade and 8px rise.
- Motion: Mobile navigation, topic, and contributor drawers slide 16px and fade their backdrop over 200ms. Search results scale from 0.99 to 1 over 140ms.
- Motion: Under prefers-reduced-motion: reduce, remove route travel, height animation, smooth scrolling, and entrance transitions while preserving instant state, focus, and text feedback.
- Imagery: Use no bitmap images, generated portraits, stock photographs, or avatar services. The complete app UI is the first-screen visual anchor, strengthened by a featured question card with an original inline SVG field-note diagram. For the default community, draw a balcony sunlight map with four planters, a pale sun arc, railing lines, and small numeric hour markers; for another subject, replace it with an equally specific technical diagram such as a bread-proofing timeline. Draw eight distinct fictional contributors as original geometric SVG head-and-shoulder portraits with varied skin tones, hair shapes, clothing, and sage, blush, ochre, blue, and clay backgrounds; never use initials-only avatars or resemble real people. Create an original [BRAND] mark from two open book-like rectangular leaves and one vermilion dot, plus a simple matching favicon.
