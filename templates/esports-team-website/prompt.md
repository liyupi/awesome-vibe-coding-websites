# Esports Team Website

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a complete original esports organization website for [BRAND], competing in [DISCIPLINE] from [HOME_CITY] during the [SEASON_NAME]. Use [TEAM_CODE] as the short team code. Deliver a cinematic home page plus roster, matches, shop, and news hash routes. All team members, opponents, sponsors, competition names, products, headlines, statistics, and stories are invented. Keep every variable value, navigation label, player record, match record, product, sponsor, story, UI string, and alt text in src/content.ts. When variable values change, rewrite the entire content set to form a coherent new organization rather than merely replacing the header name.

- Audience: Esports teams, gaming collectives, creator squads, community tournament organizations, and their fans, players, partners, and merchandise customers.
- Goal: Give fans a fast way to understand the team, inspect the roster and stats, follow fixtures and results, read original team stories, discover invented partners, and assemble a merchandise order in a working local demo cart.
- Tone: Focused, competitive, precise, and editorial. Use short declarative copy about preparation, teamwork, rounds, maps, and recovery. Avoid aggressive trash talk, gambling language, empty superlatives, fake live activity, and generic startup language.

## Stack
- Framework: Vite 5 + React 18 + TypeScript 5
- Styling: Tailwind CSS 3.4
- Libraries: react 18.3.1 (MIT), react-dom 18.3.1 (MIT), motion 11 (MIT), lucide-react (ISC), tailwindcss 3.4 (MIT), @fontsource/barlow-condensed (OFL-1.1), @fontsource/inter (OFL-1.1), @fontsource/jetbrains-mono (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Configure Vite with base: './', build.outDir: 'dist', build.sourcemap: false, and emptyOutDir: true; use one index.html entry and no server code.
  - Implement a small typed hash router with window hashchange events. Routes are home, #/roster, #/matches, #/shop, and #/news; all navigation hrefs use ./index.html or ./index.html#/route, and an unknown hash returns to home.
  - Configure Tailwind with the colors and font families from Design. Put clipped-corner utilities, keyframes, focus styles, reduced-motion overrides, and custom scrollbar styling in src/index.css.
  - Import only the specified local Fontsource weights in src/main.tsx. Do not use a font CDN.
  - Create src/content.ts as the single content source. Export a content factory that accepts the five variables and returns fully rewritten team, roster, match, sponsor, product, story, navigation, and UI content.
  - Download the six generated photographs into public/images before running the app, reference them through relative local paths, and create ASSETS.md at the project root with every source and credit.
  - Use Motion's React API for entrance, layout, modal, drawer, and route transitions. Use lucide-react for interface icons only; draw the team mark, sponsor marks, stat bars, and product illustrations as original inline SVG or CSS.
  - Keep cart contents, selected variants, and dismissed UI preferences in localStorage where useful. No cart, filter, drawer, accordion, or checkout control may be decorative or nonfunctional.

## Variables
- [BRAND] — Team name (default: "Static Vale"). Invented esports organization name used throughout the site.
- [TEAM_CODE] — Short team code (default: "STV"). Three uppercase letters for score bugs, jersey art, and compact labels.
- [DISCIPLINE] — Competitive discipline (default: "Tactical arena"). A generic or invented competition category, never a real game title.
- [HOME_CITY] — Home city (default: "Rotterdam"). The team's base, used in the hero and footer.
- [SEASON_NAME] — Season or series name (default: "Meridian Open"). An invented season or competition name for the schedule and news.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/esports-team-website in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design
### Colors
- Void `#080A0B` — Page background and the darkest footer surface.
- Carbon `#111517` — Cards, drawers, navigation, and alternating content bands.
- Steel `#2A3134` — One-pixel rules, table borders, stat tracks, and disabled states.
- Chalk `#F3F6EF` — Primary headings, scores, and high-emphasis text.
- Mist `#98A39F` — Secondary copy and metadata; use at readable sizes on Void or Carbon.
- Volt `#C8FF3D` — The single electric accent for calls to action, active filters, selected stats, and thin lighting details.

### Typography
- Display and scores: Barlow Condensed (OFL), weights 600/700/800
- Body and interface: Inter (OFL), weights 400/500/600
- Statistics, labels, and match metadata: JetBrains Mono (OFL), weights 400/500/600

### Layout & motion
- Spacing: Use a 12-column grid with a 1440px maximum content width, 48px desktop gutters, 20px mobile gutters, and 24px desktop grid gaps. Major sections have 112px desktop and 72px mobile vertical padding. Card padding is 28px desktop and 20px mobile. Keep data rows compact at 64–76px high and body measure below 68 characters.
- Radius: Use square corners with one 18px clipped top-right corner on major image cards and a 10px clipped bottom-left corner on small data panels. Buttons have 2px radii, modal drawers have none, and only tiny status chips may be fully rounded. Never soften the design into generic rounded cards.
- Motion: On initial home load, reveal the hero headline in two masked lines over 560ms, fade the eyebrow and calls to action after a 100ms stagger, and ease the arena image from scale 1.045 to 1 over 900ms.
- Motion: Reveal section headings and card groups with Motion whileInView using 24px upward travel, 480ms duration, and 70ms child stagger; trigger once at 18% visibility.
- Motion: Run the sponsor strip as a slow seamless 28-second marquee and pause it on hover or keyboard focus. Do not marquee navigation, match data, or essential copy.
- Motion: On roster hover or focus, slide the portrait 6px upward and reveal a compact stat rail; on selection, open the player detail drawer with a 240ms horizontal transition and shared focus management.
- Motion: Use 180ms fade-and-8px route transitions, 200ms accordion height transitions, and 240ms cart and product drawers. Respect prefers-reduced-motion by removing transforms, smooth scrolling, parallax, counting effects, and marquee movement while preserving every final visible state.
- Imagery: Use exactly six supplied AI-generated photographs as one coherent fictional team shoot: one wide arena group image and five individual 3:4 player portraits. All feature plain black performance apparel, charcoal haze, teal-black shadows, subtle acid-lime rim light, realistic editorial photography, and no text or logos. The wide hero is a spacious group scene, never a tight face close-up. Crop individual portraits consistently at mid-torso on desktop and slightly higher on mobile. Reuse the group image or portraits in selected news cards rather than adding unrelated stock. Draw all merchandise as polished original black-and-volt SVG product illustrations and draw simple abstract sponsor marks in code. Every team portrait is a fictional placeholder, never an initials-only substitute or a real person's likeness.
