# Kids Learning App Landing Page

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a polished, original claymorphism landing page for [BRAND], a children’s app for [APP_FOCUS], set in [STORY_WORLD]. The buyer and reader is a grown-up; the colorful lesson preview is inviting for a child to try with them. The first screen must pair a large saturated pink clay scene with a large sky-blue CSS phone containing real interactive reading and math screens. Continue with an age-aware learning path, a second clay scene explaining practice, a working sample parent dashboard, a calm safety section, pricing, an accessible local routine form, FAQs, and a final invitation. This is a static, fully usable product preview, not a real subscription service. Use the variable defaults exactly for the default build. Keep all copy, structured lesson data, prices, asset paths, alt text, and links in src/content.ts. When values change, rewrite every product-specific sentence and every lesson to fit the new audience and story world; retain the same sections, controls, color system, and level of detail. The three supplied clay images are neutral learning companions and geometric props, suitable for both the garden and floating-workshop content.

- Audience: [AUDIENCE]. Speak to the grown-up making the choice, with short encouraging instructions inside the child-facing lesson preview.
- Goal: Let a visitor understand the product in the first screen, try an age-appropriate reading and math activity, inspect a sample parent view, compare transparent prices, and build a sample family routine locally.
- Tone: Warm, curious, concrete, lightly playful, and calm about mistakes. Never promise learning outcomes or use urgency, streak pressure, guilt, awards, testimonials, or unsupported adoption numbers.

## Stack
- Framework: Vite + React + TypeScript
- Styling: Vanilla CSS
- Libraries: react and react-dom (MIT), vite and @vitejs/plugin-react (MIT), typescript (Apache-2.0), lucide-react (ISC), @fontsource/fredoka (OFL-1.1), @fontsource/dm-sans (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Use a single index.html entry with React components and semantic HTML; keep all product content and lesson datasets in src/content.ts.
  - Set Vite base to './', build.outDir to 'dist', and build.sourcemap to false; npm run build runs TypeScript checking and vite build.
  - Use CSS custom properties for every palette value and shared space, radius, shadow and focus token. Author all clay shading, page layout and animations in local CSS; do not install a UI kit or animation framework.
  - Import only the Latin 400, 500 and 600 Fredoka weights and the Latin 400, 500, 600 and 700 DM Sans weights from Fontsource, bundled locally. Use font-display: swap and sensible rounded/sans fallbacks.
  - Download the three supplied image URLs to public/images/ using the exact target filenames before implementation. Import Lucide icons from the npm package and use inline SVG output.
  - Implement ageBand, lessonMode, lessonIndex, answer feedback, parentPeriod, billingPeriod, menuOpen, and routine-dialog state locally in React. Use no storage, network calls, accounts or form submission.
  - For optional read-aloud, use only native window.speechSynthesis with an English voice whose localService flag is true. If there is no local voice, keep the sound-breakdown interaction fully usable and show a plain availability message only after the user asks. Never autoplay speech or request a remote voice.
  - Include a plain document title using [BRAND] and a simple original CSS/SVG geometric favicon. Ship ASSETS.md at the project root with every image, font and icon source and license.

## Design
### Colors
- Lilac base `#EDE7FF` — Main page canvas and the hero scene background. Keep this exact lilac; do not replace it with cream, beige or gray.
- Bubblegum pink `#FF4FA3` — Large hero clay companion and a large supporting clay orb, reading cards, pricing highlight and parent chart bars. This is a saturated hero subject, not merely a button accent.
- Sky blue `#2FADFF` — Large CSS phone body, broad math surfaces and a learning card. The blue phone occupies roughly half of the hero’s visual stage and remains clear on mobile.
- Butter yellow `#FFD84D` — Puffy arch details, age selection, lesson feedback accents and the safety section surface. Keep it bright and saturated.
- Grass green `#4ECB68` — Second clay companion, math tokens, parent dashboard balance and the final CTA band.
- Deep plum ink `#2D174D` — All headings, body text, labels, icons, outlines, chart labels and text on pink, blue, yellow, green or lilac. This ink has contrast above 5:1 on all four strong colors and above 13:1 on the lilac.
- Secondary plum `#58466B` — Supporting text on white or lilac only; never place this color on pink, blue, green or yellow. It exceeds 6.9:1 on lilac.
- Paper white `#FFFFFF` — Phone screen, dashboard panels, plain content cards and text on deep-plum filled buttons only. Never use white body text on the four bright colors.
- Clay shadow `#7A5EA8` — Tinted ambient shadows at 10–20% alpha only, never text or an extra section color.

### Typography
- Display headings, plain wordmark and large lesson answers: Fredoka (OFL), weights 400/500/600
- Body, navigation, form labels, buttons, chart labels and small UI: DM Sans (OFL), weights 400/500/600/700

- Motion: Reveal sections once with a subtle 14px translate/350ms fade through IntersectionObserver; everything remains visible if JavaScript or observation fails. Chart bars transition from their previous heights in 280ms without count-up text.

Add small original CSS sun, sprout, parcel, kite, counting pebble and shape illustrations as needed for the active story world. No real people or stock photography are needed for this playful product page.
