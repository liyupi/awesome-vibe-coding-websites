# Fireworks Show Maker

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build an original single-page fireworks composition tool for [BRAND], defaulting to Nightloom Studio. The opening view is a polished editor surrounding a live Canvas 2D waterfront performance for [SHOW_TITLE] above the fictional [CITY_NAME] skyline. Visitors arrange shell type, color, timing, track, and burst position, then play the sequence with synchronized synthesized sound and share it in a URL hash.

- Audience: Write the interface and any helper copy for [AUDIENCE], by default celebration designers and creative coders. It should feel approachable to a first-time visitor while retaining the precision of a compact timeline editor.
- Goal: Let a visitor understand the scene immediately, edit the supplied starter show without instructions or sign-in, preview a reproducible performance with sound, and copy a link that restores the same show entirely on the client.
- Tone: Nocturnal, precise, and quietly festive: a pro-tool interface with luminous color rather than a cartoon arcade. Use concise US English, concrete control labels, and no marketing sections.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Vanilla CSS
- Libraries: React 18 and React DOM (MIT), Vite 5 (MIT), lucide-react (ISC), @fontsource/sora (OFL-1.1), @fontsource/inter (OFL-1.1), @fontsource/ibm-plex-mono (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Configure Vite with base: './', minification enabled, and source maps disabled; the production entry must be dist/index.html.
  - Keep all interface copy, variable defaults, shell definitions, named colors, and starter events in src/content.ts; rewrite variable-dependent copy when values change and never leave default-brand text behind.
  - Use React for editor state and dialogs, but keep particle arrays and animation timing in refs so the component tree does not rerender for every particle or frame.
  - Use two stacked Canvas 2D layers: a cached skyline/water layer redrawn only on resize and a dynamic launch/particle/reflection layer driven by requestAnimationFrame with a fixed 1/60-second simulation step and at most five catch-up steps.
  - Derive all random variation from a stable seed based on the event id and particle index so playback, seeking, and shared links reproduce the same geometry.
  - Generate launches, low bursts, and crackles at runtime with the Web Audio API; create or resume AudioContext only after an explicit user gesture and do not bundle audio files.
  - Serialize versioned show data as base64url-encoded UTF-8 JSON under the #show= URL hash; validate imported data, cap shows at 60 events, and never send show data over the network.
  - Self-host Sora, Inter, and IBM Plex Mono through the listed Fontsource packages and create ASSETS.md with package paths, source URLs, authors, and licenses for the fonts and icons.

## Variables
- [BRAND] — Studio or project name (default: "Nightloom Studio"). An invented name used in the header, document title, and small brand mark label.
- [SHOW_TITLE] — Show title (default: "Harbor Afterglow"). A short original celebration title shown above the canvas and stored in shared shows.
- [CITY_NAME] — Fictional skyline name (default: "Port Aurelia"). An invented waterfront place, never a real city or landmark.
- [AUDIENCE] — Audience (default: "celebration designers and creative coders"). Used to adapt helper copy while retaining the same editing workflow.
- [SHOW_DURATION] — Show duration in seconds (default: "24"). A numeric duration from 12 to 60; scale starter-event times proportionally when it changes.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/fireworks-show-maker in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

### Layout & motion
- Spacing: Use a 4px base unit. Header height is 64px with 18px horizontal padding; panel padding is 16px; control gaps are 8px; section gaps are 12px. Shell rows are 64px high, inputs 36px on desktop and at least 44px on touch screens, and the timeline is 220px high on desktop.
- Radius: Use 6px for panels and dialogs, 4px for buttons, inputs, shell rows, and timeline events, and 2px for small swatches. Reserve fully round shapes for status dots, toggle knobs, and the canvas position marker; avoid floating pill cards.
- Motion: Start a muted ambient preview after 600ms so the first screen becomes a living show without audio; any edit pauses it. The primary Play with sound action restarts at zero, enables audio, and plays the actual timeline.
- Motion: Launch shells along a slightly curved 0.9–1.2 second trajectory, then simulate burst particles with gravity of 0.055 canvas-heights per second squared, velocity drag of 0.985 per 60Hz step, and 1.4–3.2 second lifetimes according to shell type.
- Motion: Draw each particle's previous six positions as a fading tapered trail and mirror live bursts into the bottom 22% water band with low-alpha, vertically stretched streaks; do not use a prerecorded animation.
- Motion: Keep interface transitions between 120 and 160ms with opacity and at most 4px translation. The playhead and dragged events follow input directly without easing; toasts enter and exit over 160ms.
- Motion: When prefers-reduced-motion is set, do not autoplay. Render a representative static tableau at 22 seconds, remove interface transitions and ambient twinkling, and use half the particles with shorter trails only after explicit playback.
- Imagery: Use no photographs or generated bitmap images. Draw the original skyline, water, shell previews, position marker, and a small four-ray brand spark entirely with Canvas 2D, CSS, and inline SVG. The skyline is an invented cluster of varied rectangular towers, setbacks, rooftop antennas, scattered warm windows, and haze; include no identifiable landmark. Use Lucide only for familiar interface icons. There are no people, mascots, external illustrations, or audio files.

## Don'ts
- Do not add a backend, accounts, database, API routes, remote forms, analytics, third-party APIs, or a sharing service; all editing, audio, persistence in the URL, and preview behavior must work as static client-side files.
- Do not use CDN scripts, CDN styles, Google Fonts URLs, hotlinked assets, placeholder-image services, external audio, or remote fonts. Bundle dependencies locally, self-host Fontsource fonts, and use relative asset paths with Vite base './'.
- Do not use stock or generated photographs, recorded fireworks, music, video, third-party illustrations, or recognizable logos. All scene visuals must be original code-drawn geometry and all sound must be synthesized locally with Web Audio.
- Do not depict real city names, identifiable landmarks, commercial fireworks brands, packaging, slogans, real people's likenesses, anime or game characters, mascots, or signature illustrations. Keep [CITY_NAME] fictional.
- Do not copy reference or restricted-library source, add commercial fonts, or add a physics, animation, audio, or state library; use only the declared stack and hand-written Canvas 2D simulation and Web Audio synthesis.
- Do not hard-code copy, filenames, shell schedules, timecodes, or helper text that becomes wrong when variables change. Keep copy and starter content in src/content.ts and scale starter timing and labels to [SHOW_DURATION].
- Do not create marketing sections, metadata beyond a plain title and favicon, Open Graph tags, JSON-LD, sitemap code, or extra routes. The only page is index.html; #show= is show data, not a router.
- Do not autoplay audible sound or create AudioContext before a user gesture. Do not throw when audio, clipboard, or hash decoding is unavailable; retain the visual editor and provide the specified accessible fallback.
- Do not allow unbounded particles, device pixel ratio, event counts, or malformed hash values. Enforce the stated caps and validation, keep dist/ below 20 MB, emit no source maps, and do not copy src/ into dist/.
- Do not ship a desktop-only editor, icon-only unlabeled controls, color-only shell labels, keyboard traps, horizontal page overflow, or canvas-only positioning. Support 1440×900 and 390×844, 44px touch targets, keyboard event editing, visible focus, and reduced motion with zero console errors.
- Do not mention VibeFather in the rendered site except through the optional [CREDIT] link, and do not use VibeFather or any real brand as a variable default.
