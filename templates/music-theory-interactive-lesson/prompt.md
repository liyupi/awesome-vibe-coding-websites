# Music Theory Interactive Lesson

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a single-page interactive music theory lesson for [BRAND], an invented evening music school, on the topic '[LESSON_TOPIC]'. The page is one long scroll that repeats a fixed rhythm: short concept, hands-on widget, small win. It contains a playable two-octave piano voiced by Web Audio oscillators, a rotating SVG circle of fifths, a chord builder that lights notes and names intervals, an eight-round ear-training quiz with a score, and a closing section about the instructor and the school. All widgets read one shared state, and twelve pitch-class colors stay consistent everywhere, so color itself teaches the relationships. Copy below is written for the default values. If the values change, rewrite all copy in the one content file to fit them, and keep the widgets, layout, colors and motion exactly the same.

- Audience: [AUDIENCE]. They may not read staff notation and may not own an instrument; a laptop keyboard or a phone is enough.
- Goal: Within ten seconds the visitor presses a key, hears it and sees the theory respond. By the end of the page they can name common intervals and chords by ear, have earned four small wins and a quiz score, and know what the [BRAND] evening course offers.
- Tone: Playful, bold and plainspoken, like a good teacher on a small stage at night. Short sentences. Describes how things sound in everyday words. Never academic, never cute for its own sake.

- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - vite.config.ts: set base to './' and build.sourcemap to false. Import Motion from 'motion/react'.
  - File layout: src/content.ts (all copy, sample data, win tasks, quiz rounds), src/theory.ts (note tables, scales, chord spelling), src/audio.ts (Web Audio engine), src/store.tsx (React context plus useReducer, no state library), src/components/ (Piano, CircleOfFifths, IntervalPicker, ChordBuilder, ChordShape, Quiz, WinBar, Dock, TopBar), src/App.tsx. Images in public/images/.
  - Add the colors and fonts from the Design section to tailwind.config theme.extend under the names given there, and export the same pitch color table from src/theory.ts as a typed array indexed by pitch class 0 to 11.
  - Note tables: DEFAULT_NAMES by pitch class = C, Db, D, Eb, E, F, F#, G, Ab, A, Bb, B. Write accidentals with plain # and b characters everywhere, with no music glyphs. FIFTHS_ORDER clockwise from the top = C, G, D, A, E, B, F#, Db, Ab, Eb, Bb, F. RELATIVE_MINORS in the same order = Am, Em, Bm, F#m, C#m, G#m, D#m, Bbm, Fm, Cm, Gm, Dm.
  - Scale spelling table: C = C D E F G A B; G = G A B C D E F#; D = D E F# G A B C#; A = A B C# D E F# G#; E = E F# G# A B C# D#; B = B C# D# E F# G# A#; F# = F# G# A# B C# D# E#; Db = Db Eb F Gb Ab Bb C; Ab = Ab Bb C Db Eb F G; Eb = Eb F G Ab Bb C D; Bb = Bb C D Eb F G A; F = F G A Bb C D E. Key signatures: C none; G 1 sharp; D 2 sharps; A 3 sharps; E 4 sharps; B 5 sharps; F# 6 sharps; Db 5 flats; Ab 4 flats; Eb 3 flats; Bb 2 flats; F 1 flat.
  - Chord spelling function: start from the root name, take the letter that many steps up for each degree (2nd +1, 3rd +2, 4th +3, 5th +4, 7th +6), then add the # or b characters needed to hit the pitch class. Double flats are written bb, for example Ebdim = Eb Gb Bbb.
  - src/audio.ts: create one AudioContext lazily inside the first pointerdown or keydown handler and call resume() there; never touch audio on page load. Graph: voices to a lowpass BiquadFilter (3200 Hz, Q 0.6), to a master GainNode (0.7), to a DynamicsCompressor, to destination. Each voice is a triangle oscillator at the note frequency plus a sine an octave up at gain 0.25, through a voice gain with attack 0.008 s to peak 0.5, decay 0.25 s to sustain 0.28 and release 0.35 s. Equal temperament with A4 = 440 Hz. Limit to 10 voices and steal the oldest. Mute ramps the master gain to 0 over 20 ms and back to 0.7 on unmute.
  - Playback helpers in src/audio.ts: playNote(midi, ms); playMelodic(midis) with 450 ms between notes, then all notes together for 900 ms; strum(midis) with 45 ms between notes and a 1200 ms hold; playScale(midis) with 170 ms between notes; tick(midi), a 60 ms note at gain 0.15. Each helper also reports notes on and off to the store, so every piano lights in sync. Each one takes a silent flag that skips this reporting; quiz playback uses it until the round is answered, so the dock cannot give away the answer.
  - src/store.tsx state: selectedKey (index into FIFTHS_ORDER, starts at [START_KEY]), activeNotes (set of midi numbers now sounding), interval {rootMidi, semitones: 7}, chord {rootName, quality: 'major'}, lastEvent {label, midis, playback}, wins [false, false, false, false], muted false, heroPlayed (last two midi notes pressed on the hero piano). The dock, top bar and all pianos read from this one store.
  - Linking rules: (1) changing selectedKey sets interval.rootMidi to the tonic in octave 4 and sets chord.rootName to the tonic, keeping the quality. (2) Choosing a root chip or quality in the chord builder rotates the circle: for major, dominant 7th, major 7th, augmented and sus chords, to the root's own wedge; for minor, minor 7th and diminished chords, to the major key whose inner wedge has that root (root + 3 half steps). This rotation must not overwrite the chord that triggered it, so pass a source flag. (3) Diatonic chord chips in the circle panel set the chord builder and keep the circle where it is. (4) A press on the hero piano sets selectedKey to that pitch class. A press on the Chapter 1 piano sets interval.rootMidi to that pitch class in octave 4 and leaves selectedKey alone. Presses on other pianos only play and pulse the matching circle wedge.
  - Keyboard map on window keydown, ignoring e.repeat, any modifier key, and focus inside an input: A=C, W=C#, S=D, E=D#, D=E, F=F, T=F#, G=G, Y=G#, H=A, U=A#, J=B, K=C up an octave, O=C# up, L=D up, P=D# up, ;=E up, '=F up. Base octave starts at 4; Z sets it to 4 and X sets it to 5; notes above B5 are ignored. The press counts as a press on the piano of the hero or chapter now in view (tracked with IntersectionObserver); anywhere else it only plays the note.
  - npm scripts: dev, build (tsc --noEmit && vite build), preview. Add public/favicon.svg, a 12-wedge pinwheel in the note colors, and a plain title '[BRAND] | [LESSON_TOPIC]'.

### Layout & motion
- Spacing: Base unit 8px. Page container max width 1320px with 40px side gutters on desktop and 16px on mobile. Chapters use 120px vertical padding on desktop and 72px on mobile. Widget panels use 32px padding on desktop and 16px on mobile. Gaps between panel groups are 24px.
- Radius: Panels 28px, cards 20px, buttons and chips fully round (999px), piano keys square at the top and 10px at the bottom on naturals, 6px at the bottom on sharps.
- Motion: Stage beam: on every press of a hero piano key, a vertical beam in that note's color rises from the key to the top of the hero, 2 key-widths wide with a linear gradient fading to transparent, scaleY 0 to 1 in 120 ms, then fades out over 600 ms. Several beams may overlap. This is the signature effect.
- Motion: Key press: a pressed key moves down 3px in 60 ms, its fill becomes the pitch color and it gains a soft outer glow in that color. On release it returns over 140 ms.
- Motion: Circle rotation: Motion spring with stiffness 180 and damping 22 to the nearest 30-degree snap, taking the shortest path. While dragging, the rotation follows the pointer directly and a tick() plays each time a new wedge crosses the pointer. Wedge labels counter-rotate to stay upright.
- Motion: Win bar: the dashed outline fills from left to right with acid yellow in 350 ms, the check icon pops in with a spring (scale 0.4 to 1), and the top bar's win count bumps to scale 1.2 and back.
- Motion: Chord change: chips animate in with a 40 ms stagger, moving up 8px and fading in; the chord shape polygon morphs to its new vertices with a spring (stiffness 140, damping 18).
- Motion: Scroll reveal: chapter text and panels move up 24px and fade in once over 500 ms as they enter the viewport.
- Motion: Idle hero: on load, a 2.4 s wave of light passes left to right across the piano's color strips, once only, with no sound.
- Motion: With prefers-reduced-motion: no beams, wave or scroll reveals. The circle jumps to its position with no spring, and key presses only change color. Sound and all widgets still work.
- Imagery: A stage at night. Four matching photographs in one shoot style (ultraviolet haze, coral key light, thin acid yellow accent) set the mood for the hero, the instructor, the evening class and the final band. Everything interactive is drawn in SVG and HTML: the piano, circle, chord shape and color strips. Instruments carry no maker names.

## Don'ts
- No backend: no server code, API routes, databases, auth, third-party APIs, analytics, or forms that submit anywhere. The contact details are plain text.
- Static output only in dist/, built with npm run build, using relative asset paths (Vite base './'). Minified, no source maps, no src/ copied into dist/, total under 20 MB.
- Keep this as one page, index.html. In-page links use anchors (#quiz); any link to a file uses a file name, never a bare directory.
- Self-host every font through the listed Fontsource packages. Never load fonts from fonts.googleapis.com, fonts.gstatic.com or any other CDN. No CDN script or link tags. Download every image into the project; never hotlink.
- Keep all copy, sample data, win tasks and quiz rounds in src/content.ts. When variable values change, rewrite that file so no default brand, person or topic remains. The widgets, layout, colors and motion stay the same.
- No audio files of any kind: no samples, recordings or sound fonts. All sound is synthesized in the browser with oscillators.
- Do not create or resume an AudioContext before a user gesture, and never autoplay sound on load. The page must run with zero console errors or warnings at 1440x900 and 390x844.
- No instrument maker names or logos on the piano, in images or anywhere else.
- No melodies, riffs or chord charts from existing songs, as examples or in the quiz, and no 'sounds like the start of' song references. Use only intervals, scales and generic progressions.
- No lesson text, diagrams or exercise wording from existing theory sites, books or courses. Use the copy in this prompt.
- No commercial music notation fonts, no staff notation, and no music glyph characters; write accidentals as # and b.
- No Aceternity UI, Tailwind Plus or other restricted UI library source, and no audio or piano component libraries; write the widgets yourself.
- No likeness of real musicians or teachers. The instructor image shows a fictional AI-generated person. No named mascots or characters from music education apps or games.
- No off-white or cream page sections. The whole page stays on the ultraviolet and violet grounds, apart from the coral band.
- Respect prefers-reduced-motion as described in Design, and keep body text at WCAG AA contrast. Never put text-colored labels on bright note colors; use pit ink #120634 there.
- No horizontal page scrolling at any width, and no fixed dock covering the piano or answer buttons.
- List every third-party file in ASSETS.md at the project root with path, source URL, author and license. No mention of VibeFather inside the site except the optional [CREDIT] footer link.
