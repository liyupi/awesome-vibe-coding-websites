# Service Status Page

> A calm service status page with 90-day uptime bars, incident timelines, and local update subscriptions.

Service Status Page is a focused, single-page template for products that need to communicate reliability without turning system health into a marketing page. It suits SaaS teams, developer platforms, online services, and internal products that want a clear home for current availability, component history, incident updates, and notification preferences.

The first screen pairs an unmistakable overall-state message with a detailed 90-day health panel. Below it, six component rows align current status, daily uptime strips, and exact sample percentages so visitors can scan for problems or inspect a pattern. The incident section includes resolved outages and completed maintenance, each with timestamped updates in expandable timelines. A subscription area provides email validation, incident and maintenance preferences, and an honest local-only success state suitable for a static demo.

The visual system uses warm off-white surfaces, deep green typography, thin borders, compact mono data, and restrained status colors. Manrope, Inter, and IBM Plex Mono keep headlines, explanations, and measurements distinct without making the interface feel busy. Layouts adapt from a wide operations dashboard to readable stacked rows on mobile. Fixed sample dates, plain-language incident updates, and accessible status labels make the page feel operational rather than decorative.

Built with Vite, React, TypeScript, and Tailwind CSS, the template needs no backend, third-party API, or remote asset. Variables change the brand, service type, audience, and support address, while the content file holds component records and incident narratives for straightforward adaptation. CSS and Lucide icons supply the complete visual layer; no photographs or generated assets are required.

## Variables

Replace these in the prompt with your own values; everything else stays as written.

| Variable | What it is | In the demo |
|---|---|---|
| `[BRAND]` | Brand name | Fablegrid |
| `[SERVICE]` | Service description | cloud application platform |
| `[AUDIENCE]` | Primary audience | product engineering teams |
| `[SUPPORT_EMAIL]` | Support email | status@fablegrid.example |

## How to use it

1. Copy [prompt.md](prompt.md), or run `npx vibefather add service-status-page` in your project.
2. Replace the `[VARIABLES]` with your own brand, copy and details.
3. Paste it into Claude Code, Codex, Cursor or another AI coding agent and let it build. [DESIGN.md](DESIGN.md) holds the colors, type and spacing on their own if you only want the look.

## Make it yours

- A developer API platform: set BRAND to your API name, SERVICE to your API, and rewrite the six components as endpoints, authentication and dashboard availability.
- An online learning platform: set AUDIENCE to students and instructors, and rewrite incident updates around video playback, quizzes and login issues.
- An indie SaaS founder: point SUPPORT_EMAIL at your own inbox and replace the sample incidents with your real resolved outages and maintenance windows.
- A cloud hosting provider: set SERVICE to cloud hosting, relabel components as compute, storage and networking, and keep the 90-day bars as your uptime record.

## FAQ

### What comes in the Service Status Page template besides the prompt?
The Service Status Page template includes the published prompt, a DESIGN.md covering colors, typography, spacing and motion, and the variable list. As a free template, the prompt and DESIGN.md are available for personal, non-commercial use under CC BY-NC 4.0. Commercial or client work, plus the demo source code, requires Pro membership.

### How do I change the components and incidents in the Service Status Page template?
All component records, 90-day daily status values and incident narratives live in the template's content file. To adapt the Service Status Page, rewrite each component name and description for your product, replace the daily status arrays with your own history, and edit the four incident entries with your own timestamped updates. The layout, record counts and expandable timelines stay the same.

### Does the Service Status Page subscription form actually send emails?
No. The Service Status Page subscription form includes email validation and incident and maintenance preference toggles, but the confirmation is a local-only success state built for a static demo. It does not connect to a mailing list or send notifications. To make it real, you would connect the form to your own email service after generating the site.

### Can the Service Status Page be used for an internal product rather than a public SaaS?
The Service Status Page template suits internal products as well as public services. Set the BRAND, SERVICE and AUDIENCE variables to your internal platform and team, and rewrite the component descriptions and incident language for that audience. The page has no backend or external API, so it can be hosted on any static host inside your network.

### Which variables do I set first when adapting the Service Status Page?
Start with BRAND, SERVICE, AUDIENCE and SUPPORT_EMAIL. The Service Status Page uses BRAND in the header, hero, subscribe panel, footer and document title; SERVICE names what is being reported; AUDIENCE shapes the component and incident copy; and SUPPORT_EMAIL gives visitors a contact address. After that, rewrite the component records and incident narratives in the content file.

### How do I build a service status page with AI?
Copy the prompt from this page or run npx vibefather add service-status-page, replace [BRAND], [SERVICE], [AUDIENCE] and [SUPPORT_EMAIL] with your own content, and paste it into Claude Code, Codex, Cursor or another AI coding agent. The live demos were built from exactly that text.
