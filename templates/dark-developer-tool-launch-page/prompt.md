# Dark Developer Tool Launch Page

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
A one-page launch site for [BRAND], a local-first [PRODUCT] for [LANGUAGES]. The page proves speed and precision by showing the product working: a hero terminal that types real-looking review sessions, a diff viewer where line comments stream in, a benchmark bar race, a keyboard shortcut overlay opened with '?', a changelog teaser and copy-to-clipboard install commands. Everything is drawn in code; there are no photos.

- Audience: [AUDIENCE]: engineers and tech leads who live in the terminal, distrust marketing pages and decide in under a minute whether a tool is worth one install command.
- Goal: Get the visitor to copy the install command and run a first review. Secondary: show exactly what a review looks like (terminal + diff), back the speed claim with an illustrative benchmark, and signal an active project through the changelog.
- Tone: Terse, technical and confident, like a well-written README. Short sentences, concrete numbers, real command names, no hype words (no 'revolutionary', 'blazing', 'supercharge', 'magic'). Monospace for anything a developer would type or read in a terminal.

## Variables
- [BRAND] — Product name (default: "Ferrule"). Invented tool name, one or two words. Used in the wordmark, title, headlines, terminal banner, comment author line, feature copy, changelog and footer. Never a real developer tool.
- [BRAND_SLUG] — Command and package name (default: "ferrule"). Lowercase, no spaces. It is the CLI command typed in every terminal line, the npm/brew package name in the install box, the config file name (.[BRAND_SLUG].toml) and the bot name on diff comments. Derive nothing else from it.
- [PRODUCT] — What the tool is (default: "code review CLI"). Short noun phrase, lowercase. Drives the title, hero copy, feature cards, terminal session content, diff comments and benchmark metric. For a test runner the diff comments become failing-test annotations; for a linter they become rule violations.
- [LANGUAGES] — Languages or file types it covers (default: "TypeScript, Go and Python"). Two to four languages or formats. The terminal file paths, the diff code sample, the config snippet and the first integration chips use these languages.
- [AUDIENCE] — Who it is for (default: "teams that ship several times a day"). Short phrase, lowercase. Used in the hero subline, the features intro and the final call to action.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/dark-developer-tool-launch-page in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

### Layout & motion
- Spacing: Container max-width 1200px with 24px side padding (16px under 640px). Sections are separated by 1px Line borders full-bleed, with 112px vertical padding on desktop and 72px on mobile. Grids use a 1px gap over a Line-colored background so cells share hairline borders. Inner card padding 24px. Base unit 4px; dense rhythm, no huge empty bands.
- Radius: 6px on buttons, chips, kbd keys, inputs and tags; 10px on the terminal window, diff viewer, install box, overlay panel and feature grid outer frame; 999px only on severity dots and the hint chip.
- Motion: Section reveal: every section heading and block fades up (opacity 0 to 1, y 16px to 0, 0.5s, ease [0.22, 1, 0.36, 1]) once when 20% visible; children stagger by 0.06s.
- Motion: Hero terminal: commands type character by character at 32ms per char with a blinking block caret (Signal, 1s steps); output lines appear one by one with 110ms between lines; the spinner cycles the braille frames ⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏ every 80ms for 900ms before being replaced by its result line. After the last line of session 2 it waits 2.6s, fades the body out over 0.3s and restarts session 1. It starts only when the terminal is in view and pauses when off screen or when the tab is hidden.
- Motion: Diff viewer: when the viewer is 35% in view, the three comments open in order, 1.1s apart. For each, the anchored line gets a 1.2s pulse-line highlight, then the comment card expands from height 0 to auto with opacity 0 to 1 (0.45s); the matching item in the Findings panel ticks from a hollow dot to a filled severity dot.
- Motion: Benchmark race: when the chart is 40% in view, bars grow from width 0 to their value (1.1s, ease [0.22, 1, 0.36, 1], stagger 0.12s top to bottom) and the numbers count up in sync using Motion's animate() on a motion value, formatted to one decimal for seconds and integers for counts. Switching tabs replays the race from 0.
- Motion: Micro-interactions: copy buttons swap the Lucide Copy icon for Check with a 0.15s scale pop and show a toast 'Copied: <command>' bottom-center for 1.8s; buttons lift 1px and brighten on hover; chips and cards change border to Line Strong on hover; the active tab underline slides between tabs with a shared layoutId.
- Motion: Shortcut overlay: backdrop fades to rgba(10,11,13,0.72) with backdrop-blur 6px in 0.2s; the panel scales from 0.97 to 1 and fades in over 0.2s; Esc or a backdrop click reverses it.
- Motion: Changelog expand: older entries animate height 0 to auto and fade in over 0.35s.
- Motion: prefers-reduced-motion: no typing, spinner or loop (the terminal renders session 1 complete and static with a Replay button that swaps to session 2), diff comments are all open from the start, bars and numbers render at their final values, reveals are instant, smooth scrolling is off. Overlay and toast still appear but without scale or movement.
- Imagery: No photos and no illustrations. The visual interest comes from code-drawn UI: the terminal window, the diff viewer, the bar chart, hairline grids, a very faint 48px background grid under the hero masked with a radial fade, and a 3.5% SVG noise overlay across the page. The wordmark glyph is an inline SVG: a 20x20 rounded square (radius 5) in Signal with two Ink horizontal strokes of different length, like two diff lines, the lower one offset right by 4px. Icons are Lucide at 18–20px with stroke-width 1.75.

## Don'ts
- No backend of any kind: no server code, API routes, databases, auth, analytics, forms that submit anywhere or third-party APIs. Copy-to-clipboard and the shortcut overlay are the only interactions that touch the browser outside the page.
- Do not load fonts from fonts.googleapis.com, fonts.gstatic.com, Adobe Fonts or any CDN. Self-host through the three Fontsource packages only.
- No CDN <script>, <link> or import maps. Every script, style, font and icon is in the project and bundled into dist/.
- No source maps in the production build (build.sourcemap false), and src/ is not copied into dist/.
- Relative asset paths (Vite base './'). Internal links are hash anchors on index.html (#demo, #features, #benchmarks, #integrations, #changelog, #install, #top) or ./index.html, never a bare directory or a leading slash. No link points to a page that does not exist.
- Do not change the stack (Vite 5 + React 18 + TypeScript + Tailwind CSS 3.4 + Motion + lucide-react + Fontsource) unless the user asks. No router, no UI kit, no syntax-highlighting library, no chart library, no 3D.
- No names, logos or wordmarks of real code-review, linting, testing or AI coding tools. The product is the invented [BRAND]; its only mark is the code-drawn glyph and typeset name.
- No real benchmark numbers and no real competitor names in the bar race. Rows are generic categories ('Hosted review bot', 'Linter chain (5 tools)', 'Script calling a large model'), every figure is invented, and the chart keeps its 'Illustrative figures' badge and methodology footnote.
- No real company or open-source project logos in integrations or anywhere else; integrations are plain text chips with generic names, and languages are plain words.
- Do not copy the diff view styling, colors, layout chrome or octicon-style glyphs of real code-hosting sites. Draw the diff viewer from scratch as specified and use Lucide icons only.
- No real repository names, usernames, people or real code in terminal, diff, config or changelog samples. Use the invented ledgerline repository and the code given here.
- No commercial or custom fonts: only Space Grotesk, Inter and JetBrains Mono (OFL), self-hosted.
- Only dependencies under MIT, ISC, BSD, Apache-2.0, 0BSD, CC0 or Unlicense (OFL for fonts). No Aceternity UI, Tailwind Plus / Tailwind UI or purchased template code; write every effect yourself.
- No photos, stock images, placeholder-image services, Unsplash, Pexels or Pixabay. All visuals are drawn in code.
- One accent only: Signal lime. Add, Del, Warn and Info are semantic colors for diffs, severities and changelog tags only, never for buttons or headings. No purple gradients, no glassmorphism cards, no neon glows beyond the two subtle ones specified (terminal shadow and final CTA radial).
- No mention of VibeFather, its pricing, members or numbers anywhere in the site except the optional [CREDIT] footer link.
- Respect prefers-reduced-motion exactly as described under Design motion: typing, spinner, comment sequence and bar race jump to their end states. The terminal loop pauses when off screen or when the tab is hidden.
- Accessibility: every interactive element is keyboard reachable with a visible 2px Signal focus ring (outline-offset 2px); the overlay traps focus and closes on Esc; tabs use role tablist/tab with aria-selected; the terminal body has aria-live off and an sr-only summary of session 1; copy buttons have aria-labels; the toast uses role status.
- Must render at 1440×900 and 390×844 with zero console errors and no horizontal page scroll (only the diff code area and terminal lines may scroll inside their own boxes). Clipboard calls are wrapped in try/catch with the textarea fallback.
- Keep dist/ under 20 MB (target under 2 MB).
- No lorem ipsum, filler or hype words. No meta descriptions, Open Graph tags, JSON-LD or sitemap: only the <title> and favicon.
