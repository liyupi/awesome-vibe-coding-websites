# Crypto Wallet Landing Page

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a polished single-page landing site for [BRAND], an invented [PRODUCT_TYPE] for [AUDIENCE]. Make the product tangible in the first screen through a large, layered CSS phone and browser-extension composition, not photography or typography alone. Use only fictional network identities, assets, balances and addresses; every product interaction is a local interface demonstration.

- Audience: The site speaks to [AUDIENCE], with secondary appeal to product founders and developers evaluating a wallet concept. Assume visitors may understand digital assets but do not want dense protocol jargon.
- Goal: Explain self-custody in plain language, show the phone and browser experiences, make security controls understandable, and guide visitors to a platform-specific demo download without implying that a real wallet service exists.
- Tone: Calm, exact and reassuring without making guarantees. Use short sentences, concrete interface labels and transparent demo disclosures. Avoid trading language, hype, fear and technical showing-off.

## Stack
- Framework: Vite 6 + React 19 + TypeScript 5.7
- Styling: Tailwind CSS 4
- Libraries: Vite 6 (MIT), React 19 + React DOM 19 (MIT), TypeScript 5.7 (Apache-2.0), Tailwind CSS 4 + @tailwindcss/vite 4 (MIT), Motion 12 (motion/react) (MIT), lucide-react (ISC), @fontsource-variable/space-grotesk (OFL-1.1), @fontsource-variable/manrope (OFL-1.1), @fontsource/ibm-plex-mono (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Set the npm build script to tsc -b && vite build. Configure vite.config.ts with base: './' and build.sourcemap: false; the deployable output is only dist/.
  - Use Tailwind CSS 4 through @tailwindcss/vite. Define the palette, font families, spacing tokens, shadows and keyframes in src/index.css; do not add a second styling system.
  - Install and import Motion from motion/react for entrance and interface transitions, and lucide-react for generic interface icons only. Do not add an animation, carousel, icon or component library beyond this stack.
  - Self-host Space Grotesk Variable, Manrope Variable and IBM Plex Mono through the listed Fontsource packages. Import only the required subsets and weights from local node_modules; no font CDN.
  - Keep every headline, paragraph, navigation label, button label, network name, balance, address, FAQ and sample datum in src/content.ts, keyed by section. Derive all default product copy from BRAND, PRODUCT_TYPE, AUDIENCE, PRIMARY_CTA and NETWORK_NAMES, and rewrite it when those values change.
  - Derive a lowercase hyphenated brand slug in code for demo hostnames and downloaded checklist filenames. Use the reserved .example suffix for any displayed demo hostname and never navigate to it.
  - Divide the implementation into Header, HeroDevices, NetworkExplorer, ProductSurfaceDemo, SecurityExplorer, SetupSteps, DownloadPanel, FaqAccordion and Footer components. Keep device screens and original network symbols as local React/HTML/CSS/inline SVG, not image files.
  - Use React state only for demo interactions. No persistence is required; reset sample UI state on reload. Provide semantic buttons, visible keyboard focus, aria-pressed or aria-selected states, labeled icon buttons and an Escape-closeable mobile menu and dialog.

## Design
### Colors
- Porcelain `#F3F1EB` — Main page canvas and quiet negative space.
- Paper `#FCFBF8` — Cards, device screens, navigation and raised surfaces.
- Ink `#121326` — Primary text, dark buttons and high-contrast details.
- Slate `#626577` — Secondary copy and metadata; never use for text smaller than 14px on tinted backgrounds.
- Line `#D9D7E1` — One-pixel borders, grid rules and inactive controls.
- Midnight `#191A30` — Security section, browser chrome and dark device details.
- Iris `#6C4FE0` — Primary accent for selected states, keylines, links and small highlights; use white text on solid Iris.
- Iris Mist `#E9E3FF` — Soft accent fields, icon containers and the download-panel halo.

### Typography
- Display and headings: Space Grotesk Variable (OFL), weights 500/600/700
- Body and interface: Manrope Variable (OFL), weights 400/500/600/700
- Numbers and technical labels: IBM Plex Mono (OFL), weights 400/500

### Layout & motion
- Spacing: Use an 8px base grid and a 12-column desktop layout inside a 1280px max-width container with 32px side gutters. Header height is 76px. Standard sections have 112px vertical padding; hero has 72px top and 88px bottom. At 390px use 20px gutters, 68px section padding, 24px card padding and a single-column flow. Keep body measure at 58–66 characters and headline measure at 11–13 characters per line where practical.
- Radius: Use 999px pills for buttons and small tags, 10px for inputs and compact controls, 16px for standard cards, 28px for feature panels, 20px for the browser frame and 38px for the phone body. Borders are 1px solid Line. Device shadow: 0 32px 80px rgba(18,19,38,0.16), 0 8px 24px rgba(18,19,38,0.08); ordinary cards have no heavy shadow.
- Motion: On initial load, stagger hero eyebrow, headline, body and actions by 70ms with opacity 0→1 and y 16→0 over 480ms. Bring the browser from y 24 and rotate -2deg and the phone from y 36 and rotate 4deg into their final positions over 700ms; play once only.
- Motion: Reveal each section's heading and direct children with IntersectionObserver and Motion at 20% visibility, using y 18→0, opacity 0→1, 480ms duration and 60ms child stagger. Never hide content when JavaScript is unavailable.
- Motion: Switch phone/browser and network/security selections with 220ms opacity and 8px vertical transitions. Preserve component dimensions so the page does not jump. Accordions animate height over 240ms and chevrons rotate 180 degrees.
- Motion: On capable pointers only, let the hero device group translate at most 6px toward the pointer with a 250ms ease-out return. Do not add continuous floating, auto-rotating carousels, marquees or scroll-jacking.
- Motion: Under prefers-reduced-motion: reduce, disable pointer response, smooth scrolling, entrance transforms and animated transitions; show all content immediately and preserve every interaction.
- Imagery: Use no raster images. The visual anchor is a meticulously layered phone and browser-extension interface drawn with HTML, CSS and inline SVG. Use subtle CSS grid lines, two blurred Iris Mist radial fields and soft shadows for depth. Network identities are six original geometric SVG compositions, not adapted token logos. Generic Lucide icons support actions such as copy, lock, check, arrow and download; they never stand in for network or platform logos.

## Don'ts
- Do not use real wallet, blockchain, token, exchange or app-store names and logos. The six network names and every symbol must remain invented, and platform buttons use generic icons only.
- Do not copy product interfaces, brand palettes, slogans, illustrations, code or marketing copy from an existing wallet or website. Build every device screen and geometric mark from this specification.
- Do not add live wallet connections, seed-phrase collection, account creation, transaction signing, price feeds, blockchain RPC calls, external APIs or real installer downloads.
- Do not make investment-return promises, display profit percentages or live prices, invent adoption figures, or claim that the product is audited, unhackable, guaranteed safe or financially beneficial.
- Do not present sample balances, addresses, network names, request approvals or downloaded checklists as real services. Keep the demo disclosures visible and never ask for genuine credentials or recovery information.
- Do not use custom commercial fonts, signature icons associated with an existing crypto product, brand mascots, recognizable people, token art or any third-party logo.
- Do not use stock photography, generated portraits, hotlinked images, placeholder-image services, Unsplash, Pexels, Pixabay, Google Images or restricted-license assets; this design needs no raster imagery.
- Do not load fonts, scripts, styles, icons or other assets from a CDN. Self-host the specified Fontsource fonts and bundle all dependencies locally.
- Do not add a backend, server code, API routes, database, authentication, remote form submission, analytics, tracking cookies or third-party embeds. All interactions and downloads must run locally in the browser.
- Do not add smooth-scroll hijacking, perpetual marquees, autoplay carousels, excessive parallax, flashing market motion or animation that ignores prefers-reduced-motion.
- Do not produce anything other than a static dist/ build with relative asset paths. Keep dist/ under 20 MB, minified, with no source maps and no src/ directory copied into it.
- Do not use bare-directory links, external demo-host links or empty href placeholders. Internal navigation must use ./index.html#section targets; demo hostnames are text only and use the reserved .example suffix.
- Do not add SEO metadata blocks, Open Graph, JSON-LD, sitemap code or keyword-stuffed headings. A plain document title derived from [BRAND] and an original local favicon are sufficient.
- Do not show dates, activity timestamps, a copyright year, fake testimonials, fake customer counts or fake company addresses.
- Do not hard-code Velmora or the default network list inside reusable components. Keep all copy and sample data in src/content.ts and rewrite product-specific copy when BRAND, PRODUCT_TYPE, AUDIENCE, PRIMARY_CTA or NETWORK_NAMES changes.
- Do not mention VibeFather in the site except the optional [CREDIT] footer link. All visible copy, labels, sample data and accessible names must be US English.
- Do not ship horizontal overflow, inaccessible click-only divs, keyboard traps or console errors. Verify the complete experience at 1440×900 and 390×844, including menus, tabs, accordions, copy feedback and checklist downloads.
