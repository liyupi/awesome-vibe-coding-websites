# Painter Portfolio and Print Shop

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build an original multi-page website for [BRAND], led by fictional painter [ARTIST_NAME], whose [ARTWORK_THEME] practice is presented through a series-filtered gallery, artwork detail pages, archival print configuration, a persistent cart, and commission inquiries. Use only the invented content and six supplied generated assets.

- Audience: The site's visitors are [AUDIENCE]. The template itself is for independent painters, mixed-media artists, and illustrators who need one coherent place to exhibit originals, sell prints, and discuss commissions.
- Goal: Let visitors move naturally from visual discovery to artwork details, a configured print purchase, or a well-defined commission brief while keeping the artwork visually dominant.
- Tone: Quiet, observant, tactile, and confident. Write like an artist explaining materials and process in plain US English; avoid grand claims, sales pressure, generic inspirational copy, and references to real people or institutions.

## Stack
- Framework: Vite 5 + React 18 + TypeScript 5
- Styling: Tailwind CSS 3.4 + vanilla CSS
- Libraries: react (MIT), react-dom (MIT), vite (MIT), @vitejs/plugin-react (MIT), typescript (Apache-2.0), tailwindcss (MIT), postcss (MIT), autoprefixer (MIT), motion (MIT), lucide-react (ISC), @fontsource/fraunces (OFL-1.1), @fontsource/manrope (OFL-1.1), @fontsource/ibm-plex-mono (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Create a Vite React TypeScript project with npm scripts dev set to vite and build set to tsc -b && vite build; keep the stack fixed.
  - Set vite.config.ts base to './', build.outDir to 'dist', build.sourcemap to false, and build.rollupOptions.input to the six root files index.html, gallery.html, artwork.html, shop.html, print.html, and commissions.html.
  - Give every root HTML file the same /src/main.tsx entry. Route from window.location.pathname and URLSearchParams; artwork.html and print.html must show the first catalog item when id is missing or unknown.
  - Configure Tailwind and PostCSS in the standard Tailwind 3.4 way, scanning all root HTML files and src/**/*.{ts,tsx}. Put the exact color tokens, typography, keyframes, frame treatments, and reduced-motion overrides in src/index.css.
  - Import only local Fontsource weight files for Fraunces 400/500/600, Manrope 400/500/600/700, and IBM Plex Mono 400/500 in src/index.css.
  - Keep all variables, navigation, artist copy, series, artwork records, print records, option prices, FAQs, form choices, image paths, and links in src/content.ts. Give artworks stable ids tidal-orchard, quiet-current, field-notes, after-rain, and ochre-interval.
  - Use a shared React cart context persisted to localStorage, with a versioned cart key and graceful handling of malformed stored data. Available originals have a maximum quantity of one; prints have a maximum quantity of six.
  - Use the motion package's React entry point for interface transitions and useReducedMotion; use lucide-react icons only, with accessible labels for every icon-only control.
  - Download the six listed generated images into public/images and use relative image paths. Create ASSETS.md at the project root listing every image path, exact source URL, generation credit, font package and OFL license, and Lucide ISC license.

## Variables
- [BRAND] — Studio or shop name (default: "Mara Vale Studio"). An invented artist-studio name used in the wordmark, page title, footer, and order copy.
- [ARTIST_NAME] — Artist name (default: "Mara Vale"). A fictional person, never a real artist or public figure.
- [ARTWORK_THEME] — Artistic theme (default: "Coastal Abstractions"). A short phrase guiding series names, artist statements, and rewritten artwork stories.
- [LOCATION] — Studio location (default: "Portland, Maine"). City and state or region used in the studio introduction and footer.
- [AUDIENCE] — Primary audience (default: "Collectors and design-led homeowners"). The visitors addressed by the shop and commission copy.
- [CONTACT_EMAIL] — Contact email (default: "hello@maravale.example"). An invented .example address for this static demonstration.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/painter-portfolio-and-print-shop in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design
### Colors
- Paper `#F3EFE6` — Primary page background with a subtle CSS noise texture at 2 percent opacity.
- Canvas `#FFFDF8` — Image mats, forms, drawers, and alternating editorial bands.
- Forest Ink `#20372E` — Primary text, dark buttons, footer background, and strong borders.
- Charcoal `#292A27` — Body copy and artwork information where forest green would be too colorful.
- Sage `#9AA48F` — Selected filters, quiet decorative fields, and secondary illustration accents; never body text on Paper.
- Terracotta `#A94F37` — Availability accents, focus rings, small underlines, and active states with accessible contrast.
- Muted Text `#676A61` — Secondary copy and metadata on Paper or Canvas.
- Hairline `#D3CCBE` — One-pixel dividers, input borders, image outlines, and grid rules.

### Typography
- Display and artist statements: Fraunces (OFL), weights 400/500/600
- Body, navigation, buttons, and forms: Manrope (OFL), weights 400/500/600/700
- Artwork metadata, dimensions, prices, and counters: IBM Plex Mono (OFL), weights 400/500

### Layout & motion
- Spacing: Use a 12-column desktop grid, max-width 1360px, 48px desktop gutters, 24px tablet gutters, and 20px mobile gutters. Section padding is 112px desktop and 72px mobile. Hero copy uses 24px internal spacing; artwork captions sit 14px below images. Use an 8px base spacing scale and keep reading columns at 62–68 characters.
- Radius: Artwork, image mats, forms, and buttons are square with 0–2px radii; only availability badges, filter chips, and small cart-count indicators may be fully rounded. Avoid floating rounded-card compositions and heavy shadows.
- Motion: On the home hero, reveal headline lines through vertical masks over 560ms with 80ms stagger; fade the studio image from opacity 0 and scale 1.025 to 1 over 850ms, then reveal the smaller artwork inset after a 180ms delay.
- Motion: Reveal section headings and artwork cards with a 24px upward translation and opacity transition over 600ms, staggered by 70ms only on first viewport entry. Never hide content indefinitely if IntersectionObserver is unavailable.
- Motion: Open the gallery lightbox with a 180ms backdrop fade and image scale from 0.985 to 1. Next/previous changes crossfade in 140ms without moving the controls.
- Motion: Slide the cart drawer in from the right over 260ms with a 180ms overlay fade. Animate quantity totals with a subtle 120ms opacity change, not bouncing badges.
- Motion: Crossfade print frame treatments over 160ms while the image dimensions remain fixed. Filtered gallery items use a 180ms fade and immediate, stable grid reflow.
- Motion: Under prefers-reduced-motion, remove masked entrances, scaling, smooth scrolling, and stagger; render content immediately and keep state changes readable with near-instant opacity transitions.
- Imagery: Use exactly six locally hosted generated assets: one wide editorial working-studio photograph and five original abstract acrylic and oil-pastel paintings. The painter is fictional and seen from behind with no visible face. Paintings share warm ivory, sage, terracotta, charcoal, and muted cobalt with layered palette-knife texture and soft north-window light. Show painting assets straight-on and uncropped on detail pages; use intentional object-fit cropping only for cards and the hero. Frame and mat previews are CSS treatments around the same artwork, not extra images. Never add signatures, watermarks, real artworks, real likenesses, stock photos, or named-artist imitation.

## Don'ts
- Do not add a backend, server code, API routes, databases, authentication, external APIs, analytics, payment collection, or forms that transmit data. Cart, drafts, previews, and the clearly labeled mock checkout must remain client-side.
- Do not hotlink images, fonts, scripts, icons, or styles. Download the six exact generated images, self-host all Fontsource files, keep every runtime asset local, and create the required ASSETS.md.
- Do not use existing artists' names, biographies, signatures, studio identities, recognizable paintings, reproductions of real artworks, or references to real exhibitions, galleries, awards, collectors, or customers.
- Do not generate or insert text, lettering, signatures, logos, watermarks, recognizable real people, celebrity likenesses, anime or game characters, branded objects, or imagery in a named artist's style.
- Do not use Unsplash, Pexels, Pixabay, Google Images, placeholder-image services, CC BY-NC or CC BY-SA assets, commercial fonts, restricted component source, or dependencies outside the allowed licenses.
- Do not change the fixed stack, exact color roles, typography, section order, or interaction model when variables change. Rewrite all default copy, series content, artist statements, product details, and alt text to suit the new values and keep everything in src/content.ts.
- Do not create bare-directory links, client-only routes, or empty detail states. Every page is a real root HTML file; internal links include the .html filename; artwork.html and print.html always fall back to their first valid item.
- Do not emit source maps, copy src into dist, exceed 20 MB in dist, use absolute deployed asset paths, or require more than npm run build for the production output.
- Do not add SEO metadata, Open Graph tags, JSON-LD, sitemaps, keyword blocks, or extra marketing sections. Use only a plain document title containing [BRAND] and the local favicon.
- Do not show dates, fake testimonials, artificial edition scarcity, unverified sales numbers, fake reviews, or unsupported claims about the artist or materials.
- Do not hide core content behind motion. Support keyboard navigation, visible focus, dialog focus trapping, accessible names, reduced motion, and zero console errors at 1440×900 and 390×844 with no horizontal overflow.
