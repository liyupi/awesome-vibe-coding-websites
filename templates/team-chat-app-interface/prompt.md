# Team Chat App Interface

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build a single-screen, fully interactive team chat application for [BRAND], set inside [WORKSPACE], a [TEAM_TYPE] collaborating on [PROJECT]. The first viewport is the actual product, not a marketing landing page: a channel sidebar, a dense but calm message thread, and a member directory share one polished workspace. All people, organizations, conversations, and project details are fictional and original.

- Audience: Designers and developers building collaboration software, product teams that need a realistic messaging UI, and people looking for a substantial React app interface rather than a static visual mockup.
- Goal: Let a visitor switch channels, search and send messages, toggle reactions, open and answer thread replies, insert mentions and Unicode emoji, filter members, and switch between dark and light themes. Keep all changes in React state and localStorage so the complete experience works as static files with no network service.
- Tone: Warm, focused, and quietly playful. Use concise, believable workplace messages with specific decisions and helpful responses; avoid corporate slogans, forced enthusiasm, and generic lorem ipsum.

## Stack
- Framework: Vite 5 + React 18 + TypeScript
- Styling: Tailwind CSS 3.4
- Libraries: lucide-react (ISC), @fontsource-variable/manrope (OFL), @fontsource-variable/inter (OFL)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Set Vite base to './', build.outDir to 'dist', and build.sourcemap to false; the production output must be fully static and portable.
  - Configure Tailwind with a class-based dark strategy and semantic color tokens backed by CSS variables; define the complete light and dark palettes in src/index.css.
  - Keep all editable interface labels, channel names, member profiles, sample messages, reactions, and thread replies in src/content.ts, organized by workspace and channel and written for the supplied variable values.
  - Use React useReducer for workspace state and small presentational components for the sidebar, message list, composer, thread, member directory, and overlays; do not add a router or a state-management dependency.
  - Persist theme, per-channel drafts, sent messages, reactions, thread replies, and cleared unread counts under one localStorage key derived from the slugified [BRAND]; include a clearly labeled Reset local demo action in the workspace menu.
  - Use a textarea for the composer and native buttons for every action, with visible focus rings, accessible names, Escape-to-close behavior, and focus return when popovers or drawers close.

## Variables
- [BRAND] — Chat product name (default: "Plumthread"). Use a short invented product name and derive its lowercase slug for the document title and localStorage key.
- [WORKSPACE] — Workspace name (default: "Fable & Fern Studio"). Name the fictional organization shown at the top of the channel sidebar.
- [TEAM_TYPE] — Team description (default: "independent product design studio"). Adapt member roles, channel names, and workplace vocabulary to this kind of team.
- [PROJECT] — Current shared project (default: "Wander notebook redesign"). Make the selected channel, pinned note, and sample conversation center on this project.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/team-chat-app-interface in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

### Layout & motion
- Spacing: Use a 4px base scale. Desktop is a 100dvh grid with a 248px channel sidebar, a fluid minmax(0,1fr) conversation, and a 248px member pane. Pane headers are 64px tall. Sidebar rows are 36px with 10px horizontal padding; message rows use 12px vertical and 20px horizontal padding with 36px avatars and 12px text-column gaps. Keep the conversation readable with a 760px maximum text width. The composer sits 16px from the conversation edges and 12px from the bottom.
- Radius: Use 8px for channel rows and small buttons, 12px for fields and reaction chips, 14px for the composer, 16px for popovers and drawers, and full circles for avatars and status dots. Panes are border-separated rather than floating cards; only overlays use a restrained 0 16px 40px rgb(20 15 30 / 0.18) shadow.
- Motion: Use 140–180ms ease-out transitions for hover backgrounds, icon color, border color, reaction state, and theme changes; never animate the full message list continuously.
- Motion: Append a sent message with a 160ms fade and translateY(4px) entrance, then scroll it into view smoothly unless reduced motion is requested.
- Motion: Open emoji, mention, reaction, and workspace popovers with a 120ms opacity and scale(0.98 to 1) transition anchored to their triggering control.
- Motion: Slide the reply panel or mobile drawers 12px into place with a 180ms ease-out transition and fade their backdrop; avoid large parallax or scroll-jacking effects.
- Motion: Under prefers-reduced-motion: reduce, remove entrance, sliding, smooth-scroll, and theme transitions while preserving immediate state feedback.
- Imagery: No photographs, generated bitmaps, stock assets, or external avatar services. The rich application UI is the first-screen visual anchor. Draw eight distinct fictional people as original inline SVG geometric portraits with simple head-and-shoulder shapes, varied skin tones, hair shapes, clothing, and violet, coral, ochre, teal, and blue backgrounds; do not use initials-only avatars or resemble real individuals. Create an original [BRAND] mark from two interlocking rounded loops. Use Lucide for interface icons and plain system-rendered Unicode characters for emoji, never downloaded emoji artwork.

## Don'ts
- Do not add a backend, server code, API routes, authentication, a database, websockets, analytics, external APIs, or any real message delivery; all interactions and persistence must work locally in the browser.
- Do not load scripts, styles, fonts, icons, emoji, avatars, or images from a CDN or remote URL. Keep every runtime asset local and use relative paths with Vite base './'.
- Do not use real chat product names, logos, slogans, branded marks, proprietary emoji artwork, commercial fonts, or the exact layout and palette of an existing chat product.
- Do not copy conversations, real user identities, recognizable avatar likenesses, or existing product copy. Keep all sample content fictional and rewrite it when the supplied variables change.
- Do not use Aceternity UI, Tailwind Plus or Tailwind UI, ThemeForest or Framer template source, copied component implementations, or dependencies without an allowed permissive license.
- Do not use initials-only member portraits, stock-photo services, placeholder-image services, hotlinked files, generated bitmap avatars, or anime, game, celebrity, or other real-person likenesses.
- Do not turn this into a marketing landing page or add a typographic hero, pricing, testimonial, or feature sections; the first screen must remain the complete, rich chat application.
- Do not leave visible buttons, menus, channel rows, reactions, replies, member filters, theme controls, or composer actions nonfunctional; every offered control must have a client-side result.
- Do not use speech-bubble-heavy message cards, glassmorphism, gradients across whole panes, continuous ambient animation, scroll-jacking, or motion that ignores prefers-reduced-motion.
- Do not display calendar dates or real-world timestamps as factual product data; use 'Today' and fictional sample times only.
- Do not produce source maps, copy src/ into dist/, exceed 20 MB in dist/, or require more than the single npm run build command for production output.
- Do not use bare-directory links or introduce routes that require a server fallback. This is one self-contained index.html application; any local navigation must target index.html or a hash route.
- Do not mention VibeFather inside the product UI except for the optional small [CREDIT] link in the sidebar footer.
