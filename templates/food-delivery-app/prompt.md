# Food Delivery App

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
Build [BRAND], an original food-delivery web app for [AUDIENCE], serving [OCCASION] around the fictional [DELIVERY_AREA]. Include address selection, cuisine filters, restaurant cards with ratings and delivery details, a complete restaurant menu with sticky category tabs, a persistent minimum-order basket, an itemized sample checkout, and a live-style order tracker with an animated courier route. Use five invented restaurants, original English copy, six generated food photographs, and one code-drawn neighborhood map; every transaction and delivery event is simulated locally.

- Audience: [AUDIENCE]. The template should also serve restaurant groups, food-product founders, indie hackers, and designers who need a polished static prototype of a complete delivery workflow.
- Goal: Let a visitor move continuously from restaurant discovery to a menu, meet the minimum order, understand the full checkout total, place a sample order, and watch its status and courier route advance. Direct visits to the restaurant, checkout, and tracking routes must also contain meaningful demo content, and every visible control must update real client-side state.
- Tone: Warm, brisk, neighborly, and precise. Use appetizing but restrained food writing, transparent prices and timing, and clear demo disclosures. Avoid delivery-platform clichés, manufactured urgency, exaggerated ratings claims, or language that implies a real order or courier exists.

## Stack
- Framework: Vite 6 + React 19 + TypeScript
- Styling: Tailwind CSS 4
- Libraries: motion (MIT), lucide-react (ISC), @fontsource-variable/bricolage-grotesque (OFL-1.1), @fontsource-variable/inter (OFL-1.1)
- Build: `npm run build` → static files in `dist/`. No backend, no server code, no external APIs.
- Setup:
  - Set Vite base to './' and build.sourcemap to false; emit minified static files into dist/ with index.html as the only HTML entry and no src/ directory copied into the output.
  - Configure Tailwind CSS 4 through @tailwindcss/vite; define the color tokens, typography, route-map keyframes, progress treatments, and reusable app utilities in src/index.css.
  - Implement index.html plus hash routes #/restaurant, #/checkout, and #/tracking. Direct #/restaurant selects the first restaurant; direct #/checkout uses the initialized sample or persisted basket; direct #/tracking creates the built-in sample order when no submitted order exists.
  - Create src/content.ts as the single source for variable values and derived copy, restaurant and menu records, cuisine filters, address presets, fees, sample order stages, image paths, map labels, and UI labels. Rewrite default copy when variables change and derive a storage namespace by lowercasing BRAND and removing spaces and punctuation.
  - Use one React context with reducers for selected address, cuisine, selected restaurant, basket lines, checkout fulfillment, submitted order, tracking playback, dialogs, and toast feedback. Do not add a state-management or routing library.
  - Persist basket lines, address selection, initialization state, submitted order, and tracking timestamps in localStorage under one versioned key derived from BRAND. Validate stored restaurant IDs, dish IDs, quantities, and totals against src/content.ts when loading.
  - On the first visit only, initialize one Charred lemon chicken in the sample basket and label it as a prefilled demo. Clearing the basket must remain empty after reload; never reseed it after the user clears or submits it.
  - Use integer minor units for all prices and Intl.NumberFormat with [CURRENCY] for display. Changing currency changes formatting only; rewrite price values explicitly rather than implying conversion.
  - Use Motion for route changes, drawers, dialogs, basket updates, and toasts. Use SVG path geometry plus requestAnimationFrame for courier position; pause timers while the document is hidden and never use Math.random for order events.
  - Self-host Bricolage Grotesque Variable and Inter Variable through the listed Fontsource packages. Bundle Lucide icons locally and draw only the original [BRAND] basket-line symbol and neighborhood map as inline SVG.
  - Implement accessible dialogs and drawers with a visible close button, Escape and scrim dismissal, focus trapping, focus restoration, and a polite status region for basket, address, checkout, and tracking updates.
  - Respect prefers-reduced-motion from the first render: disable autonomous courier movement and nonessential transitions, retain manual Next demo step and Replay controls, and keep every ordering interaction functional.

## Variables
- [BRAND] — Invented delivery service brand (default: "Pepper & Parcel"). Use in the wordmark, document title, storage namespace, checkout, order details, and footer; rewrite all brand-derived copy when changed.
- [OCCASION] — Meal occasion (default: "weeknight dinners"). A short lowercase occasion such as weeknight dinners or weekend lunches; adapt hero copy, empty states, and checkout labels without changing the food photographs.
- [AUDIENCE] — Primary customer audience (default: "busy neighbors who want a reliable meal without cooking"). Rewrite discovery and service copy for this audience while keeping the interface concise.
- [DELIVERY_AREA] — Fictional delivery district (default: "Maple District"). Use an invented district in the address bar, restaurant coverage copy, checkout, and map labels; never substitute a real branded location.
- [ACCENT] — Primary action accent as a hex color (default: "#B7472A"). Apply to primary buttons, selected chips, active categories, and route highlights while preserving accessible contrast.
- [CURRENCY] — Display currency (default: "USD"). Use Intl.NumberFormat for every price and keep all calculations in integer minor units.
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/food-delivery-app in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design
### Colors
- Canvas `#F6F1E8` — Warm parchment app background and spacious separation between modules.
- Surface `#FFFDF8` — Restaurant cards, menu panels, address dialog, checkout, and sticky bars.
- Ink `#25291F` — Primary text, wordmark, icons, prices, and high-contrast outlines.
- Muted `#6E7165` — Metadata, secondary copy, timings, and inactive controls.
- Tomato `#B7472A` — Default value of [ACCENT]; primary actions, active filters, and route progress with white text.

- Honey `#F1C75B` — Rating stars and small highlights, always beside dark Ink text.
- Hairline `#E3DCCE` — One-pixel borders, dividers, input outlines, and progress tracks.

### Typography
- Hero, page headings, restaurant names, and editorial food moments: Bricolage Grotesque Variable (OFL), weights 500/600/700/800
- Navigation, menu items, prices, forms, status labels, and body copy: Inter Variable (OFL), weights 400/500/600/700

### Layout & motion
- Spacing: Use a 4px base unit. App content has a 1280px maximum width with 28px desktop and 16px mobile gutters. Desktop header is 72px, mobile header 64px, and major page modules are separated by 24px. Restaurant cards use 16px padding, menu rows 20px, and checkout panels 24px. Keep interactive targets at least 44×44px, preserve 16px between sticky bars and content, and include safe-area padding below mobile controls.
- Radius: Use 24px for the photographic hero and tracking map, 18px for restaurant and checkout cards, 14px for menu images and dialogs, 10px for inputs, and fully rounded shapes only for cuisine chips, rating badges, and compact icon buttons. Use 1px Hairline borders and short warm shadows rather than glass effects.
- Motion: Use 180–240ms ease-out transitions for cuisine selection, restaurant hover, add buttons, quantity steppers, address changes, and cart badges; update state before playing any effect.
- Motion: Hash-route changes fade and settle 8px upward over 200ms. Preserve the shared header and bottom navigation without animating them, and move focus to the new page heading.
- Motion: Adding a dish draws one small checkmark and pulses the basket badge once. The minimum-order progress bar animates width over 260ms while its text updates immediately.
- Motion: Sticky menu category tabs use a 180ms active-indicator slide and smooth scroll with the correct header offset; scrollspy changes the active tab without moving the page.
- Motion: Checkout success transitions directly into tracking with one 240ms order-card settle. Do not use confetti, celebratory audio, or a fake payment-processing delay.
- Motion: For a playing order, move the bicycle marker continuously along the SVG route using getPointAtLength, and reveal route progress with the same normalized value. Status changes and courier position derive from one 60-second clock.
- Motion: Dialogs and mobile drawers enter over 220ms with opacity and a 12px settle; toasts remain for 1800ms. Never block basket or navigation controls during an animation.
- Motion: Under prefers-reduced-motion, remove route settles, smooth scrolling, badge pulses, progress interpolation, and autonomous courier motion. Show a static route and allow manual tracking-stage changes only.
- Imagery: Use exactly six local AI-generated realistic editorial food photographs: one wide neighborhood-dinner tableau and five 4:3 restaurant-signature dishes. Every image shares soft upper-left window daylight, warm cream stone surfaces, matte ivory ceramics, subtle tomato and sage accents, natural food texture, gentle contact shadows, 50mm lens perspective, and fine 35mm grain. Keep plates fully readable with appetizing portions and no text, packaging marks, logos, watermarks, people, hands, or recognizable branded products. Use each restaurant photograph only for that restaurant and its matching signature dish; delivery-spread.webp belongs only to discovery. Do not rename a supplied dish into unrelated food when variables change. The first screen must prominently feature the wide tableau, not typography alone.
