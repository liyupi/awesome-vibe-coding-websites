A single-page site that launches one browser extension: a hero anchored by a CSS browser-window mockup running a scripted animation of the extension at work (cluttered page, popup, clean page); a three-step 'how it works' rail synced to the mockup; a feature trio with drawn glyphs; a plain-language privacy manifesto; a review row; drawn generic install buttons with a manual-download note; and a short FAQ. The default content follows an invented extension, but the structure suits any extension, userscript or desktop tool. The look is workshop dark: graphite ground, warm paper text, one amber accent, everything code-drawn — no photographs, no browser-vendor marks. All copy lives in one content file; swapping the variables rewrites the page.

## Variables

Replace these in the prompt with your own values; everything else stays as written.

| Variable | What it is | In the demo |
|---|---|---|
| `[BRAND]` | Extension name | Hushpage |
| `[JOB]` | What it does | strips clutter from any article and hands you clean, readable pages |
| `[SHORTCUT]` | Shortcut | Alt+Shift+H |

## How to use it

1. Copy [prompt.md](prompt.md), or run `npx vibefather add browser-extension-landing-page` in your project.
2. Replace the `[VARIABLES]` with your own brand, copy and details.
3. Paste it into Claude Code, Codex, Cursor or another AI coding agent and let it build. [DESIGN.md](DESIGN.md) holds the colors, type and spacing on their own if you only want the look.

## Make it yours

- A tab manager extension: set BRAND to your name, JOB to closing duplicate tabs, and rewrite the popup toggle and slider to match your real controls.
- A developer tool or userscript: keep the workshop-dark look, set SHORTCUT to your binding and swap the feature trio for permission notes developers check first.
- An indie hacker launching a first extension: use the drawn install buttons and manual-download note, and point them at your own listing before launch.
- A writing or reading tool: set JOB to cleaning up pages, keep the reading-mode popup and rewrite the privacy manifesto around what data stays local.

## FAQ

### How do I change the extension name, job and shortcut in the Browser Extension Landing Page template?
The Browser Extension Landing Page template keeps every string in one content file, and the brief is driven by three variables: BRAND (the extension name), JOB (a lowercase verb-first phrase for what it does) and SHORTCUT (the keyboard binding shown in mono). Swap those three and rewrite each headline, paragraph, label and FAQ row to match, keeping the same length and tone. The layout, colors, type and motion stay as designed.

### What does the animated browser mockup in the Browser Extension Landing Page actually show?
The Browser Extension Landing Page hero contains a code-drawn browser window that runs a four-step scripted loop: a cluttered article page with pulsing ad blocks, the extension icon bouncing as a cursor dot moves to it, a paper popup card with a reading-mode toggle and width slider, then the page transforming into wider readable bars with a small amber done check on the toolbar icon. Hovering or focusing the mockup pauses the loop, and the four step dots are keyboard-focusable.

### How do the install buttons work if there is no backend?
The Browser Extension Landing Page uses drawn generic install buttons with a manual-download note rather than linking to a store listing. Nothing is submitted anywhere and no external APIs are called, so the page builds to static files. To go live you point the install buttons at your own download or listing URL and replace the invented brand slug and download name in the brand file.

### Which parts of the Browser Extension Landing Page should I edit first for my own extension?
Start with the content file: set BRAND, JOB and SHORTCUT, then rewrite the H1, the three-step rail, the feature trio and the privacy manifesto so they describe what your extension touches and never touches. The privacy section matters most for this audience, since the page is written for people who read permissions before installing. Finally update the review row and FAQ, and check the mockup labels still match.
