# Design Conference Website

Build this website exactly as described below. Replace the [VARIABLES] with your own values; keep everything else.

## Brief
A two-page website (home and schedule) for [BRAND], a small independent two-day conference about [EVENT_TOPIC], held in [CITY] on [EVENT_DATES]. The home page is designed like a Swiss event poster: paper off-white, near-black ink, one vermilion accent, hard rules, numbered sections, and a giant variable-font headline of the event name whose letters get heavier and wider as the pointer approaches. It covers about, speakers (abstract code-generated portraits with bios on hover), venue (hand-drawn SVG map), ticket tiers with a sold-out tier, and FAQ. The schedule page lists every session with day tabs and track filters that work entirely in the browser. All content is invented.

- Audience: [AUDIENCE] deciding whether to buy a ticket, plus attendees checking the schedule on their phone during the event.
- Goal: Make the event feel worth attending in five seconds, then get visitors to the ticket tiers or the schedule with no friction.
- Tone: Confident, dry and a little opinionated, like a poster written by designers for designers. Short sentences, concrete numbers, no hype words, no exclamation marks.

## Variables
- [BRAND] — Event name (used as the giant poster headline) (default: "Kernfolk"). One word of 5–10 letters works best for the per-letter headline effect.
- [EVENT_TOPIC] — What the conference is about (default: "independent web design")
- [CITY] — Host city (invented or real, no real venue names) (default: "Port Ellery")
- [EVENT_DATES] — The two event days (default: "June 11–12"). Day tabs read 'Day 1 — Thu 11 June' and 'Day 2 — Fri 12 June'; adjust weekdays to your dates.
- [AUDIENCE] — Who attends (default: "designers and front-end developers who still hand-build the web")
- [CREDIT] — keep a small "Template by VibeFather" link to https://vibefather.ai/t/design-conference-website in the footer (default: yes; delete this line to remove it)

The copy under Pages & Sections is written for the default values. If your values differ, rewrite every headline, paragraph, label and image for them — same length, tone and structure. Layout, colors, type and motion stay as described.
Keep all copy, image paths and links in one content file (for example `src/content.ts`), keyed by section, so the content can be swapped later without touching components.

## Design
### Colors
- Paper `#F3EFE6` — Page background everywhere except ink bands
- Shade `#E7E1D4` — Portrait backgrounds, break rows in the schedule, map land, card hover fill
- Ink `#141414` — All text, 2px rules and borders, marquee and footer background, active tab fill
- Mute `#6E6A62` — Secondary text: roles, meta labels, durations, map street labels
- Signal `#FF4A1C` — The only accent: primary buttons, hero disc (multiply), section numbers, sold-out stamp, map pin, CTA band background, focus rings
- Signal Deep `#D93A12` — Hover state of Signal buttons only

### Typography
- Display (poster headline, section titles, speaker names, prices, big times): Anybody Variable (OFL), weights 300/600/800/900
- Body (paragraphs, bios, FAQ answers, buttons): Inter Variable (OFL), weights 400/500/600
- Mono (meta rows, labels, track names, marquee, map labels, session times on mobile): JetBrains Mono (OFL), weights 400/700

### Layout & motion
- Spacing: 12-column grid, max width 1440px, side padding 40px desktop / 20px mobile, 24px column gap. Sections are separated by a full-bleed 2px Ink rule and have 120px vertical padding desktop / 72px mobile. Inside cards use 24px padding. Every section opens with a SectionHead: a row with the number in Signal (Anybody 900, 20px, e.g. '02') followed by the title in Anybody 800 at font-stretch 85%, uppercase, clamp(40px, 6vw, 88px), line-height 0.9, and a 2px Ink rule underneath with 32px gap.
- Radius: 0 everywhere: buttons, cards, chips, dialog and inputs are square-cornered. The only round things are circles in the art (hero disc, portraits, map pin).
- Motion: Poster headline: each letter is its own span; on pointermove (desktop) a requestAnimationFrame loop computes the distance d from the pointer to each letter's centre and sets font-variation-settings 'wght' and 'wdth' from t = 1 − smoothstep(0, 360px, d): wght = 300 + 600·t, wdth = 60 + 80·t. Current values ease toward targets with lerp factor 0.14 per frame. When the pointer leaves the hero, targets return to rest (wght 300, wdth 60).
- Motion: On devices with (pointer: coarse) or no pointer movement for 4s, a virtual pointer at the vertical centre of the headline sweeps left to right and back across the word, one full cycle every 7s (x = centre + sin(time) · half width).
- Motion: Headline fit: on load and on resize, set font-size so the word fits the container with every letter at wght 900 / wdth 140, capped at 300px. The word never wraps or overflows at any pointer position.
- Motion: Section reveal: SectionHead and the first block of each section fade in and move up 24px over 600ms ease [0.2, 0.7, 0.2, 1] when 20% visible (Motion whileInView, once: true).
- Motion: Marquee: Ink band, content duplicated twice in one track, translateX 0 → −50% over 40s linear infinite; pauses on hover.
- Motion: Buttons: on hover the background shifts to Signal Deep (or Ink buttons to Signal) and the label's arrow moves 4px right, 150ms. Focus-visible: 3px Signal outline with 3px offset.
- Motion: Reduced motion: headline renders static at wght 800 / wdth 100 with no pointer tracking, marquee is static and wraps, no reveals, map is fully drawn, schedule and accordion change instantly.
- Imagery: No photos and no bitmaps. All art is drawn in code: the hero disc (CSS), abstract speaker portraits (SVG generated from a seeded random function of the speaker's name), the venue street map (inline SVG), the favicon (SVG). Icons come from lucide-react only. The overprint idea: Signal shapes sit on top of or behind Ink with mix-blend-mode: multiply so overlaps read as a darker red-black, like two inks printed over each other.

## Don'ts
- No backend: no server code, API routes, databases, auth, analytics or third-party APIs. Ticket buttons open a local dialog; no form submits anywhere.
- No checkout, payment widget or embedded ticketing script.
- No CDN <script> or <link> tags. Fonts are self-hosted through Fontsource packages; never load fonts.googleapis.com, fonts.gstatic.com or any other font CDN.
- No source maps in the production build and no src/ files copied into dist/. Keep dist/ under 20 MB.
- Every internal link points to a file name (./index.html, ./index.html#tickets, ./schedule.html), never to a bare directory or /. Use relative asset paths (Vite base './').
- No photos of people and no real likenesses: speaker portraits are only the generated abstract shapes.
- No real conference names, logos, wordmarks or slogans; no real speaker names, venues, addresses or sponsors. All names in the content are invented.
- No map tiles or embeds from any map provider; the venue map is inline SVG only.
- No commercial or custom fonts; only the three OFL families listed.
- No sponsor logo strip and no brand logos of any kind.
- No rounded corners, gradients, drop shadows or glassmorphism; flat paper, ink and one accent only. Do not add a second accent colour.
- Do not let the poster headline wrap or overflow at any pointer position or viewport width.
- Must work at 1440×900 and 390×844 with zero console errors, full keyboard access (tabs, chips, accordion, speaker cards, dialog, mobile menu) and visible focus rings.
- Respect prefers-reduced-motion as described in Design → Motion.
- No SEO extras: no meta descriptions, Open Graph tags, JSON-LD or sitemap. A plain <title> and the SVG favicon only.
