This portfolio is built for designers whose strongest work needs more explanation than a gallery card can provide. It pairs a concise project index with substantial case-study pages, giving each project room for the problem, research, decisions, wireframes, interface changes, and outcomes. The structure suits independent UX and product designers, researchers moving into design, and job seekers who want hiring managers to understand how they think.

The visual direction is a warm editorial workspace rather than a polished agency showcase. Serif headlines, compact mono labels, fine rules, and annotated browser frames create a consistent rhythm from overview to evidence. Every project artifact is drawn with HTML, CSS, and SVG, so the work remains crisp and editable without relying on client screenshots. A draggable before-and-after comparison, selectable wireframe views, reading progress, and restrained scroll reveals make the material easier to explore without turning the case study into a visual effects demo.

The default content follows a fictional product designer through healthcare and financial tools, with three distinct projects and clearly labeled illustrative outcomes. An alternate set of values shifts the same structure to climate and education products. The designer name, discipline, project set, location, email, and availability are variables; all related copy lives in one content file so names, narratives, research notes, and metrics can be changed together.

About and contact pages complete the portfolio with a fictional studio portrait, working principles, experience, capabilities, and a practical project-inquiry flow. The form prepares a project brief locally instead of sending data to a server. Replace the sample work with real projects, or use the included narrative framework to draft a first portfolio from scratch.

## Make it yours

- A UX researcher moving into design: set DISCIPLINE to UX researcher, keep the research annotations and wireframe views, and rewrite the outcomes to emphasize findings rather than shipped interfaces.
- A product design studio: set BRAND to the studio name and PROJECT_SET to client sectors, then use the case-study pages to show process evidence for prospective clients instead of finished visuals.
- A design job seeker: set AVAILABILITY to open to roles and CONTACT_EMAIL to a personal address, then trim the project index to the three projects hiring managers should read first.
- A climate or education designer: use the alternate PROJECT_SET values, rename every project, research note and metric to match, and keep the same editorial evidence-board structure.

## FAQ

### How do I replace the fictional projects in the UX Designer Case Study Portfolio with my own work?
The UX Designer Case Study Portfolio keeps all project data, case-study prose, research notes and metrics in one content file, so you replace the sample healthcare and financial projects there. Set PROJECT_SET to your own subject area, then rewrite each project's problem, research, decisions, wireframes and outcomes together so the narrative stays consistent. The prompt notes the sample projects and outcomes are fictional and should be labeled as such until you swap in real work.

### What does the before-and-after comparison and the wireframe selector actually show?
The UX Designer Case Study Portfolio includes a draggable before-and-after comparison for showing interface changes and selectable wireframe views for low-fidelity layouts. Both are drawn with HTML, CSS and SVG rather than screenshots, so the artifacts stay crisp and editable. The comparison uses a drag interaction and the wireframe views switch through local state, letting a hiring manager explore evidence without leaving the case study.
